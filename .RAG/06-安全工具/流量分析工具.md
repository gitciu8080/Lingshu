# 流量分析工具

> 关键词:流量分析,Wireshark,显示过滤,抓包过滤,tcpdump,Zeek,Suricata,DNS隧道,C2通信,数据外传,加密流量,pcap,capinfos,mergecap,editcap,网络取证

流量分析是安全运营、应急响应与网络取证的核心技能:通过抓包还原攻击行为、识别恶意通信(DNS 隧道、C2、数据外传)、验证检测规则。本文件覆盖抓包(Wireshark/tcpdump)、解析告警(Zeek/Suricata)与 pcap 批处理工具。分析对象须为本人网络、授权监控范围内流量或公开数据集(如 Malware-Traffic-Analysis 样例)。

## Wireshark

- **用途**:图形化抓包与分析工具,支持数百种协议解码、流追踪、对象导出、统计与过滤;是流量分析的"显微镜"。
- **安装**:官网下载(wireshark.org);Linux 用 `apt install wireshark`;命令行版为 `tshark`。
- **抓包过滤(捕获时,BPF 语法,接口上生效,快)**:
```bash
tcpdump -i eth0 host 10.0.0.5          # 等价于在 Wireshark 捕获过滤器填 host 10.0.0.5
# Wireshark Capture Filter 示例:
host 10.0.0.5
tcp port 80 or tcp port 443
not arp and not icmp
net 192.168.1.0/24
```
- **显示过滤(分析时,完整表达式,常用)**:
```text
ip.addr == 10.0.0.5                     # 涉及该 IP 的所有包
tcp.port == 443
http.request.method == "POST"
http.host contains "example"
dns.qry.name contains "mal"
tls.handshake.extensions_server_name == "evil.com"   # SNI 主机名
frame contains "password"               # 载荷关键字搜索
tcp.flags.syn == 1 && tcp.flags.ack == 0  # SYN 包
icmp && data.len > 64                    # 可疑大 ICMP(隧道特征)
tcp.stream eq 0                          # 指定 TCP 流
```
  - 组合:`&&`(与)、`||`(或)、`!`(非)、括号分组;过滤语法可自动补全,`tshark -Y "过滤式" -r file.pcap` 等价。
- **追踪 TCP 流**:右键任意 TCP 包 → Follow → TCP Stream(快捷键 Ctrl+Alt+Shift+T),可查看完整会话内容(如 HTTP 明文请求/响应、FTP 口令),常用于还原攻击载荷与凭据泄露证据。
- **导出对象**:File → Export Objects → HTTP/SMB/TFTP…,可直接导出通过 HTTP 传输的文件(如恶意样本、webshell 上传文件),再交沙箱分析。
- **其他常用视图**:Statistics → Protocol Hierarchy(协议占比)、Conversations/Endpoints(会话与端点统计)、Telephony(VoIP);`tshark -z conv,tcp -r f.pcap` 命令行等价。
- **分析要点**:优先看"异常"——非标准端口、大流量突发、频繁重传、TLS 证书异常、DNS 查询大量随机子域等;加密流量先看元数据(SNI、证书、会话时长、流量方向)。

## tcpdump

- **用途**:命令行抓包工具,资源占用低,适合服务器现场取证与脚本化采集;语法为 BPF 过滤表达式。
- **安装**:`apt install tcpdump`(Linux/macOS 自带)。
- **常用参数**:
```bash
sudo tcpdump -i eth0 -n -s 0 -w capture.pcap          # 抓全部流量存 pcap(-n 不解析域名,-s 0 全包长)
sudo tcpdump -i eth0 -nn -c 1000                      # 只抓 1000 个包,-nn 不解析端口/主机名
sudo tcpdump -i eth0 -A 'tcp port 80'                 # -A 以 ASCII 显示载荷
sudo tcpdump -i any 'host 10.0.0.5 and tcp port 443'  # 任意网卡+复合表达式
sudo tcpdump -i eth0 -X 'icmp[0]=8'                   # -X 十六进制+ASCII,按字节偏移过滤(icmp echo)
```
- **捕获表达式(BPF)示例**:
```text
host 1.2.3.4
src host 1.2.3.4 && dst port 53
tcp[13] & 2 != 0        # 含 SYN 标志的包(字节偏移过滤)
udp port 53
not port 22
```
- **输出解读**:每行 `时间 IP.src.port > IP.dst.port: flags 序号 ack win 长度`;`Flags [S]`(SYN)/`[P.]`(数据)/`[F.]`(FIN)/`[R]`(RST);大量 `[R]` 或重传(`tcp retransmission`)提示丢包或扫描。文件写满注意 `-C 100 -W 10`(每 100MB 轮转,最多 10 个)防止磁盘爆满。

## 网络取证分析引擎(Zeek / Suricata)

- **用途**:在监控点旁路/镜像口持续解析流量,生成结构化日志(连接、DNS、HTTP、TLS 等)与告警,是 SOC/NDR 的核心组件;两者常互补部署。
- **Zeek(原名 Bro)**:
  - 定位:流量"协议解析+日志生成",不阻断;日志丰富(conn、dns、http、ssl、files、notice)。
  - 安装:`apt install zeek` 或官方二进制包;配置 `node.cfg` 与 `local.zeek`。
  - 运行与常用脚本:
```bash
zeek -r capture.pcap local            # 离线分析 pcap,生成 conn.log 等
zeek -i eth0 local                    # 实时监听
# 检测脚本示例(在 local.zeek 中加载):
# @load policy/protocols/dns/detect-external-names
# @load policy/frameworks/files/hash-all-files
```
  - 输出解读:`conn.log` 每行一个连接(时间/端点/协议/字节数/状态),`dns.log` 记录查询与应答,`notice.log` 为规则触发的告警;用 `zeek-cut` 提取字段:
```bash
zeek-cut id.orig_h id.resp_h proto service < conn.log
```
  - 典型用途:横向扫描检测(大量短连接)、DNS 隧道检测(子域熵高/查询频率异常)、文件 hash 提取。
- **Suricata**:
  - 定位:高性能 IDS/IPS,签名规则匹配(Suricata/Snort 规则),可内联阻断;也输出 EVE JSON 日志与 flow 记录。
  - 安装:`apt install suricata`;规则集用 `suricata-update` 拉取(ET Open 等)。
  - 常用命令与配置:
```bash
suricata -i eth0 -S /etc/suricata/rules/*.rules     # 实时
suricata -r capture.pcap -l ./out -S rules.rules    # 离线分析 pcap
suricata-update update                               # 更新规则
```
  - 输出解读:告警在 `/var/log/suricata/eve.json`(每行 JSON):`alert.signature`(规则名)、`alert.severity`(1~4,1 最严重)、`src_ip/dest_ip`;用 `jq` 过滤:
```bash
jq -r 'select(.event_type=="alert") | [.timestamp,.alert.severity,.alert.signature,.src_ip,.dest_ip] | @tsv' eve.json
```
  - 规则示例:`alert http any any -> any any (msg:"可疑UA"; content:"curl"; http.user_agent; sid:1000001;)`
- **Zeek vs Suricata 分工**:Zeek 重"还原与日志"(元数据全),Suricata 重"签名匹配与阻断";生产上常 Zeek 分析 + Suricata 告警并行,告警关联 Zeek 日志做深度溯源。

## 流量分析场景

### DNS 隧道检测

- **特征**:子域名随机/高熵(`qwerty123.xxx.com` 大量不同前缀)、查询频率极高、TXT 记录载荷大、单域名长时间持续查询、罕见的记录类型(TXT/MX 传数据)。
- **分析命令**:
```bash
tshark -r cap.pcap -Y "dns" -T fields -e dns.qry.name | sort | uniq -c | sort -rn | head
zeek-cut query answers < dns.log | sort | uniq -c | sort -rn | head -20
```
- **确认方法**:对高熵子域做熵值计算(Python 脚本),并比对合法业务域;被控端常用 dns2tcp、iodine、dnscat2。

### C2 通信特征

- **特征**:规律性心跳(固定间隔的短连接)、HTTP 响应体编码(如 base64/自定义 XOR)、非常规端口(8080/4444/53)、UA 固定或伪装、JA3/JA3S 指纹异常、TLS 证书自签且 CN 随机。
- **分析命令**:
```bash
tshark -r cap.pcap -Y "tcp.port==4444" -T fields -e ip.src -e ip.dst -e tcp.len | head
# 统计与同一目标交互频率(心跳检测):
tshark -r cap.pcap -T fields -e frame.time_delta -e ip.src -e ip.dst -e tcp.len | awk '{print $2,$3}' | sort | uniq -c | sort -rn | head
```
- **确认方法**:按时间绘制连接间隔;JA3 指纹可用 `tshark -Y "tls.handshake" -T fields -e tls.handshake.ja3` 提取后与已知恶意指纹比对(Moloch/ja3er 等)。

### 数据外传检测

- **特征**:大流量突发上传(方向为内→外)、FTP/HTTP POST 上传大文件、DNS TXT 承载数据、邮件附件异常、加密流量大体积持续外送。
- **分析命令**:
```bash
tshark -r cap.pcap -q -z conv,tcp | sort -k5 -rn | head -20     # 按字节排序会话
tshark -r cap.pcap -Y "http.request.method==POST" -T fields -e http.host -e http.request.uri -e http.content_length
zeek-cut orig_bytes resp_bytes proto < conn.log | sort -k2 -rn | head -20
```
- **确认方法**:对可疑 IP 的全量导出(`-w` 子集),查看载荷内容与目标信誉(威胁情报)。

### 加密流量分析思路

- 拿不到明文时转向**元数据**:SNI(TLS ClientHello)、证书信息、TLS 版本与密码套件、会话时长与字节分布、JA3/JA3S、DNS 前置解析记录。
- 流量形态学:恶意 C2 通常"低频小包 + 规律间隔",与正常浏览(突发、多域名)差异明显;可用机器学习做会话级特征(时间间隔熵、包长熵)。
- 有条件时部署 TLS 解密:企业可部署 SSL 中间人(需合规告知与证书下发),用 `sslkeylog` 导出会话密钥后在 Wireshark 中解密(Preferences → Protocols → TLS → RSA key/日志文件)。

## pcap 文件处理工具

| 工具 | 用途 | 示例 |
| --- | --- | --- |
| capinfos | 查看 pcap 元信息(时长、包数、文件大小、捕获接口) | `capinfos capture.pcap` |
| mergecap | 合并多个 pcap | `mergecap -w all.pcap a.pcap b.pcap` |
| editcap | 裁剪/过滤/修改 pcap(按时间、按包数、去重) | `editcap -A 2024-01-01 00:00:00 -B 2024-01-02 00:00:00 in.pcap out.pcap`、`editcap -c 100000 big.pcap split`(每 10 万包切片) |
| tshark | 命令行重解析与字段提取 | `tshark -r f.pcap -Y "http" -T fields -e http.request.uri` |
| pcap-splitter / tcpreplay | 切分 / 回放流量(重放需注意别打到生产) | `tcpreplay -i eth0 --topspeed f.pcap` |

- **实操组合**:
```bash
capinfos incident.pcap
editcap -A "2024-03-01 08:00:00" -B "2024-03-01 09:00:00" incident.pcap window.pcap
tshark -r window.pcap -Y "dns.flags.response==0" -T fields -e dns.qry.name | sort -u > queries.txt
suricata -r window.pcap -l ./suricata_out -S /etc/suricata/rules/
zeek -r window.pcap local && zeek-cut query answers < dns.log | head
```

## 分析工作流小结

1. 确认数据来源合法(本机抓包/授权镜像口/公开样本);
2. `capinfos` 查看概况 → 用 `editcap` 按时间切片缩小范围;
3. 顶层统计:`tshark -q -z io,phs`(协议分层)、`-z conv,tcp`(会话排序);
4. 按异常线索用显示过滤深入(Wireshark)或 Zeek/Suricata 跑全量日志;
5. 对可疑流 Follow TCP Stream、Export Objects 还原载荷;
6. 汇总 IOC(IP/域名/文件 hash/UA/JA3),输出时间线报告并关联威胁情报。
