# 安全工具模块说明(README)

> 关键词:安全工具,工具选型,开源工具,商业工具,合规,授权测试,渗透测试,工具使用红线,模块导航,Red Team,Blue Team,信息收集,漏洞扫描,流量分析,密码破解,防御监控

本模块为网络安全知识库第 06 号子模块,系统介绍安全测试与防御监控中常用工具,按"信息收集 → 漏洞扫描 → 渗透利用 → 流量分析 → 密码破解 → 防御监控"六个环节组织,并给出选型原则与使用红线,帮助读者在合法授权前提下快速上手、正确选型。本 README 是模块入口:先读红线,再按导航进入对应文件。

## 模块概览

- **定位**:面向渗透测试、安全运维、蓝队运营、合规审计与安全学习者的一站式工具速查与选型参考。
- **覆盖范围**:
  - 攻击侧(Red):信息收集、漏洞扫描、渗透利用、密码破解;
  - 分析侧:流量分析、网络取证;
  - 防御侧(Blue):EDR/HIDS、IDS/NDR、SIEM、蜜罐、基线核查。
- **使用方式**:每个工具条目统一按"用途 → 安装 → 核心命令 → 输出解读/注意事项"组织,命令可直接复制练习(靶场环境);对比表用于选型决策。
- **统一前提**:文内所有扫描、爆破、利用、破解操作**仅限授权范围**;练习一律在本地靶场或授权测试环境进行。

## 使用红线(必读)

- **仅限授权**:所有工具仅可用于你拥有明确书面授权的系统、网络与账号。未经授权对任何目标进行扫描、探测、破解或利用,均属违法行为。我国相关法律依据包括《刑法》第 285/286 条(非法侵入、非法获取计算机信息系统数据)、《网络安全法》第 27 条(禁止从事危害网络安全的活动)、《数据安全法》(数据处理须合法合规)。
- **授权书要素**:目标范围(域名/IP/网段)、测试时间窗口、允许的手法(如是否允许弱口令爆破、DoS 类操作)、数据保密与销毁要求、紧急联系人。
- **行为规范**:不下载或传播他人数据;不破坏系统可用性;控制扫描速率避免影响业务(如 nmap `-T2`/`--min-rate`);测试结束后清理植入的账号、后门与工具残留。
- **环境隔离**:练习请使用本地靶场 —— DVWA、Vulhub、Metasploitable、HackTheBox、TryHackMe、PicoCTF 等,严禁对互联网真实目标随意测试。
- **越界即停**:测试中发现超出授权范围的资产或问题,记录并上报,不得扩大测试;对授权外目标的一切操作都属违规。

## 工具选型原则

### 开源 vs 商业

| 维度 | 开源(OSS) | 商业 |
| --- | --- | --- |
| 成本 | 免费,总拥有成本低 | 按年订阅或按资产计费,价格高 |
| 能力 | 社区驱动,迭代快,可深度定制 | 厂商维护,插件/规则库更新及时,服务有保障 |
| 可用性 | 依赖社区,部分项目易停更 | 有 SLA 与技术支持 |
| 适用 | 学习研究、预算有限的团队、深度定制场景 | 合规要求严格、需要报告与支持的企业/等保场景 |
| 示例 | Nmap、Nuclei、Wazuh、Zeek、Suricata | Nessus、AWVS、Burp Suite Pro、奇安信、深信服 |

选型建议:先用开源工具建立基线能力,再按合规与人力成本评估是否采购商业产品;两者常可混用(如开源采集 + 商业平台统一管理)。

### 选型决策流程

1. **定需求**:明确要解决什么问题 —— 是合规漏扫、上线验收、红队演练,还是持续安全运营(SOC)?
2. **看约束**:预算、人力(是否有专人维护)、合规要求(等保/行业监管)、现有技术栈(云/容器/传统 IDC)。
3. **比能力**:用 PoC/试用版在真实环境验证检测率、误报率、性能与易用性,而非只看宣传。
4. **算总账**:总拥有成本 = 许可费 + 部署维护人力 + 误报处理成本 + 培训成本。
5. **定组合**:开源打底(采集与基础检测)+ 商业补齐(报告、支持、复杂场景),避免重复建设。

### 按场景匹配

- **信息收集/资产测绘**:subfinder + amass + dnsx + httpx + nmap + Shodan/Fofa 组合,自动化出资产清单。
- **漏洞发现**:综合扫描器(Nessus/OpenVAS)+ 模板化验证(Nuclei),先扫后验。
- **Web 专项**:Burp Suite + sqlmap + xray;移动/API 场景补充 mitmproxy。
- **内网/后渗透**:Metasploit + Cobalt Strike(仅授权红队场景)。
- **流量分析**:Wireshark/tcpdump 抓包,Zeek/Suricata 做持续监控与告警。
- **防御监控**:Wazuh(主机)+ Suricata(网络)+ Elastic Security(分析展示)。

### 合规要点

- 等保 2.0 要求定期漏扫与渗透测试,报告需留存;扫描器输出可作为合规证据。
- 使用商业工具时注意 license 授权范围与数据出境合规;使用 Shodan/Fofa 等测绘平台注意账号实名与查询限制。
- 渗透测试服务建议由具备资质的第三方或内部红队执行,并留存授权书与测试报告。
- 数据类操作(导出数据库、提取口令哈希、抓取用户流量)须有明确授权与最小化原则,用后销毁。

### 各文件要点速览

- **信息收集**:被动优先(subfinder/dnsx)减少暴露;nmap 负责端口与服务,httpx 收敛 Web 资产;Shodan/Fofa 查暴露面;目录枚举发现隐藏入口。
- **漏洞扫描**:综合扫描器出清单,手工/Nuclei 验证降误报;Trivy 管容器与依赖;认证扫描远比非认证准确。
- **渗透框架**:Metasploit 拿初始权限,Meterpreter 做后渗透;Burp 管 Web;sqlmap 管注入;Hydra 管弱口令;Cobalt Strike 仅授权红队。
- **流量分析**:Wireshark 微观还原,tcpdump 现场取证,Zeek/Suricata 规模化检测;重点场景:DNS 隧道、C2 心跳、数据外传。
- **密码破解**:hashcat 靠 GPU 与规则,先字典→规则→掩码→暴力;哈希识别是第一步;WiFi 破解仅限本人/授权网络。
- **防御监控**:Wazuh(主机)+ Suricata(网络)+ Elastic Security(SIEM)构成低成本 SOC;蜜罐补欺骗防御;OpenSCAP/Lynis 管基线。

## 常见问题(FAQ)

- **Q:开源工具扫描结果能用于等保合规吗?** 可以,等保侧重"是否开展定期漏扫/渗透并留存报告",关键是过程规范与报告质量,而非工具是否商业。
- **Q:扫描器报了一堆高危,怎么处理?** 先按"是否有公开 PoC + 是否可远程利用 + 是否暴露公网"排序,逐条手工复现,区分确认/待验证/误报(见[漏洞扫描工具.md](漏洞扫描工具.md))。
- **Q:爆破字典用哪个?** 基线用 rockyou.txt;线上用 SecLists 与定制规则;先小规模验证语法与目标耐受度。
- **Q:抓到的 pcap 从哪入手分析?** 先 capinfos 看概况 → editcap 切时间窗 → tshark 做协议/会话统计 → 按异常线索深入(见[流量分析工具.md](流量分析工具.md))。
- **Q:预算有限怎么做蓝队?** Wazuh + Sysmon + Suricata + Elastic Security(免费版)即可搭出可用的最小 SOC(见[防御监控工具.md](防御监控工具.md))。
- **Q:子域枚举结果太多怎么筛?** 先 dnsx 验证存活,再 httpx 收敛 Web 资产,最后按端口/指纹/技术栈去重排序(见[信息收集工具.md](信息收集工具.md))。
- **Q:扫描流量会触发 WAF/IDS 吗?** 会。建议控制速率(`-T2`/`--min-rate`、`--threads`)、随机 UA、必要时走代理分段进行,并在授权书中明确扫描行为。
- **Q:如何判断某个哈希能不能破?** 先 `hashid` 识别类型,再按速查表评估:无盐快哈希(MD5/NTLM)字典+规则基本可破;bcrypt/Argon2 只能靠优质字典(见[密码破解工具.md](密码破解工具.md))。

## 学习路径建议

1. 新手:先学 Nmap + Wireshark + Burp Suite(免费社区版),配合 DVWA 练习 Web 安全。
2. 进阶:学 Metasploit、sqlmap、hashcat,完成 HackTheBox 入门机器。
3. 实战化:以授权 SRC 项目或企业内网演练为场景,串联"信息收集→扫描→利用→报告"全流程。
4. 蓝队视角:用 Wazuh + Suricata + ELK 搭建小型 SOC,复现攻击流量做检测。

## 工具使用规范(SOP 要点)

1. **测试前**:核对授权书(范围/时间/手法),准备测试环境与回滚方案,通知相关方(IT/业务窗口)。
2. **测试中**:先小后大(先单点验证再批量)、先慢后快(控制速率与并发)、留痕(命令记录、截图、pcap)、越界即停并上报。
3. **测试后**:清理植入物(账号/后门/临时文件)、整理报告(漏洞清单/复现步骤/影响/修复建议)、数据按密级处理(加密存储、按期销毁)。
4. **工具管理**:工具来源可信(官方源/包管理器),定期更新;高危工具(Mimikatz、Cobalt Strike 等)专人专管、使用留痕。
5. **报告要素**:测试范围与时间、发现的漏洞分级(CVSS)、复现证据(请求/响应/截图)、修复建议、复测结果。

## 通用注意事项

- 工具版本差异大,命令参数以 `-h`/`--help` 与官方文档为准;本文命令示例基于常见稳定版本。
- 扫描结果必须人工复核,自动化工具误报率高(见[漏洞扫描工具.md](漏洞扫描工具.md)的误报处理章节)。
- 所有爆破类操作(密码、目录、参数)务必先评估目标耐受度,控制并发与速率。
- 使用代理(如 Burp/Proxychains)转发扫描流量,便于审计与隐蔽,同时注意合规留痕。
- 工具输出(报告、pcap、哈希)按敏感数据管理:加密存储、限制访问、用后销毁。
- 本模块文件可被 RAG 检索使用:检索命中后,请以各文件正文的命令与参数为准并结合官方文档复核。
