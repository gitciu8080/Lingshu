# 漏洞扫描工具

> 关键词:漏洞扫描,Nessus,OpenVAS,GVM,AWVS,Xray,Nuclei,Trivy,插件,扫描策略,误报处理,CVSS,漏扫报告,容器扫描,依赖扫描,扫描器对比

漏洞扫描是在授权范围内对资产批量探测已知漏洞的过程,是合规检查(等保)、上线验收与持续安全运营的基础环节。本文件介绍综合扫描器与专项扫描器,并给出结果解读与误报处理的方法论。所有扫描均须在授权书规定的目标与时间窗口内进行,严禁对未授权目标扫描。

## 综合扫描器

### Nessus(商业漏扫标杆)

- **用途**:企业级漏洞扫描与管理,插件库庞大(>20 万插件),支持网络、Web、配置、容器等多类扫描;报告专业,常用于合规与交付。
- **安装**:从 tenable.com 下载 Nessus Essentials/Professional,`dpkg -i Nessus-*.deb` 后访问 `https://localhost:8834` 完成激活(需注册账号拿激活码)。
- **扫描策略(Scan Policy)**:
  - Basic Network Scan:常规网络漏扫,最快。
  - Advanced Scan:自定义端口、凭据(认证扫描)、插件范围。
  - Web Application Tests:针对 Web 应用的专项扫描。
  - Credentialed Patch Audit:提供 SSH/域凭据后做补丁级审计,结果远准于非认证扫描。
  - 建议先做"发现(Discovery)"不跑漏洞插件,确认资产后再全量扫描,减少误报与干扰。
- **插件(Plugins)**:按家族(Family)组织,如 Apache、MySQL、Cisco;可启用/禁用指定插件;`Plugin ID` 是报告中的唯一编号,便于检索复现。
- **报告**:导出 PDF/HTML/CSV/Nessus(.nessus)格式;报告含 CVSS 评分、受影响资产、漏洞描述与修复建议。
- **核心命令(CLI 方式,可选)**:
```bash
nessuscli scan list
nessuscli scan new --name "scan1" --targets "10.0.0.0/24" --policy "Basic Network Scan"
nessuscli scan launch <scan-id>
```
- **输出解读**:按 Severity(Critical/High/Medium/Low)排序处理;Critical 优先复核,切勿直接全量上报,需人工验证(见"误报处理"节)。

### OpenVAS / GVM(Greenbone Vulnerability Management)

- **用途**:开源综合漏扫,前身是 Nessus 的开源分支;GVM 是 OpenVAS 的管理框架,含 Web 前端(Greenbone Security Assistant)。
- **安装**:
```bash
# Debian/Ubuntu 官方源安装(较繁琐,建议用 Greenbone Community Edition 文档步骤)
apt install gvm && gvm-setup && gvm-start
```
- **核心流程**:
  1. 创建 Target(目标主机/网段);
  2. 配置 Scan Config(扫描配置,如 Full and fast / Discovery);
  3. 运行 Task 并查看 Results;
  4. 按结果创建 Report 导出。
- **常用命令**:
```bash
gvm-cli --gmp-username admin --gmp-password xxx socket --xml "<create_target>...</create_target>"
```
- **输出解读**:Results 按威胁等级(NTL:None/Low/Medium/High)与 CVSS 展示;`OID` 对应插件编号,可反查细节。社区版插件更新有延迟,新漏洞覆盖不如商业版,适合预算有限的基线扫描。

### AWVS(Acunetix Web Vulnerability Scanner)

- **用途**:商业 Web 应用漏洞扫描器,擅长 OWASP Top 10 类 Web 漏洞(尤其 SQLi/XSS)与爬虫覆盖;内置 AcuSensor 与审计器可降低误报。
- **安装**:官网下载 Windows/Linux 安装包,提供 14 天试用;需 License。
- **核心使用**:
  - Add Target → 填 URL/登录态(支持录制登录序列解决登录后页面扫描);
  - 选 Scan Type(Full Scan / High Risk Vulnerabilities / SQL Injection 等);
  - 扫描后查看 Vulnerabilities 与 Evidence(证据含请求/响应报文)。
- **输出解读**:报告含漏洞详情、复现请求、修复建议;与 Nessus 交叉验证可大幅减少 Web 漏洞漏报。登录态配置不当会导致大量"未授权"假阴性,务必录制真实会话。

### Xray(被动代理式 Web 漏扫)

- **用途**:国产开源 Web 漏洞扫描器,支持被动代理模式(流量驱动)与主动模式;常配合 Burp 使用,流量经过 xray 自动检测漏洞,检测率高且隐蔽。
- **安装**:GitHub 下载对应平台二进制;配置 `config.yaml`。
- **核心命令**:
```bash
./xray_linux_amd64 webscan --listen 127.0.0.1:7777 --html-output xray.html   # 被动代理
./xray_linux_amd64 webscan --basic-crawler https://example.com --html-output out.html  # 主动爬取
./xray_linux_amd64 ws --poc poc-yaml-thinkphp-rce.yml https://example.com   # 指定 PoC 验证
```
- **输出解读**:结果按漏洞类型(如 SQL Injection、XSS、SSRF、任意文件读取)输出;被动模式需真实流量,主动模式可能触发 WAF。注意:漏洞利用类 PoC 只在授权场景使用。

### Nuclei(模板化漏洞验证,首选开源)

- **用途**:ProjectDiscovery 出品,基于 YAML 模板的快速漏洞检测引擎,社区模板库(nuclei-templates)数千个,覆盖 CVE、暴露面板、错误配置;速度快、输出结构化,是"扫描→验证"链条中的核心工具。
- **安装**:
```bash
go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest
nuclei -update-templates   # 更新模板库
```
- **常用命令**:
```bash
nuclei -u https://example.com -t cves/ -severity critical,high -o hits.txt
nuclei -l targets.txt -t exposures/ -t misconfiguration/ -stats -si 100
nuclei -u https://example.com -tags sqli -var target=example.com
nuclei -u https://example.com -t http/cves/2021/CVE-2021-41773.yaml -debug   # 验证单个 CVE
```
- **输出解读**:命中行含模板名、目标、漏洞标题;`-stats` 显示进度与命中统计;命中后务必用 `-debug` 或手工请求复现确认,避免模板误报。模板文件路径如 `http/cves/2021/...`,可用 `-tl` 列出已加载模板。

### Trivy(容器与依赖扫描)

- **用途**:云原生安全扫描器,扫描容器镜像、文件系统、Git 仓库、K8s 集群与依赖清单中的漏洞与密钥;开源免费,CI 集成方便。
- **安装**:`apt install trivy` 或 `curl -sfL https://raw.githubusercontent.com/aquasecurity/trivy/main/contrib/install.sh | sh`。
- **核心命令**:
```bash
trivy image nginx:1.22                        # 扫描镜像
trivy fs /path/to/project                     # 扫描项目依赖(go.mod/package-lock.json/pom.xml 等)
trivy repo https://github.com/org/repo        # 扫描远端仓库
trivy config ./terraform/                     # IaC 配置扫描(misconfig)
trivy image --severity CRITICAL,HIGH --ignore-unfixed nginx:1.22   # 只看有修复的漏洞
trivy image --format table --exit-code 1 image:tag                  # CI 中断构建
```
- **输出解读**:按 `Target(组件)/PkgName(包)/VulnerabilityID(CVE)/Severity/Fixed Version` 展示;`--ignore-unfixed` 过滤无修复版本的低价值项;重点修复有公开利用链的 CRITICAL 项。

## 扫描结果解读与误报处理

### 结果分级标准

- **CVSS v3 评分**:0.0~3.9 Low、4.0~6.9 Medium、7.0~8.9 High、9.0~10.0 Critical。
- **处理优先级建议**:
  1. Critical/High + 有公开 PoC/在野利用 → 立即修复/应急;
  2. 可远程利用(无需认证) → 优先于本地利用;
  3. 暴露在互联网 → 优先于内网;
  4. 无法复现的项 → 标记待验证,不直接关闭。

### 误报常见来源

- 非认证扫描看到的是"指纹猜测":如 Banner 版本号滞后、服务伪装(WAF/蜜罐)。
- 扫描器把"中间件默认页"误报为漏洞(如 Apache 默认页不是漏洞本身)。
- 凭据缺失导致"认证后漏洞"误报为"不存在"(假阴性方向)。
- 模板类工具(Nuclei)对响应匹配过宽,如仅匹配关键字未验证利用条件。

### 验证流程(降误报)

```bash
# 1) 手工复现:直接发送扫描器给出的 PoC 请求,观察响应
curl -i "http://target/vuln?file=../../etc/passwd"
# 2) 二次工具交叉验证(不同扫描器/不同插件)
nuclei -u http://target -t http/cves/2021/CVE-2021-41773.yaml -debug
# 3) 无 PoC 时,依据响应头/版本比对官方公告人工判断
# 4) 记录结论:确认(Exploitable/Applicable)、无法确认(Verify)、误报(False Positive)
```
- **管理建议**:维护"误报白名单"与"已验证漏洞库";每次扫描后由人工评审输出,再决定是否进入工单修复流程;保留复现证据截图/报文,供合规审计。

### 扫描策略建议

- 频率:上线前必扫;日常月度基线扫描;重大 CVE 公告后专项扫描。
- 范围:先小范围试点(1~2 台)调参,再全量;控制并发(如 nmap `--min-rate`、Nessus Max Checks)。
- 认证扫描优先:提供合法凭据可把误报率降低一个数量级,结果更接近真实风险。
- 与业务错峰:漏扫流量可能影响业务,选择维护窗口并评估 DoS 风险。

## 扫描器对比表

| 工具 | 类型/授权 | 适用场景 | 优势 | 劣势 |
| --- | --- | --- | --- | --- |
| Nessus | 商业(有免费版) | 企业级网络漏扫、合规报告 | 插件全、报告专业、认证扫描成熟 | 贵、重;免费版功能受限 |
| OpenVAS/GVM | 开源(GPL) | 预算有限的基线漏扫 | 免费、可自建、功能完整 | 插件更新滞后、误报偏多、部署复杂 |
| AWVS | 商业 | Web 应用专项扫描 | 爬虫强、Web 漏洞覆盖全、误报低 | 贵、仅 Web 场景 |
| Xray | 开源(社区版免费) | Web 被动扫描、与 Burp 联动 | 被动检测隐蔽、检测率高、轻量 | 主动模式易被 WAF 拦;高级功能需商业版 |
| Nuclei | 开源(MIT) | 漏洞验证、专项 CVE 排查 | 模板化、极快、可编排、社区模板多 | 需人工配置模板、依赖模板质量 |
| Trivy | 开源(Apache-2.0) | 容器/依赖/IaC 扫描、CI 集成 | 免费、覆盖面广、适合 DevSecOps | 不覆盖 Web 应用逻辑漏洞 |

## 常见问题与要点

- **扫描≠渗透**:扫描器只能发现"已知且可匹配"的漏洞,逻辑漏洞、组合利用链需人工测试(见[渗透框架与利用工具.md](渗透框架与利用工具.md))。
- **留痕与合规**:保存扫描任务、原始结果(nessus/xml/json)与报告,满足等保与审计要求。
- **授权边界**:扫描前确认目标归属与授权书有效期;发现超出授权范围的高危问题,按流程报告而非继续探测。
- **工具联动**:信息收集(见[信息收集工具.md](信息收集工具.md))→ 扫描 → 利用验证 → 修复 → 复扫闭环,是标准漏洞管理流程。
