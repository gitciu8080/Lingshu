# 防御监控工具

> 关键词:防御监控,EDR,Wazuh,Falco,Sysmon,EventLog,Suricata,Snort,Zeek,SIEM,ELK,Elastic Security,Graylog,蜜罐,Honeyd,T-Pot,Cowrie,基线核查,OpenSCAP,lynis,安全众测,商业安全产品,奇安信,深信服,CrowdStrike,SentinelOne,蓝队,SOC

防御监控(蓝队)以"看得见、拦得住、查得清"为目标:主机检测(EDR/日志)、网络检测(IDS/NDR)、日志集中与告警(SIEM)、欺骗防御(蜜罐)与配置基线核查。本文件介绍主流开源防守工具与商业产品选型参考,帮助搭建可落地的安全运营体系。

## 主机侧检测与响应(EDR/HIDS)

### Wazuh(开源 HIDS/SIEM/合规一体)

- **用途**:开源主机入侵检测 + 日志收集 + 文件完整性监控(FIM)+ 漏洞检测 + 合规基线(PCI-DSS/GDPR 等),代理(Agent)部署于被监控主机,服务端聚合告警。
- **架构**:Wazuh Manager(服务器)+ Agents(主机)+ 可选索引器(Indexer/Dashboard,基于 OpenSearch)。
- **安装**:
```bash
# 服务器端(建议用官方 quickstart 脚本或包管理)
curl -s https://packages.wazuh.com/4.x/wazuh-install.sh | bash -s -- -a
# 客户端(agent)安装后指向服务器
Wazuh Agent 安装包安装后:
/var/ossec/bin/agent-auth -m <manager-ip> -A <agent-name>
systemctl start wazuh-agent
```
- **常用功能与命令**:
  - 日志收集:agent 采集系统日志(Windows EventLog、Linux syslog、应用日志)上传分析;
  - FIM:`/var/ossec/etc/ossec.conf` 配置 `<syscheck>` 监控目录(如 `/etc`、`/usr/bin`),检测文件增删改;
  - 告警查看:Web 控制台(Security events 页)或 CLI:
```bash
/var/ossec/bin/wazuh-logtest                      # 本地测试规则
grep -i "level 10" /var/ossec/logs/alerts/alerts.json   # 查高危告警
```
  - 规则:自带规则集在 `/var/ossec/ruleset/rules/`,可自定义 xml 规则。
- **输出解读**:告警含 `rule.level`(0~15,≥10 为严重)、`agent.name`、`description`;典型告警:登录失败爆破、新增启动项、可疑 shell 命令、关键文件被改;与 Suricata 联动(读 eve.json)可实现网络+主机统一告警。

### Falco(容器与云原生运行时安全)

- **用途**:CNCF 项目,基于内核 eBPF 的运行时安全检测,专攻容器/K8s:检测异常进程执行、容器逃逸尝试、敏感文件读写、特权容器等。
- **安装**:
```bash
curl -fsSL https://falco.org/repo/falco.deb | bash   # 或用 helm 部署到 K8s
apt install falco
```
- **核心命令与配置**:
```bash
falco --version
falco -r /etc/falco/falco_rules.yaml -e event_generator 2>&1 | head   # 用事件生成器测试
# 规则示例(/etc/falco/falco_rules.yaml):
# - rule: Terminal shell in container
#   desc: ...
#   condition: spawned_process and container and shell_procs
#   output: ...
#   priority: WARNING
```
- **输出解读**:输出行含 `rule`、`priority`、`evt.time`、`container.id`、`proc.cmdline`;典型告警:`Executing binary not part of base image`、`Unexpected outbound connection destination`;优先级从 EMERGENCY 到 DEBUG,重点处理 CRITICAL/ERROR/WARNING。
- **要点**:Falco 规则基于条件表达式(如 `spawned_process`、`container`、`k8s.ns.name`),可自定义;误报需按业务画像调优(白名单进程/镜像)。

### Sysmon + Windows EventLog(Windows 日志采集)

- **用途**:Sysmon 是微软 Sysinternals 工具,通过内核驱动记录进程创建、网络连接、文件创建、注册表变更等**细粒度**日志到 EventLog(事件 ID 1/3/5/11/13 等),是 Windows 取证与检测的事实标准,常与 SIEM 配合。
- **安装与配置**:
```bash
# 下载 Sysmon(微软官方)与配置模板(如 SwiftOnSecurity/sysmon-config)
Sysmon64.exe -accepteula -i sysmon-config.xml
Sysmon64.exe -c                            # 查看当前配置
# 事件查看器:Applications and Services Logs/Microsoft/Windows/Sysmon/Operational
```
- **关键事件 ID 速查**:
  - `1` 进程创建(含命令行,检测恶意命令);
  - `3` 网络连接(检测 C2 出网);
  - `5` 进程终止;
  - `7` 镜像加载(检测 DLL 注入);
  - `11` 文件创建(检测 dropper/webshell);
  - `13` 注册表值变更(检测持久化);
  - `22` DNS 查询(检测 DNS 隧道/恶意域名)。
- **分析示例(用 PowerShell 查询)**:
```powershell
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Sysmon/Operational'; Id=1} |
  Where-Object {$_.Message -match 'powershell|cmd'} | Select-Object -First 20 TimeCreated, Message
```
- **要点**:Sysmon 不产生告警只产生日志,需 SIEM/规则引擎消费;配置过细会产生海量日志,需按需裁剪;EventLog 本身(安全日志 4624/4625/4688 等)是另一重要来源(登录审计、进程审计)。

## 网络侧检测(IDS/NDR)

- **Suricata / Snort / Zeek** 的部署、规则与告警解读详见[流量分析工具.md](流量分析工具.md),此处补充部署要点:
  - **部署位置**:核心交换/路由的镜像口(SPAN)或 TAP 旁路;云环境用 VPC 流日志 + 安全组审计;
  - **Suricata 内联(IPS)**:`-q` 队列模式 + iptables NFQUEUE 可阻断,生产建议先观察(alert)后启用(drop);
  - **规则管理**:`suricata-update` 定期更新 ET Open/ET Pro;自定义规则放单独 sid 段(≥1000000)避免冲突;
  - **Snort**:老牌 IDS,社区规则集(Community Rules)更新节奏慢,适合教学与小型环境;
  - **Zeek**:侧重会话元数据与协议日志,与 Suricata 互补(见流量分析篇)。
- **典型检测内容**:横向扫描、暴力破解(登录失败频率)、C2 回连(域名/端口/UA 特征)、挖矿矿池通信、DNS 隧道。

## SIEM 轻量方案

### ELK / Elastic Security

- **用途**:Elasticsearch(存储/检索)+ Logstash(采集/解析)+ Kibana(可视化)构成 ELK;Elastic Security 在 ELK 之上提供 SIEM 能力(规则检测、事件关联、威胁情报)。
- **部署要点**:
  - Beats 采集器:Filebeat(文件日志)、Winlogbeat(Windows 日志)、Packetbeat(网络)、Metricbeat(指标);
  - 推荐架构:主机 → Filebeat/Winlogbeat → Logstash(解析)→ Elasticsearch → Kibana;小型环境可省 Logstash 用 Ingest Pipeline。
- **最小部署示例**:
```bash
# Ubuntu 上安装 Elasticsearch + Kibana + Filebeat(版本需一致,以 8.x 为例)
wget -qO - https://artifacts.elastic.co/GPG-KEY-elasticsearch | gpg --dearmor -o /usr/share/keyrings/elastic.gpg
# 安装 deb 包后配置 elasticsearch.yml(单节点)并启动
# Filebeat 配置 input 指向 /var/log/ 与 Sysmon 日志,output 指向 ES
```
- **典型查询(Kibana / ES DSL)**:
```text
event.action: "User Logon" AND winlog.event_id: 4624
process.name: "powershell.exe" AND process.command_line: ("-enc" OR "IEX")
event.module: suricata AND suricata.eve.alert.severity: 1
```
- **输出解读**:Kibana Discover 按时间线过滤;Security → Rules 可启用检测规则(Sigma 规则可转 Elastic 规则);告警关联时间线(案件调查)。
- **资源建议**:单机演示 8GB 内存起步;生产按日志量规划节点,注意磁盘与索引生命周期管理(ILM)。

### Graylog

- **用途**:轻量日志管理/告警平台,Java 生态,内置 Pipeline 处理与告警,部署比 ELK 简单,适合中小环境。
- **安装**:`apt install graylog-server` 或官方镜像;需 MongoDB + Elasticsearch/OpenSearch 支撑。
- **要点**:输入(Input)接收 syslog/GELF;Pipeline 做解析与字段提取;Alert 规则基于查询与时间窗口触发通知(邮件/Webhook);查询语法类 Lucene,`source:"wazuh" AND level:10`。

### SIEM 选型对比

| 方案 | 优势 | 劣势 | 适用 |
| --- | --- | --- | --- |
| Elastic Security | 功能全、规则库大、可视化强 | 资源消耗大、调优复杂 | 中大型 SOC、已有 ES 团队 |
| Graylog | 部署简单、上手快 | 分析能力弱于 ES、扩展性一般 | 中小团队日志集中与告警 |
| Wazuh(兼 SIEM) | 一体化(代理+告警+合规) | 大规模性能有限 | 小规模 HIDS+合规基线 |

## 蜜罐与欺骗防御

- **用途**:布置诱饵系统/服务,诱导攻击者交互,获取攻击手法(IOC、C2、武器化样本),消耗攻击资源并提升检测响应时间。
- **Honeyd(经典轻量蜜罐)**:模拟数千个虚拟主机与 IP,虚拟服务响应;`apt install honeyd`,配置文件 `honeyd.conf` 声明模板:
```conf
create default
set default personality "Microsoft Windows NT 4.0"
set default default tcp action reset
bind 192.168.1.100 tcp port 80 proxy 10.0.0.1:80
```
- **Cowrie(SSH/Telnet 交互蜜罐)**:记录攻击者敲击的完整命令、上传的文件与 shell 会话;Docker 部署:
```bash
docker run -p 2222:2222 -v cowrie-logs:/cowrie/cowrie-git/log cowrie/cowrie
# 日志:log/cowrie.json(含 commands、session、src_ip)
```
- **T-Pot(多蜜罐平台)**:集成 20+ 蜜罐(Dionaea、Cowrie、Honeytrap 等)+ Elastic Stack + 攻击可视化地图,一键 Docker 部署,适合安全研究/蜜网实验。
- **部署要点**:蜜罐须与生产网络**隔离**(独立 VLAN/云账号),防止被当作跳板;蜜罐交互要有度,避免成为恶意软件传播源;高交互蜜罐(真实系统)风险高,优先低交互;告警优先级:蜜罐流量几乎必然为恶意,检测价值高。

## 漏洞与配置基线核查

### OpenSCAP(合规自动化)

- **用途**:SCAP 标准实现,自动化配置核查与漏洞评估,内置 CIS/PCI-DSS/等保相关 OVAL/SSG 内容;生成合规报告。
- **安装**:`apt install openscap-scanner scap-security-guide`。
- **常用命令**:
```bash
oscap xccdf eval --profile xccdf_org.ssgproject.content_profile_cis \
  --results results.xml --report report.html /usr/share/xml/scap/ssg/content/ssg-rhel9-ds.xml
oscap oval eval --results oval-results.xml ssg-rhel9-ds.xml   # 漏洞(OVAL)评估
```
- **输出解读**:报告按 profile 逐项 pass/fail/notapplicable,含修复建议;`results.xml` 可对接其他平台;常用于等保自查与上线基线。

### Lynis(轻量安全审计)

- **用途**:单文件 Shell 脚本,快速审计 Linux/Unix 系统安全配置(权限、补丁、服务、防火墙、日志等),输出分数与建议,适合日常巡检。
- **安装**:`apt install lynis` 或下载源码。
- **常用命令**:
```bash
sudo lynis audit system --logfile /var/log/lynis-report.dat
sudo lynis show details --logfile /var/log/lynis-report.dat   # 查看上次结果
```
- **输出解读**:`Hardening index` 分数(越高越好)、`[WARNING]`/`[SUGGESTION]` 列表、`[FINDING]` 关键项;逐条整改建议项即可提升基线;可配合 cron 定期巡检。
- **补充**:主机基线也可用 Wazuh 的 CIS 策略模块统一管理;`testssl.sh` 用于 TLS 基线核查(见下文 SSL 相关可并入)。

## 安全众测平台说明

- **用途**:企业将授权范围内的系统/App/小程序发布到众测平台,由注册白帽(经实名与协议约束)在**明确规则**下提交漏洞,企业验收后按漏洞等级付费,是"合法、可控、按效果付费"的众包渗透模式。
- **国内主流平台**:补天(奇安信)、漏洞盒子(Vulbox)、火线安全、CNVD 平台(国家)、各厂商 SRC(漏洞响应中心,如腾讯 TSRC、阿里 ASRC、字节跳动 SRC)。
- **参与注意**:仅可在平台明确授权的项目范围内测试;遵守平台规则(禁止 DoS、社会工程、数据下载超限、二次利用);漏洞报告需包含复现步骤与影响评估;积分/奖金体系差异大,认真阅读 SRC 评分标准(危害定级)。
- **企业视角**:众测作为渗透测试的补充(持续发现),需与常规漏扫、渗透测试节奏配合,并做好资产范围管理与报告闭环。

| 厂商/产品 | 类别 | 定位与特点 | 适用 |
| --- | --- | --- | --- |
| 奇安信(天眼/椒图/态势感知) | NDR/EDR/态势感知 | 国产全栈,天眼流量分析+椒图主机防护,等保生态完善 | 政企、等保合规 |

| 360(安全大脑/终端安全) | 端点/云安全 | 大数据威胁情报强,终端防护覆盖广 | 互联网企业、政企 |
| CrowdStrike Falcon | 云原生 EDR/XDR | 单代理架构、检测响应速度业界领先,基于云 | 中大型企业、跨国合规 |
| SentinelOne Singularity | EDR/XDR | 自主 AI 检测与自动响应(含 rollback),部署轻 | 中大型企业 |
| Microsoft Defender for Endpoint | EDR | 与微软生态(AD/365)集成好 | 微软系企业 |

- **选型参考思路**:先明确需求(合规/检测/响应/预算/团队能力)→ 对比功能覆盖(EDR 检测率、XDR 联动、报告合规性)→ PoC 试运行(真实流量与样本测试)→ 评估部署复杂度与人力成本;开源方案(Wazuh+Suricata+ELK)可作为预算有限时的可行替代。

## 落地建议(最小蓝队架构)

1. **主机**:全员部署 Wazuh Agent(+Windows 装 Sysmon),关键服务器加 Falco(容器环境);
2. **网络**:核心出口/关键网段镜像口接 Suricata(先 alert),旁路 Zeek 做全量元数据;
3. **集中**:Filebeat/Winlogbeat 汇聚到 Elastic Security,接入 Wazuh/Suricata 告警,启用常用检测规则(Sigma);
4. **欺骗**:内网放 1~2 台 Cowrie + T-Pot,蜜罐告警优先级最高;
5. **流程**:每日告警研判 → 周报指标(告警量/误报率/MTTD/MTTR)→ 季度基线核查(OpenSCAP/Lynis)→ 定期红蓝演练验证检测有效性。
