# 合规与标准 — 模块说明

> 关键词:合规、安全标准、等级保护、等保2.0、ISO 27001、NIST CSF、渗透测试标准、监管合规、安全框架、合规驱动安全建设

## 什么是"合规与标准"

"合规与标准"是网络安全知识体系中描述**组织必须遵守的外部约束**与**行业公认的最佳实践**的模块,回答三个问题:

1. **必须做什么**(强制):法律法规、监管规定、国家标准、行业规范,违反将面临行政处罚、业务停摆甚至刑事责任;
2. **应该怎么做**(推荐):国际标准与最佳实践框架,如 ISO/IEC 27001、NIST CSF,用于体系化建设安全管理能力;
3. **如何证明做到**(验证):等级测评、渗透测试、审计、认证评估,用可核验的过程与结果向监管方、客户和第三方证明合规状态。

合规不是单点技术措施,而是**"法律 + 标准 + 评估验证"三位一体**的闭环:法规给出底线,标准给出方法,测评/测试给出证据。

## 合规的分类

| 类型 | 性质 | 典型来源 | 示例 |
| --- | --- | --- | --- |
| 强制合规 | 必须满足,违反有法律后果 | 法律法规、部门规章、监管要求 | 《网络安全法》《数据安全法》《个人信息保护法》、等保2.0、金融行业监管规定 |
| 契约合规 | 按合同/协议履行,违反承担违约责任 | 客户合同、供应商协议、平台规则 | 客户合同中约定的安全条款、渗透测试授权书 |
| 自愿/认证合规 | 自愿追求,换取信任与市场准入 | 国际标准、行业最佳实践 | ISO 27001 认证、SOC 2 报告、NIST CSF 应用 |
| 内部合规 | 组织自行设定 | 内部制度、安全策略、基线 | 密码策略、数据分级制度、SDL 流程 |

强制合规是底线,自愿合规是竞争力;实践中常出现"客户要求 ISO 27001 证书 + 监管要求等保三级 + 行业要求渗透测试"的多重叠加。

## 为什么重要

### 监管处罚风险

- 中国《网络安全法》确立了网络安全等级保护制度的法律地位,对未履行等保义务、造成危害后果的单位,相关条款规定了警告、罚款、责令整改直至暂停业务、关闭网站的处罚;对直接负责的主管人员同样可处罚款。
- 《数据安全法》《个人信息保护法》施行后,违法处理重要数据、个人信息的行为面临高额罚款(个保法相关条款设定最高五千万元以下或上一年度营业额百分之五以下的罚款)。
- 欧盟 GDPR 对严重违法行为的罚款上限为 2000 万欧元或全球年营业额的 4%,取较高者。
- 监管手段常态化:网络安全检查、攻防演练、通报批评、约谈、限期整改,合规问题直接进入监管视野。

### 招投标与市场准入

- 政府与国企采购中,**等保三级测评报告、ISO 27001 认证、渗透测试报告**常被列为资质门槛或评分项;
- 金融、医疗、教育、能源等行业有专项监管要求,未达标将影响业务许可、新增业务审批与供应商准入;
- 供应链安全审查中,供应商的合规资质(如 SOC 2 报告、等保证书)成为客户评估的重要依据。

### 安全建设牵引

- 合规要求往往是最容易获得预算支持的安全投入理由,"以合规为抓手"推动安全体系从无到有;
- 标准框架(ISO 27001、NIST CSF)提供了覆盖组织、人员、流程、技术的完整建设蓝图,避免零散采购安全产品;
- 等级测评、渗透测试暴露真实差距,形成"差距分析 → 整改 → 复测"的持续改进循环。

## 合规风险管理流程

| 步骤 | 工作内容 | 常用方法/产出 |
| --- | --- | --- |
| 合规识别 | 梳理组织适用的法律法规、标准、合同义务,建立合规义务清单 | 合规义务登记表、合规地图 |
| 差距分析 | 将现状与要求逐项比对,识别差距与风险 | 差距分析报告、整改计划 |
| 整改实施 | 技术整改(加固、产品、配置)+ 管理整改(制度、流程、人员) | 整改记录、复测报告 |
| 验证评估 | 通过测评、测试、审计、认证验证合规状态 | 等级测评报告、渗透测试报告、认证证书 |
| 持续监测 | 跟踪法规变化与监管动态,定期复评 | 合规例会、年度复测、法规跟踪简报 |

## 各行业合规要点概览

| 行业 | 主要监管依据/要求 | 高频合规动作 |
| --- | --- | --- |
| 政务/公共机构 | 《网络安全法》、等保2.0、政务信息系统整合共享要求 | 等保定级备案、三级系统年度测评、攻防演练 |
| 金融(银行/证券/保险) | 金融监管机构网络安全要求、等保、数据分类分级 | 年度渗透测试、攻防演练、灾备建设、数据安全评估 |
| 医疗健康 | 《数据安全法》、医疗数据管理办法、等保 | 等保测评、患者隐私数据保护、重要数据评估 |
| 教育 | 教育行业数据安全要求、等保 | 信息系统备案、学生个人信息保护 |
| 能源/工控 | 关键信息基础设施保护、等保工控扩展要求 | 工控系统测评、CII 认定与保护、供应链安全 |
| 互联网/平台 | 《个人信息保护法》、算法与平台治理要求 | 个保法合规、隐私政策、个人信息保护影响评估(PIA) |
| 出海企业 | GDPR、数据出境管理 | 跨境传输合规、海外分支机构认证、DPO 设置 |

行业要求通常在等保基础上叠加:金融重"持续测试与演练",医疗重"隐私与数据分级",工控重"物理隔离与扩展要求"。

## 合规、安全与风险的关系

- **合规 ⊂ 安全**:合规是安全的最低要求集合,不等于安全;一个"合规"的系统仍可能被攻破,但合规缺失的系统风险更高、问责更重;
- **合规是风险治理的输入**:合规义务本身是组织面临的一类风险(法律风险、声誉风险),合规管理是风险管理(如 ISO 31000 思路)在法规维度的落地;
- **证据思维**:合规的核心是"可证明",所有措施都要能拿出记录(测评报告、测试报告、制度、日志、演练记录),证据缺失等于未做;
- **动态平衡**:合规要求会随法规与标准版本演进,安全投入需同时覆盖"合规基线"与"真实风险"两条线,避免只盯着检查表。

## 常见合规误区

- **把合规当终点**:测评通过/证书到手即停止投入,忽视了合规是"最低要求",真实风险远高于合规边界;
- **重文档轻落地**:制度写了一大套,执行与验证缺失,检查与测评时原形毕露;
- **照搬模板**:直接套用其他行业的测评整改清单或制度模板,与自身系统、业务不匹配;
- **混淆测评与测试**:等级测评是合规核查,渗透测试是深度验证,一个替代不了另一个;
- **忽视扩展要求**:云上系统、工控系统、移动应用只做通用要求,漏掉扩展要求导致测评不过;
- **数据合规缺位**:重系统安全、轻数据与个人信息保护,而数据安全法/个保法处罚力度更大;
- **法规更新滞后**:等保2.0、NIST CSF 2.0、ISO 27001:2022、CIS v8 等新旧版本差异大,仍按旧版执行导致要求遗漏。

## 使用建议

- **先定级再建设**:中国境内网络运营者先按《网络安全法》与定级指南确定系统等级,再按对应等级要求建设;
- **内外结合**:面向国内监管用等保体系,面向国际客户/出海业务用 ISO 27001 与 SOC 2,两者可互补复用大部分管理措施;
- **测试验证不可省**:合规文件与制度只是起点,等级测评、渗透测试、审计才是发现真实风险的手段;
- **优先高风险项**:预算有限时,优先整改测评中的高风险项与渗透测试发现的高危漏洞,再逐步补齐中低风险项;
- **持续跟踪更新**:等保 2.0 标准体系、NIST CSF 2.0、ISO 27001:2022、CIS Controls v8 均较旧版有重大调整,引用时注意版本与年份。
