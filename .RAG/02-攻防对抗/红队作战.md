# 红队作战

> 关键词:红队,攻击模拟,渗透测试,ATT&CK,杀伤链,侦察,武器化,投递,利用,C2,命令与控制,免杀,白名单,Living off the Land,权限维持,红队报告,TTP

## 红队是什么

红队(Red Team)是以**目标导向**方式模拟真实攻击者的专业团队。与常规渗透测试不同,红队不满足于"找出漏洞",而是站在攻击者视角回答:**"如果对手真的想打进来,能打多深、造成多大影响、我们能否及时察觉?"** 红队活动必须基于明确的授权范围(Scope)与规则(Rules of Engagement, RoE),通常在独立网络、影子 IT 资产或专用靶场环境中进行。

### 红队 vs 渗透测试

| 维度 | 渗透测试 | 红队 |
|---|---|---|
| 目标 | 发现漏洞并出具修复清单 | 达成业务级目标(域控权限、核心数据、物理入侵等) |
| 时间 | 数天至数周,范围明确 | 数周至数月,范围常含边界外社工、物理等 |
| 隐蔽性 | 低,通常不做规避 | 高,需绕过检测、尽量不被发现 |
| 产出 | 漏洞报告 | 攻击路径 + 检测缺口 + 改进建议 |

## 红队工作流程

1. **授权与规则确认**:签署授权书,确认目标范围、禁则(禁用的破坏性手段)、时间窗口、紧急联系人。
2. **情报收集(OSINT)**:域名、子域名、证书、员工信息、GitHub 泄露、招聘信息等公开情报;判断技术栈与暴露面。
3. **目标建模**:梳理资产清单、关键业务、入口点(边界、VPN、邮件、供应链),确定攻击路径规划。
4. **攻击执行**:按杀伤链推进,记录每步时间、手法、检测情况;保持隐蔽。
5. **横向移动与提权**:从初始立足点扩大控制,向核心目标推进。
6. **权限维持**:建立持久化,模拟长期潜伏攻击者。
7. **报告与复盘**:输出攻击路径、影响证明(PoC, 破坏性最小化)、检测缺口清单;与蓝队复盘。

## ATT&CK 框架应用

MITRE ATT&CK 是红蓝双方的**共同语言**。红队用它:
- **规划攻击路径**:按战术(侦察、初始访问、执行、持久化、提权、防御规避、凭据访问、发现、横向移动、收集、C2、影响)选择技术组合。
- **对标真实威胁**:参考已知 APT 组织的 TTP 映射,使模拟贴近现实威胁。
- **汇报成果**:用 ATT&CK 战术-技术映射表说明"我们打到了哪一层"。

ATT&CK 战术→典型技术示例(T1003 凭据转储、T1059 命令与脚本解释器、T1021 远程服务、T1078 有效账户、T1136 创建账户、T1098 账户操作、T1105 工具传输、T1071 应用层协议通信、T1568 动态解析、T1041 通过 C2 通道外传数据等)。**防御视角**:将 EDR/SIEM 检测规则按战术维度建目录,确保每个战术至少有一条可落地的检测。

## 杀伤链(Kill Chain)

Lockheed Martin 杀伤链将攻击分为七阶段,红队据此组织攻击节奏:

1. **侦察(Reconnaissance)**:收集目标信息——子域名枚举、端口扫描、Web 指纹、员工社交信息。
2. **武器化(Weaponization)**:将漏洞与载荷绑定,如制作钓鱼附件、构造恶意文档、生成免杀木马。
3. **投递(Delivery)**:通过邮件、Web 下载、USB、供应链等途径送达载荷。
4. **利用(Exploitation)**:触发漏洞或诱骗执行,获得初始代码执行。
5. **安装(Installation)**:安装后门/植入物,建立持久化。
6. **命令与控制(C2)**:建立失陷主机与攻击者服务器之间的隐蔽通信信道。
7. **行动(Actions on Objectives)**:数据窃取、加密勒索、破坏等最终目标。

### 杀伤链的防御启示(每阶段至少一道防线)

| 阶段 | 检测点 | 防御手段 |
|---|---|---|
| 侦察 | 大量子域查询、端口扫描、目录爆破流量 | 隐藏/收敛暴露面、限制扫描(IDS/WAF 告警) |
| 武器化 | 恶意宏、混淆脚本、异常文件特征 | 文件沙箱分析、宏禁用策略 |
| 投递 | 钓鱼邮件、可疑附件、异常外链 | 邮件网关、URL 信誉过滤、安全意识 |
| 利用 | 漏洞利用特征、异常进程行为 | 补丁管理、EDR 行为检测、应用白名单 |
| 安装 | 新增计划任务/服务/注册表项 | 持久化行为监控、基线比对 |
| C2 | 异常外连、DNS 隧道、Beacon 流量 | 出站访问控制、NDR 检测 |
| 行动 | 大量文件读取/打包/外传 | 数据防泄漏(DLP)、敏感操作审计 |

## C2(命令与控制)基础设施与流量特征

C2 是红队维持控制的核心,也是蓝队检测的重点。

### 基础设施形态
- **重定向器(Redirector)**:前置 CDN/云函数/反向代理隐藏真实 C2 服务器。
- **域名轮换与动态解析**:Fast-flux(多 IP 轮换)、Domain Generation Algorithm(DGA, 域名生成算法)、付费域名仿冒。
- **高防与低慢信道**:利用 HTTPS 443、DNS、HTTP 隧道混入正常流量。
- **多级 C2**:一级(边缘)→ 二级(内网)分层,降低单点暴露风险。

### 常见流量特征(蓝队检测点)
- **Beacon 规律性**:固定间隔的心跳(如每 60 秒一次),间隔抖动可识别。
- **JA3/JA3S 指纹**:TLS 客户端指纹与正常浏览器/系统不一致。
- **DNS 异常**:DNS TXT 隧道、高熵子域名、长域名、异常查询频率。
- **HTTP 特征**:UA 缺失或不常见、POST 频率异常、请求头顺序异常、Base64 特征、隧道模式(如 HTTP 隧道头部异常)。
- **外连模式**:非工作时间外连、单一进程持续外连、目的 IP 归属云厂商且无业务关联。

### C2 检测与处置建议
- 部署 NDR/流量分析,建立出站连接基线并告警偏离。
- 在出口防火墙按业务需求实施**出站白名单**,限制内部主机直连互联网。
- 对 TLS 流量做 SSL 解密检测(合规前提下)或基于 JA3 指纹做信誉匹配。
- 失陷确认后:**先断外连、再取证、后清杀**,避免直接拔网线导致内存证据丢失。

## 隐蔽与规避

### 免杀思路(检测对抗,方法论层面)
- **特征免杀**:修改恶意样本静态特征——换壳、加花指令、混淆字符串、改变编译特征。
- **行为免杀**:将恶意行为拆散、延迟、交替执行,绕过行为检测的时间窗。
- **内存执行**:无文件落地,通过 PowerShell、WMI、Office 宏等在内存中加载执行(注意:这同样属于防御方重点检测行为)。
- **签名伪造**:窃取/伪造合法代码签名,或利用未撤销的过期证书。
- **白利用与 LOLBin**:见下。

**防御视角**:EDR 应重行为检测轻静态特征;启用攻击面减少(ASR)规则;限制脚本执行环境(如 PowerShell Constrained Language Mode、AMSI)。

### 白名单利用(Trusted Utilities)
利用系统自带或被信任的合法工具执行恶意操作,常见清单:

| 系统工具 | 常见滥用方式 |
|---|---|
| PowerShell | 内存加载、远程脚本执行、绕过执行策略 |
| WMI(wmic/mofcomp) | 远程命令执行、持久化 |
| MSHTA / Rundll32 | 执行远程恶意脚本/载荷 |
| Regsvr32 | 加载远程 COM 组件 |
| Certutil | 下载文件、Base64 编解码 |
| Bitsadmin | 隐蔽下载、持久化 |
| Schtasks / 服务 | 计划任务持久化 |
| Windows 自带 LOLBin(Living Off the Land Binaries) | 横向移动、提权、代理 |

**防御视角**:即使工具合法,也应监控其**异常调用上下文**——如 PowerShell 由 Office 进程启动、Certutil 访问陌生域名、wmic 发起远程进程创建。

### Living off the Land(LotL)
尽量不引入外部工具,完全使用目标环境已有的二进制、脚本与协议完成攻击,降低文件落地检测率。蓝队应对:**文件哈希白名单失效场景下,重点做行为基线**;对高价值主机启用 Sysmon 详细日志(Process Creation、Network Connection、DNS Query、File Create)。

## 权限维持

攻击者在获得立足点后建立持久化,常见手法:
- **计划任务/启动项**:注册表 Run 键、启动文件夹、计划任务、服务。
- **账户操纵**:创建隐藏账户、修改现有账户组成员、克隆管理员令牌。
- **凭据窃取复用**:抓取 LSASS 内存、DCSync 同步域凭据、哈希传递(Pass-the-Hash)。
- **Web 后门**:在 Web 应用植入 Webshell、修改应用配置。
- **内网隧道**:SSH 反向隧道、代理工具维持内网访问。

**防御视角**:定期审计账户与权限(禁用长期不用的管理员账户)、监控计划任务/服务/启动项变更、部署特权账户管理(PAM)、对域控启用凭据保护(LSA Protection、Credential Guard)。

## 报告与复盘

### 红队报告结构
1. **执行摘要**:目标达成情况、最高影响、管理层可读结论。
2. **攻击时间线**:每个阶段的起止时间、手法、证据。
3. **技术细节**:漏洞、利用链、复现步骤、截图(脱敏)。
4. **检测缺口**:蓝队未能发现的具体环节及建议。
5. **修复建议**:按优先级(紧急/高/中/低)列出整改项。
6. **附录**:使用的 TTP、ATT&CK 映射、IOC(失陷指标)清单。

### 复盘要点
- 与蓝队共同回顾**每个阶段的检测盲区**,而非互相指责。
- 输出可复用的检测规则与狩猎假设。
- 明确整改责任人与截止时间,跟踪闭环。
- 红队自评:目标是否达成、隐蔽性如何、报告是否可执行。

## 红队项目启动要素(RoE 关键字段)

| 要素 | 说明 | 示例 |
|---|---|---|
| 目标范围 | 允许攻击的资产清单与边界 | 指定域名段、IP 段、系统,明确"禁区" |
| 禁则 | 明确禁止的行为 | 禁止 DoS、禁止删除数据、禁止破坏可用性 |
| 时间窗口 | 攻击行为允许的起止时间 | 每日 9:00–21:00,或全程 7×24 |
| 联系方式 | 紧急叫停与问题上报通道 | 蓝队 24h 值班电话、双方联络人 |
| 数据边界 | 允许接触与获取的数据范围 | 仅规则指定的"目标文件/目标系统" |
| 报告要求 | 证据保留与报告交付标准 | 攻击时间线、复现步骤、IOC 清单 |

授权书建议由法务审核,明确责任边界与保密义务;授权不完整时应**拒绝启动**。

## 侦察技术要点

| 侦察对象 | 常用手段 | 蓝队检测/缓解 |
|---|---|---|
| 子域名 | 证书透明度日志(CT 日志)、字典爆破、搜索引擎 | 收敛子域名、监控 DNS 解析异常 |
| Web 应用 | 指纹识别、目录爆破、JS 文件分析 | WAF、目录访问告警 |
| 邮箱/员工 | OSINT、泄露库查询、LinkedIn | 管控公开信息、员工隐私教育 |
| 网络边界 | 端口扫描、Banner 抓取、服务识别 | IDS/NDR 扫描告警、端口收敛 |
| 供应链 | 供应商官网、招聘信息、代码仓库 | 供应链风险评估、第三方接入审计 |

**OPSEC 要点**:控制扫描频率与并发、使用代理/跳板、避免在同一 IP 上长时间操作、侦察与利用分离账户与通道,降低被溯源概率。

## 投递方式对比

| 投递方式 | 成功率 | 暴露风险 | 适用场景 |
|---|---|---|---|
| 钓鱼邮件(附件/链接) | 中高 | 中(可被网关拦截) | 常见首选,社工结合效果更佳 |
| Web 漏洞利用 | 中 | 低(利用流量即业务流量) | 目标 Web 暴露面大时 |
| 供应链(第三方/更新劫持) | 高 | 低 | 长期目标、高价值定向攻击 |
| USB 投递 | 低-中 | 高(物理痕迹) | 有物理接触条件时 |
| 水坑攻击 | 中 | 低 | 目标群体集中访问特定站点时 |

## 横向移动与提权(方法论)

- **横向移动常见路径**:SMB/WinRM/SSH 远程执行 → 内网服务漏洞 → 凭据复用(哈希传递、票据传递 Pass-the-Ticket)→ 组策略/脚本下发。
- **提权常见方向**:内核漏洞 → 服务配置错误(弱权限服务、可写服务路径)→ 计划任务滥用 → 令牌窃取 → 本地凭据文件(SAM、缓存)。
- **蓝队对应检测**:异常远程登录(源/目标/账户组合异常)、新进程从网络共享启动、可疑账户权限变更、NTLM/Kerberos 异常流量。

## 常见红队失误与质量保证

- **失误**:范围漂移(打到未授权资产)、动静过大提前暴露、证据丢失导致无法证明目标达成、报告缺少可执行修复建议、忽视 OPSEC 导致被溯源反制。
- **质量保证**:内部评审攻击路径合理性;行动日志(时间、命令、结果)双人核对;报告脱敏审查;演练结束后按规则清理植入物与测试账户。

## 合规与伦理红线

- 红队活动**必须取得书面授权**,明确目标、时间、范围、联系人;授权书应经法务审核。
- 禁则示例:不得破坏生产数据、不得发起拒绝服务、不得影响可用性、不得涉及第三方未授权资产。
- 演练环境建议:优先使用隔离靶场;涉及生产环境时严格限制高危动作。
- 所有攻击行为限于授权范围,超出范围立即停止并上报。
- 红队技术资料与工具按保密要求管理,防止外泄被恶意利用。
