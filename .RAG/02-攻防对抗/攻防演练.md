# 攻防演练

> 关键词:攻防演练,护网,HVV,实战攻防,沙盘推演,桌面演练,评分规则,禁则,时间窗口,暴露面收敛,进攻策略,防守策略,失分点,加分项,整改闭环,演练总结

## 攻防演练概述

攻防演练(Red vs Blue Exercise)是**在明确规则与授权下**,由红队模拟攻击、蓝队组织防御的对抗活动。国内最具代表性的是护网行动(HVV, 即国家级/行业级实战攻防演习):在指定时间窗口内,红队对目标单位发起真实攻击,检验其网络安全防护与应急处置能力。

演练的价值不在于"谁赢谁输",而在于**暴露真实风险、锻炼队伍、倒逼整改**。所有演练必须经组织授权,在规则约束与受控环境下进行。

## 演练类型

| 类型 | 特点 | 适用场景 | 组织成本 |
|---|---|---|---|
| 实战攻防(红蓝对抗) | 红队真实攻击目标系统,蓝队实时防守 | 检验整体防护与响应能力,如护网 | 高 |
| 沙盘推演 | 基于设定场景,双方在模拟环境推演攻防决策 | 检验策略与预案,不接触真实系统 | 中 |
| 桌面演练(Tabletop) | 围绕剧本讨论式推演,无真实攻击 | 检验流程、角色、沟通机制 | 低 |

**选择建议**:首次开展从桌面演练起步,成熟后升级为沙盘推演与实战攻防;不同层级演练形成年度计划。

## 规则设计

规则的完备性决定演练成败,组织方应在演练前发布并宣贯《演练规则书》。

### 评分规则(示例框架,以组织方实际规则为准)
- **红队得分**:突破目标系统、获取数据、达成指定目标(如拿到域控、控制业务系统)得分。
- **蓝队得分**:发现攻击、及时响应、成功阻断、溯源还原攻击链路得分。
- **双向扣分**:违规操作(破坏数据、影响业务、超范围攻击)扣分或取消资格。

### 禁则(典型)
- 禁止对演练范围外的系统发起攻击。
- 禁止破坏数据、删除业务数据、加密勒索式破坏。
- 禁止发起影响可用性的拒绝服务攻击(除非规则明确允许)。
- 禁止物理破坏、禁止社工针对未授权人员。
- 禁止在未授权情况下进行数据外传。

### 时间窗口
- 明确演练起止时间、每日作战时段(如 9:00–21:00)。
- 明确攻击行为允许的窗口(如夜间是否允许持续 C2)。
- 明确上报与响应的时限要求。

### 其他规则要素
目标资产清单与边界、紧急叫停机制(熔断)、事故分级与上报通道、红蓝双方联络人、成绩仲裁机制、数据与个人信息保护要求。

## 红队进攻策略

1. **前期侦察**:演练前利用公开信息摸清目标暴露面(域名、IP、应用、VPN、邮件系统、第三方接口)。
2. **多点试探**:边界入口(Web 漏洞、VPN、邮件网关、供应链)并行探测,寻找薄弱点。
3. **打点突破**:优先利用已知漏洞、弱口令、未修复高危 CVE;成功后快速建立隐蔽立足点。
4. **内网渗透**:枚举域环境,寻找提权与横向移动路径,向核心系统(域控、数据库、核心业务)推进。
5. **保持隐蔽**:使用白名单工具、减少文件落地、控制攻击频率,避开蓝队检测重点时段。
6. **目标达成**:按规则要求证明影响(如获取指定文件、控制指定系统),保留证据链。
7. **策略调整**:根据蓝队防守表现动态调整,攻击被发现的路径及时更换。

**红队得分技巧**:优先找"没人管的资产"(影子 IT、老旧系统、测试环境);关注默认口令与弱口令;利用供应链与第三方接口;注意蓝队休息与轮班薄弱时段(以规则允许为前提)。

## 蓝队防守策略

1. **赛前备战**:资产盘点与暴露面收敛、漏洞整改、日志全量接入、检测规则调优、人员排班与预案演练。
2. **战时值守**:7×24 轮班;告警分级处置;重点守护核心资产与易失分点(域控、VPN、邮件、数据库)。
3. **快速遏制**:发现攻击立即最小化隔离(断外连、主机隔离、禁用账号),先止损再溯源。
4. **溯源反制**:还原攻击路径,识别攻击手法与 IOC,反查红队基础设施(在规则允许范围内)。
5. **每日复盘**:统计当日攻击事件、防守盲区、调整次日策略;形成防守日报上报。
6. **事后整改**:演练结束按问题清单整改,验证闭环。

**蓝队得分技巧**:关键日志必须全(AD、DNS、防火墙、EDR);高置信告警秒级响应;处置过程全程留痕;主动威胁狩猎发现"无声攻击"可获得额外加分。

## 互联网暴露面收敛(演练前必做)

| 检查项 | 具体动作 |
|---|---|
| 端口收敛 | 关闭非必要公网端口,仅保留业务必需;变更后复扫验证 |
| 服务下线 | 下线测试系统、演示系统、无人认领的老旧服务 |
| 弱口令治理 | 修改默认口令、弱口令;核查 VPN/邮箱/堡垒机账户 |
| 补丁加固 | 修复高危 CVE;无法修复的加缓解措施(WAF 规则、访问控制) |
| 防扫描 | 关注扫描器指纹暴露;对核心系统启用访问控制 |
| 邮件系统 | 配置 SPF/DKIM/DMARC,核查邮件网关防钓鱼能力 |
| 第三方接口 | 梳理与外部系统的接口,确认安全措施与责任人 |

## 演练前中后工作清单

### 演练前(准备期)
- [ ] 成立组织架构:指挥组、红队、蓝队、保障组、仲裁组
- [ ] 发布并宣讲规则书,签订授权与保密协议
- [ ] 完成资产盘点、暴露面收敛、漏洞整改
- [ ] 日志与检测体系就绪,告警阈值与升级流程明确
- [ ] 红蓝双方排班表、联络表、紧急叫停通道确认
- [ ] 备份关键系统与配置(演练期间可回滚)
- [ ] 沙盘/桌面预演一次,检验流程

### 演练中(对抗期)
- [ ] 每日战情会:红队进展、蓝队防守、新增风险通报
- [ ] 事件登记与处置留痕(时间、手法、处置动作、证据)
- [ ] 及时上报重大事件;触发熔断条件立即执行
- [ ] 每日输出防守日报 / 红队战报
- [ ] 保障组监控业务可用性,防止演练影响生产

### 演练后(总结期)
- [ ] 红蓝双方提交完整报告(攻击路径 / 防守复盘)
- [ ] 仲裁组核定成绩,确认无违规
- [ ] 召开总结会:攻防双方交叉复盘,输出问题清单
- [ ] 问题分级,明确整改责任人与期限,建立整改台账
- [ ] 整改完成验证,必要时复测;形成年度改进计划

## 常见失分点与加分项

### 常见失分点(蓝队)
- 资产底数不清,红队打到"无人认领"的系统
- 关键日志缺失或留存不足,无法溯源
- 告警大量积压,高置信攻击被淹没
- 发现攻击后处置犹豫,错失遏制窗口
- 响应操作无留痕,无法证明防守过程
- 通报流程混乱,超时未上报

### 常见失分点(红队)
- 前期侦察不足,攻击路径单一
- 突破后动静过大,过早暴露
- 违规操作(超出范围、影响业务)被扣分
- 报告证据链不完整,目标达成无法证明

### 加分项(双方通用)
- 蓝队:主动狩猎发现隐蔽攻击;溯源还原完整攻击链;处置全程规范留痕
- 红队:在蓝队严密防守下完成复杂攻击链;发现非公知的高价值漏洞;报告专业可执行

## 演练总结与整改闭环

### 总结报告结构
1. **演练概况**:时间、范围、规则、参演单位。
2. **红队成果**:攻击路径、达成目标、使用 TTP。
3. **蓝队成绩**:发现/阻断/溯源情况、防守指标。
4. **问题清单**:按严重程度分类,注明归属(资产/检测/响应/流程/人员)。
5. **整改计划**:措施、责任人、期限、验证方式(整改台账)。
6. **能力提升建议**:检测规则、预案、培训、工具的后续改进。

### 整改闭环要点
- 问题分级(紧急/重要/一般)并设定 SLA。
- 每项整改有验证证据(复扫结果、规则上线记录、预案演练记录)。
- 由独立人员抽查验证,防止"纸面整改"。
- 未整改项滚动进入下一轮演练的考察重点。

## 演练组织架构与角色职责

| 角色 | 职责 |
|---|---|
| 指挥组(总导演) | 确定目标与规则、仲裁争议、审批熔断 |
| 红队领队 | 制定攻击策略、分配任务、汇总战报 |
| 蓝队领队 | 组织防守排班、统筹研判与处置、输出防守日报 |
| 保障组 | 网络/系统/平台保障,监控业务可用性 |
| 仲裁组 | 依据规则核定得分、审查违规行为 |
| 观察员 | 记录过程、评估双方表现(供报告参考) |

组织方建议:**规则书提前一周发布**,组织规则宣贯会;演练期间每日召开"战情会"(攻防双方分别简报,仲裁组列席)。

## 典型演练场景剧本(沙盘/桌面演练示例)

| 场景 | 剧本要点 | 推演重点 |
|---|---|---|
| 钓鱼+内网渗透 | 红队鱼叉邮件攻破财务人员主机 → 横向移动至财务系统 | 告警发现、通报流程、隔离决策 |
| 边界漏洞利用 | 红队利用公网 VPN 高危漏洞进入内网 | 补丁管理、暴露面收敛、应急响应 |
| 供应链投毒 | 红队攻陷供应商更新服务器下发恶意更新 | 第三方风险评估、更新校验、应急替代 |
| 勒索软件场景 | 红队模拟勒索加密关键业务 | 备份有效性、恢复演练、业务连续性 |
| 数据泄露场景 | 红队获取数据库并尝试外传 | DLP、数据分级、外传检测 |

## 演练统计指标(报告与评分参考)

| 指标 | 红队 | 蓝队 |
|---|---|---|
| 目标达成数 / 攻击路径数 | 突破系统数、达成目标数 | — |
| 被发现攻击数 / 成功攻击数 | 隐蔽性(未发现率) | 发现率 |
| 平均停留时间 | 从打点到被发现的时长 | 检测时效 |
| 响应处置成功率 | — | 阻断/遏制成功率 |
| 溯源完整率 | — | 还原攻击链的比例 |
| 违规事件数 | 越界/破坏行为次数 | 流程违规次数 |

指标口径在规则书中预先定义,避免事后争议。

## 沟通与通报机制

- **每日战情会**:固定时间(如每日 9:30),红蓝双方简报,时长≤30 分钟。
- **重大事件直报**:蓝队发现核心系统失陷、红队达成关键目标时,立即上报指挥组。
- **熔断机制**:出现影响业务可用性、波及第三方、超出范围等情况,指挥组一键叫停演练。
- **信息纪律**:演练期间攻击手法、防守情况仅限参演人员知晓,防止外部干扰与信息外泄。

## 资源与预算准备

| 项目 | 说明 |
|---|---|
| 演练平台 | 靶场环境(优先)、攻防演练平台、日志分析平台 |
| 人力 | 红蓝双方人员、保障组、仲裁组;排班覆盖演练全程 |
| 工具 | 检测平台、扫描/攻击工具(红队,受控管理)、通信工具 |
| 预算 | 差旅、平台租用、奖励与表彰经费 |
| 后勤 | 值班场所、网络专线、应急备份 |

演练不是"零成本"活动,组织方应在年初预算中预留;小型组织可从桌面演练+单次实战攻防起步。

## 演练效果评估

| 评估维度 | 问题示例 |
|---|---|
| 风险暴露 | 是否发现新漏洞、新攻击路径?失分点是否与预期一致? |
| 能力验证 | 检测与响应是否达标?预案是否可执行? |
| 流程检验 | 通报、升级、熔断流程是否顺畅? |
| 人员锻炼 | 参演人员技能与协作是否提升? |
| 整改闭环 | 问题是否按期修复并验证? |

评估结论应形成**年度攻防能力报告**,指导下一年度演练计划与安全投入。

## 合规与伦理红线

- 演练必须基于书面授权,明确目标范围、禁则、时间窗口与熔断机制。
- 涉及生产系统的操作以"不影响业务可用性"为底线。
- 演练数据、攻击手法、IOC 按保密要求管理,演练后按规则销毁或归档。
- 未经授权的"演练"即真实攻击,属违法行为;个人不得擅自对任何组织发起攻击性测试。
