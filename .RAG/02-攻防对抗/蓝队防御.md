# 蓝队防御

> 关键词:蓝队,安全运营,SOC,资产与攻击面管理,EDR,NDR,SIEM,威胁狩猎,蜜罐,欺骗防御,告警研判,误报,隔离,遏制,红蓝对抗,防守评分,防守报告

## 蓝队是什么

蓝队(Blue Team)是组织的**防守力量**,以安全运营中心(SOC)为核心,负责"看得见、防得住、响应快、恢复好"。蓝队的价值不在于堆砌安全产品,而在于**资产清楚、检测有效、响应及时、闭环彻底**。

### 蓝队核心职责

1. **资产与攻击面管理**:搞清楚"我们有什么、暴露了什么、谁在管"。
2. **威胁检测**:运营 EDR/NDR/SIEM 等工具,持续发现异常。
3. **威胁狩猎**:主动寻找未被规则覆盖的隐蔽攻击。
4. **告警研判与响应**:对每一条告警判断真伪、评估影响、采取措施。
5. **隔离与遏制**:攻击发生时快速止损,防止扩散。
6. **修复与复盘**:根因修复、加固、更新检测规则,形成闭环。
7. **红蓝对抗**:通过演练验证防守能力,持续改进。

## 资产与攻击面管理

攻击面 = 互联网暴露面 + 内网资产 + 供应链 + 人(社工)。管理四步:

1. **资产盘点**:CMDB 梳理主机、应用、API、云资源、物联网设备;标识负责人与重要性(核心/重要/一般)。
2. **暴露面收敛**:关闭不必要的公网端口与服务,统一入口(如 VPN、零信任网关),删除无人认领的"影子 IT"。
3. **漏洞与配置管理**:定期漏洞扫描与基线核查,按风险优先级排期修复;重点盯高危 CVE 与默认口令。
4. **持续监测**:新资产上线必须纳入监控;对域名、证书、公网 IP 变化保持跟踪。

**清单**:公网资产是否全部登记?是否有遗留测试系统/老版本中间件?第三方系统接口是否纳入管理?高危漏洞是否超期未修?

## 威胁检测体系

### EDR(端点检测与响应)
- 能力:进程行为监控、脚本执行检测、内存防护、持久化监控、隔离与取证。
- 部署要点:全量覆盖(包括服务器与工控机)、与系统日志联动、定期验证探针存活。
- 典型告警:异常进程链(如 Office 启动 PowerShell)、LSASS 访问、计划任务新增。

### NDR(网络检测与响应)
- 能力:流量元数据提取、异常外连检测、C2 识别、DNS 隧道检测、内网横向移动检测。
- 部署要点:关键汇聚点旁路部署、出站流量全量分析、与威胁情报联动。
- 典型告警:Beacon 心跳、JA3 指纹异常、非业务端口外连、内网大量 445 端口扫描。

### SIEM(安全信息与事件管理)
- 能力:多源日志集中、关联分析、告警聚合、合规报表。
- 部署要点:覆盖 AD、DNS、防火墙、Web、邮件等关键日志;确保时间同步(NTP);日志留存满足合规(通常≥6个月)。
- 典型用例:同一源 IP 爆破多台主机、异常时间登录、登录后短时间内发生凭据转储。

### 检测体系选型与联动
| 工具 | 侧重 | 典型部署位置 | 主要盲区 |
|---|---|---|---|
| EDR | 端点行为 | 全部主机 | 网络侧攻击、离线主机 |
| NDR | 网络行为 | 核心交换/出口 | 加密流量(无解密时)、端点内部行为 |
| SIEM | 关联分析 | 中心化平台 | 无日志源即无检测 |
| 蜜罐/欺骗 | 诱捕攻击者 | 内网/互联网边界 | 高维护成本、误报需要甄别 |

**建议**:先明确"要检测的攻击场景",再选型;三类工具数据打通,形成"EDR 发现主机异常 → SIEM 关联上下文 → NDR 确认外连"的联动闭环。

## 威胁狩猎

威胁狩猎是**主动寻找规则未覆盖的隐蔽攻击**,而非等待告警。

### 假设驱动方法
1. **提出假设**:基于威胁情报、最新漏洞、历史事件,如"攻击者可能利用某新披露的 RCE 漏洞"、"可能通过计划任务持久化"。
2. **收集数据**:拉取对应时间窗的进程、网络、登录、文件日志。
3. **验证假设**:编写查询(如 KQL/Splunk SPL)检索特征,人工研判命中项。
4. **得出结论**:确认攻击则升级为事件处置;未命中则记录假设并保留查询模板。
5. **沉淀检测**:将有效狩猎查询转化为常态化检测规则。

### ATT&CK 映射狩猎
按战术维度设计狩猎场景,例如:
- **执行战术**:查找 Office/脚本解释器异常启动链。
- **持久化战术**:查找新增服务、计划任务、注册表 Run 键。
- **C2 战术**:查找高熵域名、定期外连、异常 TLS 指纹。
- **凭据访问**:查找 LSASS 进程访问、敏感文件读取。

### 狩猎素材来源
威胁情报(厂商/开源)、红队报告与渗透测试复盘、HVV 战报、ATT&CK 新增技术、内部历史告警的"漏网"分析。

## 蜜罐与欺骗防御

- **蜜罐(Honeypot)**:部署诱饵主机/服务(如伪数据库、伪管理后台),吸引攻击者交互,记录其手法。
- **欺骗防御(Deception)**:在真实资产旁布设诱饵(蜜标文件、蜜标账号、假凭据),攻击者一旦触碰即触发高置信告警。
- **效果**:显著提高检测置信度、拖慢攻击者、获取攻击手法与工具样本。
- **部署建议**:蜜罐网段与生产隔离、不承载真实数据、诱饵信息(如账号名、文档命名)贴近业务实际、定期维护避免被识破。
- **注意**:蜜罐本身也可能被攻击者用作跳板,必须隔离并严格限制出站。

## 告警研判与误报处理

### 研判流程(五步)
1. **看上下文**:告警关联的资产价值、业务属性、时间、源/目的 IP。
2. **查证据**:拉取对应主机进程树、网络连接、登录日志、文件操作。
3. **判真假**:区分真实攻击、误报、正常业务行为(如内部扫描工具、合法自动化任务)。
4. **评影响**:若是真攻击,评估影响面(横向移动迹象、数据访问痕迹)。
5. **定处置**:按事件等级(观察/一般/严重/紧急)升级或关闭。

### 误报治理
- **建立白名单**:对已知正常行为(内部监控、备份任务、合法工具)维护白名单,注明理由与有效期。
- **规则调优**:基于误报样本调整阈值与排除条件,避免"一刀切"导致漏报。
- **反馈闭环**:误报案例定期评审,沉淀为调优规则;统计误报率并设定目标(如<20%)。
- **避免告警疲劳**:分级告警(高危直呼、中危聚合、低危日报),保证分析师精力投向关键告警。

## 隔离与遏制手段

攻击确认后,**先遏制、后取证、再清杀**,按影响面从小到大选择手段:

| 手段 | 适用场景 | 注意事项 |
|---|---|---|
| 网络 ACL/防火墙阻断 | 失陷主机与 C2 外连、与内网互访 | 保留阻断前后流量证据;阻断范围写清并记录 |
| 主机隔离(EDR 一键隔离) | 单台失陷主机 | 隔离前先抓取内存/进程快照;告知业务影响 |
| 网段级隔离 | 攻击已横向扩散 | 需预置隔离预案与应急演练 |
| 账号禁用/强制改密 | 失陷账号、异常登录 | 先评估业务依赖;域控层面联动处理 |
| 会话终止 | 可疑远程会话(RDP/WinRM/SSH) | 记录会话日志后再断开 |
| 服务/进程停用 | 恶意服务、持久化后门 | 停用前取证(进程内存、文件副本) |

**顺序建议**:证据保全 → 最小化遏制 → 确认无扩散 → 清除 → 恢复业务 → 加固 → 复盘。

## 红蓝对抗中的防守评分项

演练中蓝队通常按以下维度被评分(不同演练规则有差异,以组织方为准):

| 评分项 | 说明 | 得分要点 |
|---|---|---|
| 攻击发现率 | 发现红队攻击行为的比例 | 全资产覆盖检测、日志齐全 |
| 检测时效 | 从攻击发生到发现的时间 | 告警及时、研判快速 |
| 响应时效 | 从发现到处置完成的时间 | 预案熟练、权限到位 |
| 溯源分析 | 能否还原攻击链路与手法 | 日志完整、分析能力 |
| 通报与上报 | 按规则及时上报事件 | 流程明确、沟通顺畅 |
| 整改闭环 | 演练后问题是否修复 | 有台账、有验收 |

**防守策略要点**:摸清资产底数 → 优先守住核心与失分点(如域控、核心业务)→ 关键日志必须全 → 高置信告警优先处置 → 处置过程留痕(截图、时间线)→ 每日防守复盘调整策略。

## 防守报告

### 报告结构
1. **防守概况**:参演资产数、检测体系覆盖、人员分工。
2. **攻击事件汇总**:按时间线列出发现的攻击行为、手法(TTP/ATT&CK 映射)、处置结果。
3. **防守指标**:发现率、平均检测时间(TTD)、平均响应时间(TTR)、误报率、闭环率。
4. **攻击路径复盘**:红队打通的路径、防守缺口、关键时刻判断。
5. **问题清单**:按严重程度列出的资产、检测、响应、流程问题。
6. **整改计划**:每项问题对应措施、责任人、期限、验证方式。

## 防守清单(日常+演练通用)

- [ ] 资产台账完整且实时更新,核心资产标识明确
- [ ] 互联网暴露面收敛:最小化开放端口,统一入口
- [ ] EDR/NDR/SIEM 全量覆盖,探针存活自动监控
- [ ] 关键日志(AD/DNS/防火墙/邮件/Web)完整接入并合规留存
- [ ] 高危漏洞按 SLA 修复,遗留风险有缓解措施
- [ ] 告警分级与升级流程明确,值班表有效
- [ ] 隔离/遏制预案已演练,权限与工具有效
- [ ] 蜜罐/欺骗层已部署并纳入监控
- [ ] 威胁狩猎按周期执行并沉淀规则
- [ ] 演练期间每日复盘,问题当日入台账
- [ ] 演练后整改闭环,验收有证据

## 事件分级标准

| 等级 | 定义 | 处置时限 | 典型场景 |
|---|---|---|---|
| 观察 | 可疑但无确证 | 24h 内核实 | 单次异常登录、低危扫描 |
| 一般 | 确认为攻击行为,影响有限 | 4h 内遏制 | 单台主机被投毒、钓鱼邮件已阻断 |
| 严重 | 已失陷或有扩散迹象 | 1h 内遏制 | 域控异常、横向移动迹象、数据外传 |
| 紧急 | 重大业务影响或大范围失陷 | 立即处置+上报 | 核心业务中断、勒索软件、批量数据泄露 |

分级决定响应力度与上报层级;建议将分级标准写入值班手册,并定期用演练验证判定一致性。

## 关键日志源清单(防守基线)

| 日志源 | 关键事件 | 用途 |
|---|---|---|
| 域控/AD | 登录、账户锁定、组策略变更、DCSync 特征 | 横向移动与凭据攻击检测 |
| 终端(EDR/Sysmon) | 进程创建、网络连接、文件创建、注册表/服务变更 | 行为分析与狩猎 |
| DNS | 域名解析记录 | DGA/隧道/异常外连检测 |
| 防火墙/NDR | 会话元数据、阻断记录 | 外连与扫描分析 |
| Web 服务器/WAF | 访问日志、攻击特征命中 | Web 攻击溯源 |
| 邮件网关 | 收发记录、拦截记录 | 钓鱼研判 |
| VPN/堡垒机 | 登录、命令审计 | 特权访问监控 |
| 云平台 | 控制台操作、API 调用 | 云上失陷检测 |

日志要求:统一时间同步(NTP)、集中留存(≥6 个月,合规要求另计)、防篡改(只追加/转发)。

## 检测规则生命周期

1. **需求**:从威胁情报、狩猎结论、演练复盘提炼检测场景。
2. **开发**:编写规则(如 Sigma/Splunk SPL),注明 ATT&CK 战术映射。
3. **测试**:用历史真实攻击数据验证命中,用正常流量验证误报率。
4. **上线**:灰度发布,先"仅记录"再"告警",观察一周。
5. **调优**:根据误报/漏报反馈迭代阈值与白名单。
6. **退役**:业务变化或场景消失后下线,避免规则膨胀。

**度量**:定期统计规则命中率与误报率,淘汰长期零命中的"僵尸规则"。

## SOC 值班与交接流程

- **值班流程**:监控台值守 → 告警分诊(按分级标准)→ 研判取证 → 处置/升级 → 记录工单 → 复盘沉淀。
- **交接要点**:未闭环事件的状态、进行中的处置动作、临时白名单与变更记录、当天新增规则/情报、重点关注对象。
- **工具**:工单系统(SOAR)记录全流程;交接班会议 10–15 分钟,聚焦"异常与风险",避免流水账。

## 防守关键指标(KPI)定义

| 指标 | 定义 | 目标参考 |
|---|---|---|
| 检测率 | 红队攻击行为中被发现的比例 | 越高越好,演练复盘统计 |
| TTD(检测时间) | 攻击发生到被发现的时间 | 分钟级(高危) |
| TTR(响应时间) | 发现到完成遏制的时间 | 分钟级(高危) |
| 误报率 | 误报告警占全部告警比例 | <20% |
| 闭环率 | 事件从发现到整改验证完成的比例 | >95% |
| 溯源完整率 | 能还原完整攻击链的事件占比 | 核心事件 100% |

指标应纳入演练评分与日常运营考核,形成"度量→改进"循环。

## 紫队协作

- 紫队(Purple Team)由红蓝成员共同组成:红队按计划执行攻击,蓝队现场观测、提问、学习;每步攻击后立即复盘检测盲区。
- 产出:攻击手法清单 + 检测缺口清单 + 新增检测规则 + 修复建议。
- 相比独立对抗,紫队能**即时沉淀检测能力**,适合日常能力建设;实战演练则用于检验整体效果。

## 蓝队团队构成与技能

| 角色 | 职责 | 关键技能 |
|---|---|---|
| SOC 分析师 | 告警研判、事件处置 | 日志分析、取证、沟通 |
| 威胁狩猎分析师 | 主动搜寻隐蔽攻击 | 数据查询、ATT&CK、情报研判 |
| 安全工程师 | EDR/NDR/SIEM 运维与规则 | 平台管理、规则编写、自动化 |
| 应急响应专家 | 重大事件处置与取证 | 数字取证、逆向、复现 |
| 安全架构师 | 攻击面收敛与加固设计 | 网络/身份/云架构、零信任 |

## 合规与伦理红线

- 蓝队的隔离、禁用账号等操作须遵循组织应急响应制度,避免对业务造成次生影响。
- 涉及个人信息与取证数据时遵守数据保护法规。
- 防守手段(如蜜罐诱捕)需在组织内部合规框架内实施,不得对外部无关人员造成伤害。
- 蓝队掌握的告警与用户数据严格按最小必要原则使用,防止内部滥用。
