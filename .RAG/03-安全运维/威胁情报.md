# 威胁情报
> 关键词:威胁情报,Threat Intelligence,OSINT,STIX,TAXII,IOC,失陷指标,信誉库,情报驱动检测,威胁狩猎,情报生命周期,战略情报,战术情报,国内情报源

## 一、威胁情报概念与价值

威胁情报(Threat Intelligence,TI)是基于证据的、关于针对组织资产的**现有或潜在威胁**的知识,包含上下文、机制、指标、影响与可执行建议。

**核心价值**:

1. **看得早**:在攻击发生前了解攻击者 TTP(战术、技术、流程),提前加固与设防。
2. **判得准**:告警命中已知 IOC 时,可信度大幅提升,减少误报与研判时间。
3. **响应快**:情报附带处置建议(封禁 IP、查杀哈希、下线域名),指导应急。
4. **补盲区**:自有检测能力覆盖不到的威胁(如新型变种、钓鱼域名),靠情报补齐。

**用好情报的关键**:情报必须**落地为检测动作**才产生价值——"入库≠可用,命中≠处置"。

## 二、情报类型(战略/战术/运营/技术)

| 类型 | 面向对象 | 时间跨度 | 内容 | 产出形式 |
|------|---------|---------|------|---------|
| 战略情报(Strategic) | 管理层/决策者 | 季度-年度 | 威胁趋势、行业定向攻击态势、地缘风险 | 报告、简报 |
| 运营情报(Operational) | 安全运营负责人 | 周-月 | 针对本行业/本组织的攻击活动、攻击者动机与目标 | 专题分析、攻击活动通告 |
| 战术情报(Tactical) | 安全分析师 | 实时-天 | 攻击者的 TTP、工具、基础设施 | 攻击手法分析、检测规则 |
| 技术情报(Technical) | 检测/响应系统 | 实时 | IOC:IP、域名、URL、文件哈希、证书 | IOC 列表、信誉库、规则 |

> 使用原则:**向高层讲趋势与风险,向运营讲活动,向系统喂 IOC 与规则**。把战略报告丢给 SIEM、把 IOC 丢给董事会,都是错配。

## 三、情报生命周期(规划-收集-处理-分析-分发-反馈)

```
规划 → 收集 → 处理 → 分析 → 分发 → 反馈
 ↑                                      ↓
 └──────────────────────────────────────┘(持续循环)
```

| 阶段 | 关键动作 | 输出 |
|------|---------|------|
| 规划(Planning) | 明确情报需求(PIR, Priority Intelligence Requirements):保护什么资产、防什么威胁 | 需求清单 |
| 收集(Collection) | 从开源、商业、行业、自产渠道采集数据 | 原始数据 |
| 处理(Processing) | 格式转换、去重、标准化、自动化入库 | 结构化数据 |
| 分析(Analysis) | 关联、验证、判断可信度与影响 | 情报产品(IOC、报告) |
| 分发(Dissemination) | 推送到 SIEM/防火墙/EDR 及各团队 | 落地检测 |
| 反馈(Feedback) | 命中情况、误报、时效性反馈,优化下一轮 | 改进项 |

> 生命周期要"闭环":情报命中率低的来源要降权或剔除;过期的 IOC 要定期清理,避免误报。

## 四、情报来源

| 来源类型 | 说明 | 示例 | 注意事项 |
|---------|------|------|---------|
| 开源情报(OSINT) | 免费公开渠道 | 开源情报平台(如 VirusTotal 免费查询、AbuseIPDB、URLhaus、CIRCL)、安全厂商博客、GitHub 恶意样本库 | 质量参差,需交叉验证 |
| 商业订阅 | 付费专业情报 | 微步在线、奇安信威胁情报、绿盟、Recorded Future、CrowdStrike、ThreatConnect | 成本高,关注覆盖与时效 |
| 行业共享 | 行业/国家平台共享 | 网络安全威胁信息共享平台(国家)、金融/运营商行业情报共享 | 信任度高,有共享义务 |
| 自产情报 | 自有数据提炼 | 自身蜜罐、沙箱分析、事件复盘提炼的 IOC 与 TTP | 最贴合自身环境,优先级最高 |
| 社区情报 | 白帽社区/论坛 | 乌云历史库、FreeBuf、安全社区披露 | 注意时效与版权 |

**选型建议**:自产情报 > 商业订阅 > 行业共享 > 开源;商业情报优先选能覆盖本行业攻击者的厂商,并验证其对**最近 30 天新出现样本/域名**的命中能力(可回测)。

## 五、STIX / TAXII 标准简介

| 标准 | 作用 | 说明 |
|------|------|------|
| STIX(Structured Threat Information eXpression) | 情报描述标准 | 定义情报对象的统一结构,包括威胁行为者、攻击模式(TTP)、IOC、漏洞、工具、事件等对象及其关系 |
| TAXII(Trusted Automated eXchange of Intelligence Information) | 情报传输协议 | 定义情报的传输与共享方式(Collection/Channel),基于 HTTPS,用于情报自动同步 |

**STIX 2.x 核心对象(SDO)**:

- `indicator`:指标(如恶意 IP、哈希),含 pattern 描述匹配条件。
- `malware` / `tool` / `attack-pattern`:恶意软件、工具、攻击模式(TTP)。
- `threat-actor`:威胁行为者(组织/团伙)。
- `intrusion-set`:攻击活动集合(如 APT 组织的系列行动)。
- `relationship`:对象间关系(如某 actor 使用某 malware)。

**应用场景**:商业情报源通过 TAXII 推送 STIX 格式数据到本地平台,自动入库解析,无需人工维护格式。

## 六、IOC(IP/域名/哈希/URL)与使用

### 6.1 IOC 类型与特点

| IOC 类型 | 示例 | 时效性 | 误报风险 | 使用建议 |
|---------|------|--------|---------|---------|
| IP 地址 | 45.xx.xx.xx | 短(数小时-数天) | 高(CDN/云共享 IP) | 仅用于短期封禁与告警,不宜长期黑名单 |
| 域名 | evil.example.com | 中(数天-数月) | 中(可被攻击者更换) | 适合 DNS 检测与邮件网关拦截 |
| URL | hxxp://evil.com/payload | 中 | 中 | 用于 Web 防护与沙箱比对 |
| 文件哈希 | MD5/SHA1/SHA256 | 长 | 低(哈希唯一) | 适合 EDR/杀软检测与样本库匹配 |
| 邮箱/证书 | 发件人、C2 证书指纹 | 中 | 低-中 | 邮件网关、流量检测辅助 |

> 注意:**IP 与域名的时效最短**,商业情报库需按天更新;哈希长期有效但需配套"家族+行为"情报才能指导处置。

### 6.2 IOC 使用流程

1. **入库**:从情报平台导入 IOC,标准化后存入威胁情报库(如 MISP、自建库)。
2. **同步**:推送至 SIEM(检测)、防火墙/EDR(阻断)、邮件网关(拦截)、DNS 设备(解析拦截)。
3. **命中响应**:命中时自动丰富上下文(来源情报、置信度、家族)并触发处置。
4. **生命周期管理**:按首次出现时间与最后命中时间淘汰过期 IOC;每月清理误报源。

## 七、情报驱动的检测(信誉库、规则、狩猎)

| 落地方式 | 做法 | 示例 |
|---------|------|------|
| 信誉库匹配 | SIEM/防火墙加载情报库,流量/日志匹配即告警 | DNS 解析到恶意域名、主机外联恶意 IP |
| 检测规则 | 将情报转化为特征与行为规则 | 已知恶意家族的文件名/行为特征规则 |
| 威胁狩猎 | 用情报指引主动搜索未触发告警的隐蔽活动 | 用 APT 组织常用工具名在历史日志中检索 |
| 攻击面情报 | 监测外部暴露资产与泄漏数据 | 监测自有域名被仿冒、GitHub 代码泄漏 |

**情报驱动检测示例(KQL)**:
```kql
// 主机 DNS 解析到情报库中的恶意域名
event.dataset: "dns" and dns.question.name: ("evil.example.com" or "c2.panel.net")
// 或引用威胁情报索引关联
host.name: * and threat.feed: "ti_feeds" and threat.indicator: * 
```

## 八、情报误用与质量评估

### 8.1 常见误用

- **IOC 当结论**:命中 IOC ≠ 失陷,可能是被 DNS 污染、共享 IP 或误入库,必须结合行为证据。
- **过期情报长期生效**:老旧 IP 早被攻击者弃用,命中只会造成误报。
- **只看技术情报**:忽略 TTP 与上下文,无法判断攻击者意图与影响。
- **情报不落地**:买了订阅却只存不进检测体系,"情报仓库"变"情报坟场"。
- **共享 IP 一刀切封禁**:误伤大量正常用户,尤其 CDN/云主机 IP。

### 8.2 情报质量评估维度

| 维度 | 评估问题 |
|------|---------|
| 准确性(Accuracy) | 情报是否经验证?误报率多高? |
| 时效性(Timeliness) | 从攻击者行动到情报发布间隔多久? |
| 完整性(Completeness) | 是否包含上下文(家族、TTP、处置建议)? |
| 相关性(Relevance) | 是否覆盖本行业、本组织的威胁? |
| 可操作性(Actionability) | 能否直接转化为封禁/查杀/拦截动作? |

**量化评估方法**:抽取近 30 天新情报做回测——在自有历史日志中统计命中数与误报数,计算"有效命中率 = 确认相关命中 ÷ 总命中"。低于 20% 的情报源考虑降级或替换。

## 九、国内情报源示例

| 类型 | 平台/服务 | 说明 |
|------|----------|------|
| 商业情报 | 微步在线(ThreatBook) | 国内主流,提供 IP/域名/文件信誉、威胁情报 API |
| 商业情报 | 奇安信威胁情报中心 | 覆盖 APT 与漏洞情报,配套威胁分析平台 |
| 商业情报 | 绿盟威胁情报 | 与绿盟设备联动 |
| 开源查询 | 奇安信威胁情报社区、微步在线查询页 | 单条 IOC 免费查询 |
| 开源平台 | VirusTotal(可访问性视网络环境)、URLhaus、AbuseIPDB | 国际开源情报 |
| 国家/行业 | 国家互联网应急中心(CNCERT)、CNNVD 漏洞库、行业威胁情报共享平台 | 权威通报与共享 |
| 自建 | 蜜罐系统、EDR 恶意样本库、自有沙箱 | 自产情报,贴合内网环境 |

**落地建议(中小企业起步路径)**:
1. 先用免费查询 + 开源平台建立基础 IOC 库;
2. 采购一个商业情报订阅(优先覆盖本行业)接入 SIEM;
3. 接入 CNCERT/CNNVD 通报与漏洞情报,补齐漏洞管理输入;
4. 自建蜜罐/沙箱,沉淀自产情报,逐步降低对外部情报的依赖。

> 提示:使用国际开源平台时注意网络可达性与数据合规;涉及个人信息或业务数据的情报分享需遵守数据安全法。
