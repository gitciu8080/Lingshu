# 信息收集(Information Gathering)

> 关键词:信息收集, OSINT, 被动信息收集, 主动信息收集, 子域名枚举, DNS解析, 端口扫描, 指纹识别, Shodan, Fofa, Google Hacking, Git泄露, WHOIS, subfinder, amass, nmap, httpx

## 概述

信息收集是渗透测试的第一阶段,决定后续攻击面的广度和成功率。**信息越多,攻击面越大**。信息收集分为两类:

| 类型 | 定义 | 特点 | 与目标交互 |
| --- | --- | --- | --- |
| 被动收集(Passive) | 不直接与目标系统交互,从公开渠道获取 | 隐蔽、不产生流量、无法律风险 | 否(仅查询第三方服务) |
| 主动收集(Active) | 直接向目标发送探测请求 | 信息更精确、实时 | 是(需授权,可能触发告警) |

> ⚠️ **仅限授权测试**:主动探测(端口扫描、目录枚举)会在目标侧留下流量记录,必须获得书面授权,并注意频率控制以免影响业务。

## 被动信息收集(OSINT)

### 1. 域名 WHOIS 查询

WHOIS 可获取域名注册人、注册商、注册/到期时间、联系邮箱、DNS 服务器等。注册人邮箱常用于反查关联域名(同一邮箱注册多个域名)。

```bash
# Linux / Kali
whois example.com
whois 8.8.8.8              # IP 反查归属(inetnum 段)
# Windows
# 在线查询:https://whois.icann.org 或 https://whois.domaintools.com
```

**判断要点**:
- 注册人信息是否泄露(隐私保护是否开启)。
- 注册商/邮箱反查:用邮箱在 `viewdns.info/reverseip`、`whoisxmlapi` 反查关联域名。
- 域名历史解析:使用 SecurityTrails、WhoisXML、`viewdns.info/iphistory` 查看历史 IP,常可发现已下线但未清理的旧资产。

### 2. 子域名枚举

子域名常暴露测试环境、后台、API、旧系统等被遗忘资产。方法分为字典爆破、证书透明日志(CT 日志)、搜索引擎与 DNS 记录枚举。

```bash
# 1) 证书透明日志查询(被动、隐蔽)
subfinder -d example.com -all -silent | tee subs.txt
# 2) 字典爆破(主动,需授权)
amass enum -d example.com -passive          # 被动模式
amass enum -d example.com -active -brute    # 主动爆破
# 3) 从证书日志获取(在线):https://crt.sh/?q=%25.example.com
# 4) DNS 记录枚举
dnsrecon -d example.com -t std -t brt -D /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
# 5) 校验存活子域名
cat subs.txt | sort -u | httpx -silent -status-code -title -tech-detect -o live.txt
```

**推荐字典**:`SecLists/Discovery/DNS/`(subdomains-top1million-*.txt)、`commonspeak2`。

### 3. DNS 解析与记录类型

```bash
# nslookup(Windows/Linux 通用)
nslookup example.com
nslookup -type=MX example.com    # 邮件服务器
nslookup -type=TXT example.com   # TXT(含 SPF/DMARC,可能泄露内部信息)
nslookup -type=NS example.com    # 权威域名服务器
nslookup -type=ANY example.com

# dig(Linux,信息更全)
dig example.com A
dig @8.8.8.8 example.com A       # 指定 DNS 服务器
dig example.com ANY +noall +answer
dig -x 8.8.8.8                    # 反向解析(PTR)
dig example.com +trace            # 完整解析路径

# 区域传送测试(严重配置错误:可获取全部 DNS 记录)
dig @ns1.example.com example.com AXFR
# 成功则说明 DNS 允许未授权区域传送,应立即修复
```

**实战技巧**:
- 用 `dnsdumpster.com`、`DNSDumpster` 画目标网络拓扑。
- 测试环境域名常见前缀:`test`、`dev`、`uat`、`staging`、`pre`、`beta`、`api`、`admin`、`vpn`、`git`、`jenkins`、`grafana`。
- 子域名接管(Subdomain Takeover)线索:解析到 `CNAME` 指向已删除的第三方服务(如 `github.io`、`herokuapp`、`s3`),见《Web渗透测试.md》。

### 4. IP 归属与 C 段

```bash
# IP 归属与地理位置
whois 1.2.3.4
# 在线:ipinfo.io、ip138.com、Shodan
# C 段(相邻网段)资产:同 C 段主机常属同一组织
# 使用 Shodan 搜索网段
shodan search net:1.2.3.0/24
# Fofa 搜索网段
fofa: ip="1.2.3.0/24"
```

**判断标准**:确认目标是否拥有该 IP(查看 ASN/org 字段)。若目标使用 CDN(Cloudflare 等),需查找真实 IP(见下文「绕过 CDN」)。

### 5. 历史漏洞查询

```bash

searchsploit -m 50383          # 复制 exploit 到当前目录

```

## 主动信息收集

### 1. 端口扫描(nmap)

```bash
# 快速扫描常见端口
nmap -sV -sC -T4 target.com -oA nmap_quick
# 全端口 TCP 扫描(慢但完整)
nmap -p- -T4 target.com -oA nmap_full
# 指定端口 + 服务版本 + 默认脚本
nmap -sV -sC -p 22,80,443,3306,6379,8080,8443 target.com
# UDP 关键端口(DNS/SNMP/NTP 常被忽略)
nmap -sU --top-ports 100 target.com
# 防火墙探测
nmap -sS -Pn -f -D 8.8.8.8,1.2.3.4 target.com   # 分片+诱饵
# 扫描结果导出为表格
nmap -oX out.xml target.com && xsltproc out.xml -o report.html
```

**nmap 常用参数速查**:

| 参数 | 含义 | 适用 |
| --- | --- | --- |
| `-sS` | SYN 半开扫描(默认,需 root) | 常规 |
| `-sT` | TCP connect 全连接扫描 | 无 root 权限时 |
| `-sV` | 版本探测 | 服务识别 |
| `-sC` | 默认脚本(安全脚本集) | 常规 |
| `-p-` | 全端口(1-65535) | 完整扫描 |
| `-Pn` | 跳过主机发现 | 目标禁 ping 时 |
| `-O` | 操作系统指纹 | 系统识别 |
| `--script=vuln` | 漏洞检测脚本 | 扫描阶段 |

**判断标准**:开放端口 → 对应服务 → 版本 → 在漏洞库查找该版本已知 CVE。

### 2. 服务与版本识别

```bash
# 精确版本识别(主动发送探测报文)
nmap -sV --version-intensity 9 -p 80 target.com
# Web 服务快速探测
httpx -u http://target.com -status-code -title -tech-detect -follow-redirects
# 抓取服务 Banner(Telnet/HTTP 等)
nc -nv 1.2.3.4 80        # 输入 HTTP 请求头后回车两次
openssl s_client -connect target.com:443 -servername target.com   # TLS 证书信息
```

**版本识别的价值**:版本号是漏洞匹配的关键输入。例如发现 `Apache/2.4.49`,可立即关联 CVE-2021-41773(路径穿越);发现 `OpenSSH 7.2` 需进一步确认发行版补丁情况(很多版本号相同但已打补丁)。

### 3. 指纹识别(Web / 框架 / CMS)

```bash
# whatweb(Web 指纹)
whatweb target.com
whatweb -a 3 target.com              # 激进模式,信息更全
# wappalyzer(浏览器插件)
# 在线:https://www.wappalyzer.com
# 自动化指纹扫描
nuclei -u target.com -t http/technologies/ -silent
# 404 页面 / 报错页 / 源码注释 手工判断
curl -s http://target.com | grep -iE "generator|powered by|wordpress|drupal|jquery"
# CMS 专项:WordPress
wpscan --url target.com --enumerate u,vp,vt --api-token YOUR_TOKEN
```

**常见指纹特征速查**:

| 类型 | 特征 |
| --- | --- |
| WordPress | `/wp-login.php`、`wp-content/`、`/wp-json/` |
| Joomla | `/administrator/`、`<meta name="generator" content="Joomla!">` |
| Drupal | `/CHANGELOG.txt`、`X-Generator: Drupal` |
| ThinkPHP | 特定报错格式、`/index.php?s=` 路由 |
| Spring | `Whitelabel Error Page`、`X-Application-Context` |
| Nginx | `Server: nginx/1.18.0` |
| IIS | `Server: Microsoft-IIS/10.0`、`X-Powered-By: ASP.NET` |
| Shiro | 响应头 `Set-Cookie: rememberMe=deleteMe` |

### 4. Google Hacking(搜索引擎语法)

```bash
# 语法示例(在 Google/Bing 中搜索)
site:example.com admin                    # 站点内包含 admin 的页面
site:example.com filetype:sql             # 泄露的 SQL 文件
site:example.com inurl:php?id=            # 可能存在注入的页面
site:example.com intitle:"index of"       # 开放的目录列表
site:example.com filetype:bak / filetype:log
site:example.com intext:"password" | intext:"口令"
# 关联搜索(不限于主域名)
site:*.example.com -www
# 高级:inurl:8080 OR inurl:8443           # 暴露的管理端口
```

**注意**:Google Hacking 属于被动信息收集,但搜索引擎可能缓存敏感内容;检索结果需在授权范围内验证,不得利用搜索引擎抓取其他组织数据。

### 5. 搜索引擎与空间测绘(Shodan / Fofa / 钟馗之眼)

空间测绘引擎扫描全网 IP 的端口与服务,可直接检索目标暴露面,属于被动收集(数据是测绘平台采集的)。

```bash
# Shodan(https://www.shodan.io)
shodan search "port:6379 country:CN"          # 未授权 Redis
shodan search "http.title:后台" 
shodan host 1.2.3.4                           # 查看单 IP 全部开放服务
shodan search "product:Microsoft-IIS country:US"

# Fofa(https://fofa.info)
# 语法:title="后台" && country="CN" && protocol="https"
#      ip="1.2.3.0/24" / domain="example.com" / banner="phpstudy"
fofa: title="登录" && body="thinkphp"

# 钟馗之眼 ZoomEye(https://www.zoomeye.org)
zoomeye: app:"Nginx" + port:"8080"
```

**测绘结果价值**:
- 直接定位未授权访问服务(Redis 6379、MongoDB 27017、Docker API 2375)。
- 发现暴露的摄像头、工控设备、数据库。
- 结合端口与 Banner 反查真实 IP、绕过 CDN。

**绕过 CDN 找真实 IP 常用手段**:
- 历史 DNS 解析(SecurityTrails、`viewdns.info/iphistory`)。
- 子域名不挂 CDN(如 `mail.`、`vpn.`、`ftp.` 直连源站)。
- 邮件头溯源(`nslookup -type=MX`,发信 IP)。
- 空间测绘搜索目标 SSL 证书指纹:Shodan `ssl.cert.subject.cn:example.com`。

### 6. Git 信息泄露

开发者常将代码仓库(含配置、密钥、内网地址)误传至公开仓库或暴露在 Web 上。

```bash
# 常见泄露路径(直接访问验证)
# https://target.com/.git/config
# https://target.com/.svn/entries
# https://github.com 搜索:example.com password / api_key / internal IP

# 若 .git 目录可访问,可还原源码
git clone http://target.com/.git/ 泄露仓库
# 或使用工具 dump 远程 .git
# git-dumper / GitTools
# 扫描工具:gitleaks(扫描代码中的密钥)、trufflehog

# 历史提交中的敏感信息(即使后来删除仍可恢复)
git log --all -p | grep -iE "password|token|secret|api[_-]?key"
```

**判断标准**:`.git/config` 返回 200 且包含 `[core]` 段 = 确认泄露。GitHub 搜索注意区分同名项目,优先 `org:目标公司名` 限定。

## 信息收集产出物清单(建议模板)

| 类别 | 字段 |
| --- | --- |
| 域名 | 根域名、子域名列表、注册信息 |
| IP | 真实 IP、CDN 状态、C 段、归属 ASN |
| 端口服务 | 开放端口、服务版本、Banner |
| Web | 技术栈、CMS、框架、中间件、证书 |
| 账号 | 泄露邮箱、GitHub 用户名、默认口令线索 |
| 文档 | 泄露文件(.git/.svn/备份/配置文件) |
| 拓扑 | DNS 结构、邮件服务器、VPN、内网入口 |

## 防御视角

1. **收敛暴露面**:关闭不必要端口与服务,管理端口仅内网可达。
2. **CDN 正确配置**:源站 IP 仅对 CDN 放行,避免子域名绕过。
3. **信息泄露治理**:清理 `.git`/`.svn`/备份文件;代码仓库扫描密钥(gitleaks 接入 CI);GitHub 组织公开仓库审计。
4. **DNS 安全**:禁止区域传送;隐藏内部 DNS 记录;敏感子域名不公开解析。
5. **监控**:对陌生 IP 的端口扫描、目录枚举建立告警(如基于 `nmap` 特征、高频 404)。
6. **隐私保护**:注册 WHOIS 隐私保护,减少 OSINT 关联面。
