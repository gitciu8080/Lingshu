# 渗透测试模块说明(README)

> 关键词:渗透测试, 渗透测试方法论, PTES, 授权测试, 网络安全, 知识库模块导航, 红队, 漏洞利用, 风险评估

## 模块定位

本模块是网络安全知识库中「渗透测试」专题的入口文件,收录从**信息收集 → 漏洞发现 → 漏洞利用 → 权限维持 → 报告输出**的完整攻防知识体系。内容以**实战可操作**为第一原则:给出命令、参数、判断标准与清单表格,同时每个攻击主题均附带**检测、防御与修复视角**,并强调「仅限授权测试」。

> ⚠️ **合规声明**:本模块所有技术内容仅用于**获得书面授权的渗透测试、CTF 竞赛、靶场练习(如 DVWA、Vulnhub、HackTheBox)与防御研究**。未经授权对任何系统实施探测、扫描或利用均属违法行为,请遵守所在国家/地区法律法规。

## 渗透测试的定义

渗透测试(Penetration Testing,简称 Pentest)是**在授权范围内**,模拟真实攻击者的思路、技术与工具,对目标系统进行主动探测与攻击尝试,以发现可被利用的安全漏洞,并评估其实际危害程度的安全评估活动。

与漏洞扫描的区别:

| 维度 | 漏洞扫描 | 渗透测试 |
| --- | --- | --- |
| 深度 | 自动化检测已知漏洞 | 结合人工分析验证可利用性 |
| 输出 | 漏洞清单(可能有误报) | 可被利用的漏洞 + 影响证明 + 修复建议 |
| 成本 | 低、可高频执行 | 高、周期较长 |
| 风险 | 低 | 中高(可能影响业务,需严格授权) |

## 渗透测试的价值

1. **真实风险度量**:确认漏洞是否可被利用、利用后的实际影响(数据泄露/权限获取/横向移动)。
2. **验证防御有效性**:检验 WAF、IDS/IPS、EDR、日志告警是否真正拦截攻击。
3. **满足合规要求**:等级保护(等保 2.0)、ISO 27001、PCI-DSS、GDPR 等均要求定期渗透测试。
4. **量化修复优先级**:结合 CVSS 评分与业务重要性,指导安全投入方向。
5. **人员能力提升**:暴露安全团队盲区,沉淀检测规则与应急预案。

## 渗透测试与相关概念的区别

| 概念 | 定位 | 关键差异 |
| --- | --- | --- |
| 漏洞扫描 | 自动化检测已知漏洞 | 无人工利用验证,误报较多 |
| 渗透测试 | 授权模拟攻击验证危害 | 有人工分析与利用验证,产出可复现报告 |
| 红队评估 | 模拟真实 APT 攻击全流程 | 目标包含防守方检测能力,常不限手段(仍受限授权) |
| 安全审计 | 检查是否符合标准/规范 | 合规视角,不追求利用危害 |
| 攻防演练 | 攻防双方对抗 | 强调检测、响应、溯源能力 |

## 使用建议

1. **按流程阅读**:先读《渗透测试流程与报告》建立合规与流程意识,再按攻击链逐篇深入。
2. **命令注意环境**:示例命令默认 Linux/Kali;Windows 环境请使用等效命令(如 `netstat -ano` 替代 `ss -tlnp`)。
3. **工具需自备**:文中工具(subfinder、nmap、sqlmap、BloodHound 等)均可在 Kali 中 `apt install` 或从官方仓库获取。
4. **勤打靶场**:建议配合 DVWA、Vulhub、HackTheBox、VulnHub 等合法靶场练习,避免在生产环境试错。
5. **联动本知识库**:攻防对抗视角见 `02-攻防对抗` 模块;方法论细节见 `00-总览`。

## 关键安全原则(贯穿全模块)

- **先授权,后测试**:无书面授权的一切扫描均为非法。
- **最小影响**:优先使用非破坏性验证,禁用可能造成数据破坏的 payload。
- **证据留存**:记录时间戳、命令、截图,支撑报告复现步骤。
- **知止**:拿到权限证明(如读到 flag/证明文件)即停止,不做无意义纵深破坏。
- **报告即价值**:漏洞发现但写不出可复现、可修复的报告,测试价值减半。
