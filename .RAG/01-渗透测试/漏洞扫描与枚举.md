# 漏洞扫描与枚举(Vulnerability Scanning & Enumeration)

> 关键词:漏洞扫描, Nessus, OpenVAS, AWVS, Xray, Nuclei, CVE, CVSS, EPSS, 误报处理, 目录枚举, 用户枚举, searchsploit, 漏洞验证, 指纹匹配

## 概述

漏洞扫描与枚举位于信息收集之后、漏洞利用之前,目标是**系统化地发现目标存在的已知漏洞、敏感资源与可枚举信息**。本章覆盖:扫描原理、主流扫描器对比与用法、结果解读、误报处理、Web 目录枚举、用户枚举与 CVE 匹配。

> ⚠️ **仅限授权测试**:扫描器会发送大量探测流量,可能触发 WAF/IDS 拦截、影响业务可用性。正式测试前务必确认授权范围与时间窗口,必要时限速。

## 漏洞扫描原理

漏洞扫描器本质上做三件事,理解原理才能正确解读结果:

1. **指纹匹配(Version-based)**:先识别服务/中间件/应用版本,再与漏洞库(CVE、CNVD、厂商公告)中的「版本→漏洞」对应关系匹配。
   - 优点:速度快、覆盖广;缺点:补丁后版本号不变则误报/漏报(版本号 ≠ 实际补丁状态)。
2. **主动探测(Probe-based)**:发送特定构造的请求/报文,依据响应判断漏洞是否存在。
   - 例如:发送 `../../etc/passwd` 看是否返回文件内容;发送 SQL 注入 payload 看是否报错。
   - 优点:准确率高于指纹匹配;缺点:可能触发业务写入、告警,需控制风险。
3. **验证(Verification)**:对疑似漏洞进行无害化确认(如读取版本号、请求回显标志),或直接尝试利用(仅在授权的高可信阶段)。

**判断标准**:扫描结果可信度排序为 主动探测验证 > 指纹匹配;凡是「仅凭版本号」判定的漏洞都要在利用前人工复核。

## 主流扫描器对比

| 扫描器 | 类型 | 特点 | 适用场景 | 许可证 |
| --- | --- | --- | --- | --- |
| Nessus | 主机/网络综合扫描器 | 漏洞库全、插件多、报告专业 | 主机与网络设备基线扫描 | 商业(有免费版) |
| OpenVAS | 主机/网络综合扫描器 | 开源、功能接近 Nessus | 预算有限的团队 | GPL(开源) |
| AWVS(Acunetix) | Web 应用扫描器 | Web 漏洞覆盖深、含爬虫 | Web 应用专项扫描 | 商业 |
| Xray | Web 应用扫描器(被动/主动) | 国内团队常用、被动模式可接流量 | Web 应用、配合 Burp 使用 | 社区版免费 |
| Nuclei | 模板化快速扫描器 | 基于 YAML 模板、极快、可自写模板 | 大规模资产巡检、专项 CVE 检测 | 开源 |
| Burp Suite Pro | Web 手工+自动 | 爬虫与扫描器,配合人工测试 | Web 渗透测试(行业标准) | 商业(社区版免费) |
| Goby | 资产+漏洞扫描 | 资产测绘+PoC 验证,可视化拓扑 | 资产梳理与快速验证 | 免费/商业 |

**选型建议**:
- 主机/内网环境 → Nessus 或 OpenVAS。
- Web 应用 → AWVS / Xray / Burp Pro;大规模资产 → Nuclei。
- 攻防演练快速打点 → Nuclei + Goby 组合。

## 扫描器用法示例

### Nessus(主机扫描)

```bash
# Nessus 为图形界面工具(https://localhost:8834),CLI 常用 nessuscli
# 1) 创建扫描策略:选择 "Basic Network Scan"
# 2) 填 Targets:1.2.3.4, 5.6.7.0/24
# 3) 凭据扫描(Credentialed Scan)可发现配置类漏洞,非凭据扫描只测暴露面
# 4) 导出报告:PDF/HTML/CSV,按主机与严重级别分组
# 命令行触发(需先登录获取 token)
curl -k -H "X-ApiKeys: accessKey=xxx; secretKey=xxx" \
  -X POST "https://localhost:8834/scans" -d '{"uuid":"扫描模板ID","settings":{"name":"test","text_targets":"1.2.3.4"}}'
```

### OpenVAS(GVM)

```bash
# Kali 安装
apt install gvm && gvm-setup && gvm-start
# 图形界面 https://127.0.0.1:9392
# 快速扫描:Tasks → New Task → 选择 "Full and fast" 配置 → 填目标主机
# 导出:Reports → 选择报告 → 导出 PDF/XML
```

### AWVS / Xray(Web)

```bash
# Xray 被动模式(推荐:挂代理,仅扫描真实流量涉及的路径,减少误报)
xray webscan --listen 127.0.0.1:7777 --html-output report.html
# 浏览器/Burp 设置代理 127.0.0.1:7777,正常浏览目标站点
# Xray 主动模式(需谨慎限速)
xray webscan --basic-crawler http://target.com --html-output report.html
# 配置高级选项见 config.yaml:限速、跳过静态资源、POC 开关
```

### Nuclei(模板化扫描)

```bash
# 安装:go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest
# 全模板扫描(默认不启用危险模板)
nuclei -u http://target.com -o results.txt
# 指定模板分类:只扫 CVE 或技术栈
nuclei -u target.com -t cves/ -t exposures/configs/
nuclei -l urls.txt -t http/ -severity high,critical -rate-limit 100
# 更新模板
nuclei -update-templates
# 自定义模板示例(判断 HTTP 响应头暴露指纹)
# templates/my-tmpl.yaml:
# id: example-check
# info: { name: example, author: you, severity: info }
# http:
#   - method: GET
#     path:
#       - "{{BaseURL}}/"
#     matchers:
#       - type: word
#         words: ["X-Powered-By: PHP"]
```

## 扫描结果解读

### 严重级别与评分体系

| 体系 | 说明 |
| --- | --- |
| CVSS v3.x | 通用漏洞评分 0.0-10.0:Critical(9.0-10.0)、High(7.0-8.9)、Medium(4.0-6.9)、Low(0.1-3.9)、None(0)。由攻击向量(AV)、攻击复杂度(AC)、权限要求(PR)、用户交互(UI)、影响(C/I/A)组成 |
| EPSS | Exploit Prediction Scoring System,0-1 的概率值,表示漏洞未来 30 天被实际利用的概率。**EPSS 高 + CVSS 高 = 优先修复** |
| KEV | CISA Known Exploited Vulnerabilities 目录,在野外已被利用的漏洞,优先级最高 |

```text
判断优先级公式(实操):
  P0:在 KEV 目录 或 (CVSS ≥ 9.0 且 EPSS > 0.2) —— 立即修复
  P1:CVSS 7.0-8.9 且影响核心资产 —— 本周内修复
  P2:其余 High/Medium,存在可利用路径 —— 排期修复
  P3:信息类(Info)、无法验证 —— 记录观察
```

### 常见误报类型与处理

| 误报类型 | 表现 | 处理方式 |
| --- | --- | --- |
| 版本号误判 | 打了补丁但版本号未变 | 人工确认补丁时间/厂商公告 |
| 指纹误判 | 指纹规则太宽,把相似响应当目标 | 用 Burp 复现请求,人工验证 |
| 扫描器自身特征 | 探测器请求被 WAF 特殊响应干扰 | 关闭 WAF 防护再扫或被动模式 |
| 业务正常行为 | 把业务功能(如文件上传)报为漏洞 | 结合业务场景判断,联系开发确认 |
| 环境相关 | 依赖项漏洞但实际未使用 | 核对组件是否真实加载、可达 |

**误报处理流程**:扫描结果 → 复现(手工重放 payload)→ 判断可利用性 → 不可利用标为「已核实不可利用」并从报告剔除或降级。

## Web 目录枚举

目录枚举用于发现未公开入口:后台、备份文件、敏感路径、API 文档等。

```bash
# dirsearch(常用)
dirsearch -u http://target.com -e php,html,js,txt -t 20 --random-agent
# ffuf(快,支持自定义)
ffuf -u http://target.com/FUZZ -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -mc 200,204,301,302,403 -o dirs.json
# gobuster(经典)
gobuster dir -u http://target.com -w /usr/share/wordlists/dirb/common.txt -x php,bak,txt
# 常见敏感文件手动验证
# /robots.txt  /sitemap.xml  /.git/config  /.svn/entries  /backup.zip
# /admin/  /phpmyadmin/  /actuator/  /swagger-ui.html  /api-docs  /.env  /web.config.bak
```

**判断标准**:
- 状态码 200 + 可读内容 = 确认存在。
- 302 跳转到登录页 = 存在但受保护,记录待后续测试。
- 403 = 存在但禁止访问,可尝试绕过(改方法、加 `X-Forwarded-For`、`..;/` 路径混淆)。
- **留意** `/.git/`、`/.env`、`/backup.*` 等高价值目标,配合《信息收集.md》Git 泄露章节。

## 用户枚举

用户枚举(Username Enumeration)通过响应差异确认账号是否存在,是暴力破解与撞库的前提。

```bash
# 1) 登录接口响应差异:账号不存在 → "用户不存在";存在 → "密码错误"
curl -s -X POST http://target.com/login -d "username=admin&password=x" | grep -iE "不存在|错误"
# 2) 注册接口:提示 "邮箱已注册" 即确认存在
# 3) 忘记密码/找回密码:不同账号返回不同提示
# 4) 时间差:账号存在时后端执行密码校验耗时更长(秒级判断)
# 5) 批量枚举(基于响应码/响应体长度)
# 使用 wfuzz 按响应特征过滤
wfuzz -z file,users.txt -d "username=FUZZ&password=wrong" -u http://target.com/login \
  --hh 与错误账号一致的响应长度   # 排除相同长度,剩余即为存在的账号
```

**防御**:统一错误提示(「用户名或密码错误」)、注册/找回接口加验证码与频率限制、登录接口限速。

## 版本漏洞对应与 CVE 搜索

拿到服务/组件版本后,需要匹配已知漏洞并找可利用 PoC。

```bash
# searchsploit(Exploit-DB 离线库)
searchsploit apache 2.4.49
searchsploit wordpress plugin      # 按组件搜索
searchsploit -t struts             # 标题搜索
searchsploit -p 50383              # 查看路径与详情
searchsploit -m 50383              # 下载到当前目录

# Nuclei 专项:直接按 CVE 检测
nuclei -u target.com -t cves/2021/CVE-2021-41773.yaml

# 在线资源
# CVE/NVD:https://nvd.nist.gov/vuln/search
# CNVD:https://www.cnvd.org.cn
# 阿里云漏洞库:https://avd.aliyun.com
# Exploit-DB:https://www.exploit-db.com
# GitHub 搜索:https://github.com/search?q=CVE-2021-41773&type=repositories
# 漏洞情报:https://www.vulhub.org(含一键环境复现)
# 中文应急:https://help.aliyun.com/noticelist 、奇安信/绿盟公告
```

**匹配流程**:

```text
版本指纹 → searchsploit 本地匹配 → NVD/CNVD 确认 CVE 与影响版本
→ 查 EPSS(https://www.first.org/epss)与 KEV 确认实际利用情况
→ Vulhub/靶场复现 → 授权范围内验证 → 记录到报告
```

**注意**:多数 CVE 只有 PoC 无完整利用;商业情报(如 Vulners、Rapid7 数据库)可按版本批量匹配。对组件版本要留意「发行版补丁回移」现象(RHEL/Debian 会 backport 修复而不升版本号),避免误报。

## 扫描与枚举的防御视角

1. **减少指纹暴露**:隐藏 `Server`/`X-Powered-By` 头、移除默认页面与报错详情。
2. **封禁扫描特征**:WAF 规则识别 nmap/Nuclei/ffuf 的 UA 与请求模式;对高频 404/异常路径限速封禁。
3. **敏感路径管控**:`.git`、备份文件、管理入口禁止公网访问;使用跳板/VPN 才可访问。
4. **统一登录反馈**:杜绝用户枚举;登录/找回密码接口加验证码、限速、锁定策略。
5. **漏洞管理闭环**:扫描器发现的漏洞进入工单系统,按 CVSS+EPSS 分级排期,复测确认修复。
6. **扫描器自身安全**:扫描器凭据与报告文件加密存储,防止内部信息二次泄露。
