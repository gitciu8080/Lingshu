# 系统安全加固

> 关键词:Linux加固,Windows加固,账户策略,口令策略,SSH加固,chattr,SUID,SGID,firewalld,iptables,ufw,sysctl,auditd,rsyslog,logrotate,PAM,SELinux,AppArmor,UAC,组策略,审核策略,加固清单

## 加固前准备
- 备份系统关键配置与数据(生产环境准备回滚方案);记录当前状态:开放端口(`ss -tlnp`)、自启服务(`systemctl list-unit-files`)、现有用户与权限。
- 加固策略先小范围测试再批量下发,每改一项验证业务连通性,避免"加固完成、业务全挂"。
## Linux 加固(以 CentOS 7/8、Ubuntu 20.04/22.04 为例)
### 账户与口令策略
#### 密码复杂度与有效期
口令策略核心配置在 `/etc/login.defs`(有效期)与 `/etc/security/pwquality.conf`(RHEL 系复杂度)或 `/etc/pam.d/common-password`(Debian 系)。

`/etc/login.defs` 关键项:
```
PASS_MAX_DAYS   90      # 密码最长有效期 90 天
PASS_MIN_DAYS   7       # 最短修改间隔,防止频繁改回旧密码
PASS_WARN_AGE   14      # 过期前 14 天提醒
```
`/etc/security/pwquality.conf`(RHEL 系):
```
minlen = 12          # 最小长度 12
dcredit = -1         # 至少 1 个数字
ucredit = -1         # 至少 1 个大写字母
lcredit = -1         # 至少 1 个小写字母
ocredit = -1         # 至少 1 个特殊字符
maxrepeat = 3        # 同一字符最多连续重复 3 次
difok = 5            # 新密码与旧密码至少 5 个字符不同
```
Debian/Ubuntu 在 `/etc/pam.d/common-password` 追加:
```
password requisite pam_pwquality.so retry=3 minlen=12 dcredit=-1 ucredit=-1 lcredit=-1 ocredit=-1
```
验证:`chage -l <user>` 查看账户有效期;`passwd` 修改密码测试复杂度是否生效。
#### 锁定策略(防暴力破解)
RHEL 系使用 `pam_faillock`(替代旧 pam_tally2),在 `/etc/pam.d/system-auth` 与 `/etc/pam.d/password-auth` 中:
```
auth        required      pam_faillock.so preauth audit silent deny=5 unlock_time=900
auth        sufficient    pam_unix.so
auth        [default=die] pam_faillock.so authfail audit deny=5 unlock_time=900
account     required      pam_faillock.so
```
含义:连续失败 5 次锁定 15 分钟;默认不锁 root,如需锁 root 加 `even_deny_root`(需评估运维风险)。维护解锁:`faillock --user <user> --reset`。
Debian/Ubuntu(`/etc/pam.d/common-auth`):
```
auth required pam_faillock.so preauth deny=5 unlock_time=900
auth required pam_faillock.so authfail deny=5 unlock_time=900
```
#### 账户管理检查项
```bash
awk -F: '($2==""){print $1}' /etc/shadow     # 空口令账户(应无输出)
awk -F: '($3==0){print $1}' /etc/passwd      # UID=0 账户(应只有 root)
lastlog                                         # 最近登录记录,发现异常
```
建议:禁用无用系统账户(`usermod -L <user>` 或 `passwd -l <user>`);非 root 的 UID=0 账户一律删除;`/etc/sudoers` 用 `visudo` 修改并精确授权。
### SSH 加固
配置文件 `/etc/ssh/sshd_config` 关键项:
```
Port 2222                     # 修改默认端口,降低扫描暴露(需同步放行防火墙)
Protocol 2                    # 仅允许 SSHv2
PermitRootLogin no            # 禁止 root 直接登录(先普通用户再 su/sudo)
PubkeyAuthentication yes      # 启用密钥认证
PasswordAuthentication no     # 关闭密码认证,仅密钥登录
PermitEmptyPasswords no       # 禁止空密码
MaxAuthTries 3                # 单连接最大认证尝试 3 次
LoginGraceTime 60             # 登录超时 60 秒
ClientAliveInterval 300       # 每 300 秒发送保活探测
ClientAliveCountMax 2         # 无响应 2 次后断开
AllowUsers ops@10.0.0.0/8     # 白名单:仅允许指定用户及来源
X11Forwarding no              # 关闭 X11 转发
AllowTcpForwarding no         # 无需隧道转发时关闭
```
密钥登录配置:
```bash
ssh-keygen -t ed25519 -a 100            # 客户端生成密钥
ssh-copy-id -p 2222 ops@server          # 分发公钥
chmod 600 ~/.ssh/authorized_keys        # 公钥文件权限
```
要点:改端口后先测试新端口连通再重载;`sshd -t` 校验语法;`systemctl reload sshd` 平滑重载;有条件时用 `Match` 块按来源限定认证方式,并在网络层把 SSH 端口限制为管理网段/堡垒机来源。

### 文件与权限
#### umask
设置默认 umask 为 027 或 077,确保新建文件不默认对组/其他可写:
```bash
# /etc/profile 或 /etc/bashrc 中;亦可写入 /etc/login.defs
umask 027
UMASK 027
```
#### SUID/SGID 排查
```bash
find / -perm -4000 -type f 2>/dev/null   # SUID 文件
find / -perm -2000 -type f 2>/dev/null   # SGID 文件
find / -perm -6000 -type f 2>/dev/null   # 同时含 SUID+SGID
```
保留白名单(ping、sudo、passwd、mount 等),其余高危 SUID(如 vim、find、bash、less、cp)执行 `chmod u-s <file>` 移除;建立 SUID 白名单快照定期对比,发现新增 SUID 即告警。
#### 关键文件属性 chattr
对关键配置与日志加不可变/追加属性,防篡改:
```bash
chattr +i /etc/passwd /etc/shadow /etc/group /etc/gshadow   # +i 不可修改
chattr +a /var/log/messages /var/log/secure                 # +a 仅可追加
lsattr /etc/passwd                                            # 查看属性
chattr -i /etc/passwd                                         # 解除
```
注意:chattr +i 会阻止用户/服务正常修改(如 passwd 改密),变更前先解除;对 /etc/shadow 加锁需评估运维流程。
### 服务最小化
```bash
systemctl list-unit-files --type=service | grep enabled   # 自启服务清单
systemctl disable --now <service>                          # 停用并禁止自启
ss -tlnp                                                    # 监听端口与进程
```
建议停用的常见无用服务:telnet、rlogin、rsh、tftp、chargen、echo、daytime、cups、avahi-daemon、bluetooth、postfix(非邮件服务器)。规则:非业务必需服务一律 disable;未知监听端口用 `ss -tlnp` 定位进程并溯源。

### 防火墙(firewalld / iptables / ufw)
#### firewalld(CentOS/RHEL 7+)
```bash
systemctl enable --now firewalld
firewall-cmd --permanent --zone=public --remove-service=ssh
firewall-cmd --permanent --zone=public --add-port=2222/tcp
firewall-cmd --permanent --zone=public --add-rich-rule='rule family="ipv4" source address="10.0.0.0/8" port port="2222" protocol="tcp" accept'
firewall-cmd --permanent --zone=public --set-target=DROP      # 默认丢弃
firewall-cmd --reload
firewall-cmd --list-all
```
#### iptables(裸 iptables 场景)
```bash
iptables -P INPUT DROP          # 默认拒绝入站
iptables -A INPUT -i lo -j ACCEPT
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A INPUT -s 10.0.0.0/8 -p tcp --dport 2222 -j ACCEPT
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT
iptables -A INPUT -j DROP
service iptables save          # 持久化(或安装 iptables-persistent)
```
#### ufw(Ubuntu)
```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow from 10.0.0.0/8 to any port 2222 proto tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
ufw status verbose
```
规则次序:显式放行白名单 → 默认拒绝;管理端口放行必须限定来源 IP,避免全网可达。

### 内核参数加固(sysctl)
写入 `/etc/sysctl.d/99-hardening.conf`,执行 `sysctl -p` 生效:
```
net.ipv4.ip_forward = 0                    # 关闭 IP 转发(非路由场景)
net.ipv4.conf.all.send_redirects = 0       # 禁止发送 ICMP 重定向
net.ipv4.conf.all.accept_redirects = 0     # 禁止接收 ICMP 重定向
net.ipv4.conf.all.accept_source_route = 0  # 禁止源路由
net.ipv4.tcp_syncookies = 1                # SYN Cookie,防 SYN Flood
net.ipv4.icmp_echo_ignore_broadcasts = 1   # 忽略广播 ping
net.ipv4.icmp_ignore_bogus_error_responses = 1
net.ipv4.conf.all.rp_filter = 1            # 反向路径过滤,防 IP 欺骗
net.ipv4.conf.all.log_martians = 1         # 记录异常源地址
net.ipv6.conf.all.accept_redirects = 0     # IPv6 同理收紧
kernel.sysrq = 0                           # 关闭 SysRq 调试
kernel.core_uses_pid = 1
```
验证:`sysctl -a | grep -E 'ip_forward|syncookies|accept_redirects'`。

### 日志与审计
#### rsyslog 集中收集
```bash
# /etc/rsyslog.conf:转发关键日志到日志服务器,并收紧文件权限
*.*  @10.0.1.10:514
$FileCreateMode 0640
$DirCreateMode 0750
systemctl restart rsyslog
```
#### auditd 审计
```bash
yum install audit -y          # 或 apt install auditd
systemctl enable --now auditd
# 规则 /etc/audit/rules.d/audit.rules
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/sudoers -p wa -k sudoers          # sudoers 变更
-w /etc/ssh/sshd_config -p wa -k sshd     # sshd 配置变更
-a always,exit -F arch=b64 -S execve -k exec            # 记录命令执行
-a always,exit -F arch=b64 -S setuid,setgid -k priv     # 记录提权调用
augenrules --load && service auditd restart
auditctl -l                     # 查看规则
ausearch -k identity            # 检索审计事件
aureport -au                    # 认证失败报表
```
#### logrotate
```bash
/var/log/secure {   # 配置于 /etc/logrotate.d/
    weekly
    rotate 12          # 保留 12 份
    compress
    missingok
    notifempty
    create 0600 root root
}
```
### PAM 加固
- 限制 root 远程登录:配合 sshd 的 `PermitRootLogin no`。
- 限制可登录用户与来源:`/etc/security/access.conf` 中 `+:root:10.0.0.0/8`、`-:ALL:ALL`。
- 防资源耗尽:`/etc/security/limits.conf` 中限制 `nofile`、`nproc`、`maxlogins`。
- 复核 `/etc/pam.d/system-auth` 已引入 faillock 与 pwquality(见上文)。

### SELinux / AppArmor
**SELinux(RHEL/CentOS)**:保持 enforcing 模式,而非禁用。
```bash
getenforce                 # 查看当前状态
setenforce 1               # 临时开启
# /etc/selinux/config 设 SELINUX=enforcing 永久生效;业务异常时用 audit2allow 精化策略:
grep denied /var/log/audit/audit.log | audit2allow -M mypol && semodule -i mypol.pp
```
**AppArmor(Ubuntu)**:
```bash
aa-status                      # 查看已加载策略
systemctl enable --now apparmor
apparmor_parser -r /etc/apparmor.d/<profile>   # 业务应用 profile 加载
```
原则:二者是纵深防御的一层,禁止以"影响业务"为由直接关闭;异常先按审计日志精化策略。

### 更新源与补丁
- 配置可信更新源(RHEL 官方/镜像源、Ubuntu 官方源),启用 GPG 校验(`gpgcheck=1`)。
- 定期更新:安全补丁按变更窗口执行(`yum update -y --security` / `apt update && apt upgrade`),先在测试环境验证;内核与依赖重大更新需重启,纳入变更窗口与回滚预案(详见《补丁与配置管理.md》)。

## Windows 加固
### 账户策略(secpol.msc)
路径:`secpol.msc → 账户策略 → 密码策略 / 账户锁定策略`:
- 密码必须满足复杂性要求:已启用;密码长度最小值:12;密码最长使用期限:90 天;强制密码历史:5 个。
- 账户锁定阈值:5 次无效登录;账户锁定时间:15 分钟;重置账户锁定计数器:15 分钟。
命令行等效:
```
net accounts /maxpwage:90 /minpwlen:12 /uniquepw:5 /lockoutthreshold:5 /lockoutduration:15
```
### 本地安全策略
- **审核策略**:开启登录事件(成功/失败)、账户登录、账户管理、策略更改、对象访问(失败)审核:
```powershell
auditpol /set /subcategory:"Logon" /success:enable /failure:enable
auditpol /set /subcategory:"Account Logon" /success:enable /failure:enable
auditpol /set /subcategory:"Account Management" /success:enable /failure:enable
```
- **用户权限分配**:收紧"从网络访问此计算机"、"允许本地登录"成员;禁用 Guest;复核"作为服务登录"主体。
- **安全选项**:禁止匿名枚举 SAM 账户;SMB 通信签名设为"始终";禁用 SMBv1(`Set-SmbServerConfiguration -EnableSMB1Protocol $false`)。

### 服务与启动项清理
```powershell
Get-Service | Where-Object {$_.StartType -eq 'Automatic'}   # 自启服务
Set-Service -Name Spooler -StartupType Disabled             # 示例:停用打印服务
Get-CimInstance Win32_StartupCommand                        # 启动项
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run'
Get-ScheduledTask | Where-Object {$_.State -eq 'Ready'}     # 计划任务排查
```
原则:非业务必需服务改为 Disabled 或 Manual;未知启动项与计划任务逐一溯源,无法解释的立即隔离排查。

### 防火墙(Windows Defender Firewall)
`wf.msc` → 入站规则:
- 默认入站:阻止(域/专用/公用三个配置文件均设为"阻止")。
- 仅放行业务端口,管理端口限定来源 IP;RDP(3389)建议仅内网网段放行、启用 NLA,必要时改高端口或经堡垒机代理。
```powershell
New-NetFirewallRule -DisplayName "RDP-Allow-Internal" -Direction Inbound -Protocol TCP -LocalPort 3389 -RemoteAddress 10.0.0.0/8 -Action Allow
Set-NetFirewallProfile -Profile Domain,Private,Public -DefaultInboundAction Block
```

### UAC(用户账户控制)
- 保持 UAC 开启,"对管理员使用管理员审批模式"= 已启用;不要将 UAC 调至"从不通知"。
- 日常使用标准用户账号,管理员账号仅在提权时使用;配合 LAPS 管理本地管理员密码。
### 组策略常用项(gpedit.msc)
| 策略路径 | 建议 |
| --- | --- |
| 计算机配置→Windows 设置→安全设置→本地策略→审核策略 | 关键审核全部开启 |
| 计算机配置→管理模板→Windows 组件→远程桌面服务→连接 | 启用 NLA;限制连接数 |
| 计算机配置→管理模板→网络→Windows 防火墙 | 入站默认阻止 |
| 计算机配置→管理模板→系统→Internet 通信管理 | 关闭不必要的自动搜索/反馈 |
| 计算机配置→管理模板→系统→远程协助 | 按需禁用远程协助 |
| 用户配置→管理模板→控制面板→显示 | 屏幕保护+恢复时密码保护 |
### 补丁更新
- 启用 Windows Update 或 WSUS/Intune 统一管理;安全更新按月例行,紧急补丁(如已公开利用的 RCE)按应急流程 72 小时内处理。
- 更新前在测试环境验证;生产分批发布(Canary→分组→全量);保留回滚路径(`wusa /uninstall /kb:xxxx`)。

- 功能回归:业务端口连通性、SSH 登录、数据库连接、Web 访问、日志正常写入。
- 对照《基线核查.md》输出差距项并跟踪整改;建立配置基线快照,配合 CMDB 检测配置漂移(见《补丁与配置管理.md》)。
