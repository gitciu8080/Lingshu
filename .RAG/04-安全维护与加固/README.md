# 安全维护与加固

> 关键词:安全维护,系统加固,加固原则,最小权限,默认拒绝,纵深防御,攻击面,安全基线,等保2.0,整改闭环,模块导航

## 模块定位

"安全维护与加固"是网络安全知识库的第四模块,面向系统管理员、安全运维工程师、等保测评与整改人员,覆盖从操作系统、Web 服务、网络设备到安全基线核查与补丁管理的完整加固知识体系。

安全维护(Operation & Maintenance)与加固(Hardening)是持续性的安全工作:加固解决"当前配置是否安全"的问题,维护解决"安全状态能否长期保持"的问题。二者结合形成"初始加固 → 基线核查 → 整改 → 补丁与变更 → 再核查"的闭环,而不是一次性的上线动作。

## 加固(Hardening)的核心概念

加固指通过**修改默认配置、关闭非必要功能、收紧权限、修补已知漏洞**等方式,缩小系统的攻击面(Attack Surface),降低被入侵与横向移动的可能性。

- **攻击面**:系统对外暴露的所有入口,包括开放端口、服务进程、管理接口、Web 应用、弱口令账号、未打补丁的组件等。加固的本质是"能不开的不开,能不用的不用,能少暴露就少暴露"。
- **默认不安全**:多数操作系统与网络设备的出厂配置面向"可用性"而非"安全性",如默认开放服务、默认口令、宽松的 ACL 与默认共享,因此上线前必须进行基线化加固。
- **加固 ≠ 一次性**:配置会发生漂移(Configuration Drift),新装软件、临时排障、人员操作都可能破坏加固状态,需要通过基线核查定期复检(见《基线核查.md》)与配置管理持续约束(见《补丁与配置管理.md》)。

## 加固原则

### 最小权限原则(Principle of Least Privilege)

任何用户、进程、服务只拥有完成任务所必需的最小权限,权限"按需授予、用完回收、定期复核"。

- **账户**:区分管理员与普通用户;禁止使用 root/Administrator 直接操作;sudo 精确到命令与参数。
- **文件**:敏感文件权限 600/640,目录 700/750;剥离不必要的 SUID/SGID 位。
- **进程**:Web/DB 等业务服务使用独立低权限账号运行,而非 root/Administrator。
- **网络**:只放行业务必需端口,且限定来源 IP 段。

### 默认拒绝(Default Deny)

没有明确允许的,一律拒绝。具体体现:

- **防火墙策略**:先拒绝全部,再显式放行白名单(显式 allow、隐式 deny)。
- **访问控制**:文件 ACL、SELinux/AppArmor 策略、交换机端口安全均以允许清单为准。
- **Web 服务**:默认关闭目录列表,默认拒绝非必要 HTTP 方法(如 DELETE/TRACE)。

### 纵深防御(Defense in Depth)

不依赖单一防线,在网络、主机、应用、数据多个层面叠加防护,任何一层被突破后,后续层仍能阻断或检出:

```
网络层(防火墙/ACL/分段) → 主机层(系统加固/HIDS) → 应用层(WAF/代码审计) → 数据层(加密/备份) → 管理面(审计/监控/响应)
```

### 其他常用原则

- **失效安全(Fail-Safe)**:组件失效或策略异常时默认进入拒绝/关闭状态,而不是放行。
- **最小暴露面(Minimal Exposure)**:关闭未使用服务、隐藏版本信息、收敛管理端口到内网或堡垒机。
- **可审计性(Auditability)**:所有变更、登录、权限调整留痕,日志集中收集且不可篡改。
- **变更最小化(Change Minimization)**:加固操作先评估业务影响,走审批、测试、灰度与回滚预案(见《补丁与配置管理.md》)。

## 加固落地五步法

1. **盘点**:梳理资产清单、开放端口、服务、账号与权限(基线核查的第一步)。
2. **定标**:对照等保2.0、CIS 等基线确定本组织的加固标准(见《基线核查.md》)。
3. **执行**:按《系统安全加固.md》《Web安全加固.md》《网络设备安全配置.md》逐项落地。
4. **验证**:功能回归 + 基线核查工具复核,输出差距项。
5. **维持**:纳入 CMDB、配置漂移检测、周期性核查与补丁流程,防止回退。

## 与等保2.0的对应关系

加固工作与等保2.0(GB/T 22239-2019)三级要求高度对应,便于测评整改对照:

| 等保2.0 控制点 | 对应模块内容 |
| --- | --- |
| 身份鉴别 | 口令策略、锁定策略、SSH 密钥认证、双因素 |
| 访问控制 | 最小权限、文件权限、防火墙策略、ACL、安全组 |
| 安全审计 | auditd、Windows 审核策略、设备日志集中、NTP 校时 |
| 入侵防范 | 服务最小化、内核参数、WAF、SELinux/AppArmor |
| 恶意代码防范 | 补丁管理、组件版本管理、虚拟补丁 |
| 集中管控 | 基线核查、CMDB、补丁台账、变更审批 |

## 角色与职责

- **系统/网络管理员**:执行加固与补丁落地,保证业务可用性,提供变更与回滚记录。
- **安全运维**:制定基线标准、组织核查、跟踪整改闭环、维护补丁台账与例外清单。
- **业务方**:确认加固与补丁的业务影响,参与例外审批与变更窗口协调。
- **管理层**:审批高风险变更与例外,提供资源保障(测试环境、工具、人力)。

## 典型应用场景

- **新系统上线**:按《系统安全加固.md》+《Web安全加固.md》执行加固,用《基线核查.md》方法验证达标后再接入业务。
- **护网/重保前**:全量基线核查 + 公网暴露面收敛 + WAF/补丁复查,输出整改与例外清单。
- **等保测评整改**:以测评结论中的不符合项为差距清单,按加固文档修复,复测闭环。
- **日常安全运营**:漏洞跟踪 → 补丁评估发布 → 日志巡检 → 周期性核查,维持安全状态。

## 使用建议

1. 新系统上线:按《系统安全加固.md》+《Web安全加固.md》执行加固,再用《基线核查.md》的方法验证达标。
2. 网络改造:参考《网络设备安全配置.md》的区域划分与策略设计,先梳理业务流量再写策略。
3. 长期维持:依赖《补丁与配置管理.md》与基线核查自动化,避免"加固一次、漂移一年"。
4. 所有加固项落地前评估业务影响;重要变更走变更审批与回滚预案;涉及生产的关键配置修改前先备份。

## 常见误区

- **只加固不核查**:认为配置过一次就永远安全,忽略了配置漂移与人员误操作。
- **为了业务便利关闭安全机制**:如直接 `setenforce 0`、关闭防火墙、关闭 UAC,应以精化策略代替整体关闭。
- **只做网络层不做应用层**:防火墙放行后不再关注 Web 应用漏洞,导致 WAF/应用加固缺失。
- **补丁只打操作系统不打组件**:Web 框架、中间件、第三方库才是高危漏洞的重灾区。
- **加固清单不维护**:检查项不随新版本、新威胁更新,基线过期。
