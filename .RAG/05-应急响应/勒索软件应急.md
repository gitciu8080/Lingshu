# 勒索软件应急(Ransomware Incident Response)

> 关键词:勒索软件,勒索病毒,加密勒索,Ransomware,断网隔离,解密工具,No More Ransom,备份恢复,支付赎金,3-2-1备份,RDP防护,横向移动,应急处置时间线,锁定文件,赎金信,扩展名

## 一、发现与确认(Detection & Confirmation)

勒索软件攻击通常表现为文件被加密后索要赎金。**确认要快但动作要稳**:先判断是不是勒索,再执行遏制。

**典型加密迹象**:

- 文件打不开、扩展名批量变化(如 `.locked`、`.encrypted`、`.crypt`、`.devos`、`.phobos`、`.mkp`、`.babyk`)
- 桌面/目录出现勒索信(通常为 `README.txt`、`HOW_TO_DECRYPT.txt`、`DECRYPT.html`,内容含 Tor 洋葱地址与比特币地址)
- 系统出现大面积异常弹窗、壁纸被替换、文件名被追加随机后缀
- 杀毒软件/EDR 大量告警,文件被改、被删、被加密事件井喷
- 文件被改名且伴随 **Shadow Copy(卷影副本)被删除**、备份被清除
- 服务器性能异常、磁盘 IO 飙升、异常进程(如 `taskhost.exe`、随机名进程)大量写盘

**确认动作**:

1. 查看勒索信内容:勒索信中的扩展名、邮箱、BTC 地址是确认勒索家族的关键线索
2. 用勒索信特征(扩展名、勒索信文件名、BTC 地址)在 **No More Ransom 项目**与威胁情报平台查询家族归属
3. 查看是否有已知可解密工具(见恢复章节),确认前**不要重启系统**,避免丢失内存证据

> ⚠️ 不要双击打开可疑加密文件或勒索信里的链接;勒索信里的"解密工具下载链接"可能是二次投毒。

## 二、第一时间行动清单(First Response Checklist)

按顺序执行,头 30 分钟决定损失上限:

- [ ] **1. 断开网络**:立即拔掉受影响主机网线/关闭交换机端口/断无线,阻止横向传播与数据外传
- [ ] **2. 隔离而非关机**:失陷主机**先断网、不要关机**,保留内存与进程证据;如判断为磁盘加密型(非内存驻留),可断网后保持运行
- [ ] **3. 保护证据**:对受影响主机做内存转储与磁盘镜像(若条件允许),记录屏幕现象、勒索信文件
- [ ] **4. 冻结备份系统**:立即暂停备份作业或断开备份存储,防止备份被加密/覆盖;确认备份副本完好性
- [ ] **5. 通知与上报**:按预案通知安全负责人、管理层、IT 运维,启动应急小组;达到分级标准时上报监管
- [ ] **6. 封禁 IOC**:在边界防火墙封禁已知 C2 域名/IP、BTC 钱包相关域名,阻断外联
- [ ] **7. 关闭高危服务**:临时关闭 RDP 对外端口、SMB 共享写权限、域管理员账号远程登录
- [ ] **8. 记录时间线**:记录发现时间、动作时间、负责人,供后续复盘

> **常见错误**:直接关机(丢失内存证据)、直接重装(丢失样本与证据)、继续开机联网(扩大加密范围)、未隔离就查杀(攻击者仍可横向移动)。

## 三、排查感染范围与传播方式(Scoping & Propagation Analysis)

**感染范围排查**:

- 通过 EDR/SIEM 检索异常文件写入事件(大量文件扩展名变更、批量改名、卷影删除)
- 扫描内网:检查其他主机是否有相同扩展名文件、相同可疑进程、勒索信文件
- 检查共享盘/网络映射盘是否被加密(勒索软件常优先加密网络共享)
- 检查备份系统:备份是否被删除/加密,备份代理账号是否被滥用

**常见传播方式(对应排查方向)**:

| 传播方式 | 特征线索 | 排查方向 |
| --- | --- | --- |
| 漏洞利用(如永恒之蓝 MS17-010、Log4j) | 445 端口异常连接、补丁缺失 | 检查补丁情况、防火墙 445 访问日志 |
| 弱口令/RDP 爆破 | 大量 4625 登录失败后 4624 成功 | 查 Windows 安全日志 RDP 登录、事件 4624/4625 |
| 钓鱼邮件 | 用户邮箱可疑附件、宏文档 | 查邮件网关日志、用户终端 |
| 供应链/软件破解 | 内网软件分发异常 | 查软件分发服务器、下载源 |
| 域渗透后批量投放 | 域内批量主机同时中毒、GPO 异常 | 查 AD 登录事件、GPO 修改记录 |

**排查重点**:攻击者的**初始入口**和**是否已获取域管理员权限**——后者决定影响面是否覆盖全内网。

## 四、遏制措施(Containment)

- **隔离网段**:在核心交换机/防火墙将受影响网段与其余网络隔离;关闭受影响主机间的互访
- **停服务**:停止受影响服务器上的业务服务(数据库、文件服务、Web)
- **禁用账号**:锁定被利用的账号、攻击者可能使用的域账号;修改本地管理员口令
- **阻断 C2**:防火墙封禁已知 C2 IP/域名、Tor 出口节点;DNS 层做 sinkhole
- **关闭入口**:临时关闭对外 RDP、SMB 1.0/445 访问、VPN 中可疑用户会话
- **保护备份**:备份存储断连、只读挂载,验证备份完整性(这是恢复的底气)

> 遏制目标:先让加密停止、外传停止、横向移动停止。若攻击仍在扩散,果断扩大隔离范围,必要时断全网——与业务方确认后执行。

## 五、根除(Eradication)

- **查杀**:用最新病毒库/专杀工具(如 Emsisoft Emergency Kit、卡巴勒索专杀)全盘扫描清除勒索样本;确认无驻留(内存型勒索需重启后复查)
- **清除持久化**:检查计划任务、服务、注册表 Run 键、启动文件夹、WMI 订阅、vbs/ps1 脚本残留
- **封堵入口**:修复被利用漏洞、加固 RDP(改端口/限来源 IP/启用 NLA 与 MFA)、清理弱口令、撤销异常账号权限
- **重置凭据**:重置受影响主机本地口令、域账号口令、服务账号与密钥;轮换可能被窃取的会话令牌
- **验证根除**:确认勒索样本、后门、C2 连接均消失;观察期(至少 7 天)无复发

## 六、恢复(Recovery)

**1. 备份恢复策略**:

- 确认备份**未被污染**(先检查备份中是否有勒索样本与加密文件),从干净备份还原
- 恢复前确认根除已完成,否则还原后会被再次加密
- 恢复顺序:先核心系统(域控、核心业务),后外围;**先恢复监控**,再恢复业务
- 恢复后立即打补丁、改口令、上 EDR,避免二次中招
- 无备份时:评估解密工具;解密无望时重建系统并接受数据损失

**2. 解密工具(No More Ransom 等)**:

- **No More Ransom 项目**(https://www.nomoreransom.org):由 Europol、Kaspersky、McAfee 等联合运营,提供 100+ 勒索家族的免费解密工具
- 使用方式:输入勒索信中的扩展名/邮件/BTC 地址搜索家族 → 下载对应 **Decryptor** → 先在小范围测试
- 其他来源:Emsisoft Decryptor、Avast 解密工具、AVG、卡巴斯基解密页面
- 注意:只从**官方渠道**下载解密工具,警惕冒充解密工具的恶意软件

**3. 支付赎金的风险与法律问题**:

| 风险 | 说明 |
| --- | --- |
| 不保证解密 | 约 1/4 的受害者付费后仍未拿到解密密钥,部分勒索团伙收款即失联 |
| 助长犯罪 | 支付赎金会激励针对本组织的下一次攻击(受害名单被共享) |
| 再次攻击 | 攻击者可能再次入侵,或出售受害者信息 |
| 法律风险 | 支付给受制裁实体(如特定国家背景团伙)可能违反制裁法规;部分司法辖区对支付赎金有限制 |
| 声誉风险 | 支付行为披露后损害信任 |

> 决定是否支付是**管理层决策**,应咨询法务与执法部门;即使支付,也要同时开展备份恢复与止损。支付赎金前先确认:是否有免费解密工具、备份是否可用、支付通道是否合法。

**4. 恢复验证**:数据完整性校验、业务功能测试、漏洞复扫、持续监控观察期。

## 七、应急处置时间线示例

```
T+00:00  业务人员反馈文件服务器文件打不开,扩展名变为 .locked
T+00:05  运维确认:大量文件被加密,发现 README.txt 勒索信 → 判定勒索事件
T+00:10  拔掉文件服务器网线,暂停所有备份作业,断开备份存储
T+00:20  启动应急小组;封禁勒索信中的 BTC/C2 相关域名于边界防火墙
T+00:30  用 No More Ransom 检索扩展名 .locked → 识别为某家族,确认无免费解密工具
T+00:45  排查共享盘与其他主机:确认 3 台主机被加密,1 台仍在线但已断网
T+01:00  分析传播路径:发现 445 端口弱口令爆破痕迹 → 临时关闭对外 SMB 与 RDP
T+02:00  对失陷主机做内存转储与镜像取证;用专杀工具查杀,清除计划任务后门
T+04:00  修补漏洞、重置口令、加固 RDP;启用 EDR 全网排查
T+08:00  从干净备份还原文件服务器(先验证备份无污染);恢复核心业务
T+12:00  全系统恢复;进入 7 天监控观察期
T+72:00  完成事件报告与复盘:落实弱口令治理、RDP 加固、备份异地容灾、EDR 覆盖
```

## 八、预防加固(Prevention & Hardening)

- **备份 3-2-1 原则**:至少 **3 份**数据副本,存于 **2 种**不同介质,其中 **1 份**离线/异地存放(防勒索软件连备份一起加密);定期**恢复演练**验证备份可用
- **RDP 防护**:不直接暴露公网;改用 VPN/堡垒机;启用 NLA 与 MFA;限制来源 IP;关闭默认 3389 端口;监控 4625 登录失败
- **补丁管理**:及时修复高危漏洞(重点:MS17-010、Log4j、Exchange、VPN 设备漏洞)
- **EDR/杀软**:部署 EDR 并开启勒索行为检测(批量加密行为、卷影删除行为告警)
- **账号安全**:强制强口令 + MFA,清理本地管理员与共享账号,最小权限
- **邮件防护**:邮件网关过滤宏与可疑附件,禁用 Office 宏自动执行
- **入口收敛**:减少公网暴露面,禁用 SMBv1,关闭不必要的 445/3389 端口
- **演练**:定期做勒索场景应急演练,验证预案、备份恢复与通信流程

## 九、常见勒索家族速查

| 家族 | 典型特征 | 说明 |
| --- | --- | --- |
| LockBit | 扩展名 `.lockbit`,勒索信要求联系 Tor 站点 | 曾最活跃的 RaaS 勒索团伙,赎金极高 |
| Conti | 扩展名 `.CONTI`,勒索信内容长 | 团伙已解散,但变种仍在传播 |
| REvil/Sodinokibi | 扩展名 `.sodinokibi` 等 | 曾针对企业,双重勒索(加密+窃密) |
| Ryuk | 针对企业横向移动后投放 | 常与 TrickBot/Emotet 僵尸网络配合 |
| Maze/Egregor | 双重勒索开创者 | 先窃取数据再加密,威胁公开数据 |
| Phobos/Dharma | 扩展名如 `.phobos`、`.id[xxx].email` | 常经 RDP 爆破入侵,中小企业高发 |
| 永恒之蓝系(WannaCry 变种) | 利用 SMB 漏洞批量传播 | 内网横向传播极快,445 端口爆破特征 |
| STOP/Djvu | 扩展名 `.djvu`,离线加密 | 个人用户高发,部分有免费解密工具 |

**识别步骤**:勒索信内容 + 扩展名 + BTC 地址 → No More Ransom / 威胁情报平台查询家族 → 查是否有官方解密工具 → 无工具则走备份恢复。

## 十、内部通报与升级沟通要点

- **第一时间通知**:安全负责人 + IT 运维 + 管理层(达到定级标准时),说明:发现时间、受影响范围(已知)、当前动作、所需支持
- **信息口径**:初期信息不全时按"已知事实 + 待确认项"汇报,不要猜测定性
- **决策事项清单**:是否断全网、是否支付赎金(需法务意见)、是否对外公告(需 PR 评估)、是否报案(需法务与执法沟通)
- **与业务沟通**:明确告知受影响业务范围与恢复时间预估,协调业务优先级,避免业务自行操作(如重启服务器)破坏证据或扩大影响
- **通报模板要素**:事件概述、影响范围、处置进展、下一步计划、需要决策的问题、联系人

**支付赎金的决策流程**:技术评估(备份可用性、解密工具、数据价值)→ 法务评估(法律风险、制裁合规)→ 管理层决策 → 如支付,由专人通过合规渠道操作并留痕,同时继续推进备份恢复与止损。
