# 日志取证分析(Log & Forensics Analysis)

> 关键词:日志分析,取证,数字取证,证据保全,链式保管,哈希校验,时间线构建,Windows安全日志,事件ID,4624,4625,4720,Linux日志,auth.log,secure,Web访问日志,防火墙日志,内存取证,Volatility,磁盘取证,镜像,文件恢复,攻击链,取证报告

## 一、取证原则(Forensics Principles)

取证的目标是**合法、完整、可追溯**地还原事件真相。四条核心原则:

| 原则 | 说明 | 落地要点 |
| --- | --- | --- |
| 证据保全 | 原始证据不得被修改 | 优先使用只读介质,取证前不要对目标系统做写操作 |
| 链式保管(Chain of Custody) | 证据的每个流转环节可追溯 | 记录:谁、何时、何地、以何种方式取得/移交/存放证据 |
| 只读介质 | 取证过程不污染原始数据 | 使用写保护器(hardware write blocker)或只读挂载 |
| 哈希校验 | 证明证据未被篡改 | 取证时与移送时计算 MD5/SHA-256,哈希一致才有效 |

**取证顺序(易失性从高到低)**:内存/进程 → 网络连接/状态 → 磁盘 → 日志/备份。**先取内存再关机**,关机操作本身会破坏易失证据。

**基本操作规范**:

- 取证现场先拍照、记录环境状态与时间
- 对原始介质只读访问,镜像到干净介质
- 所有命令输出、截图、工具版本留档
- 取证工具与知识库保持更新,使用前记录版本

## 二、时间线构建(Timeline Construction)

时间线是把分散在各类日志中的事件按时间排序,还原攻击过程的核心方法。

**1. 系统时间校准**:

- 先确认每台设备的时间偏差(与 NTP 对比),否则跨设备时间线会错位
- 检查时区设置(UTC vs 本地时间),统一换算后再分析
- 记录时间来源(系统日志、文件时间戳、网络设备时间)

**2. 日志关联**:

- 以**单一标识**串联:源 IP、账号、会话 ID、进程 ID、文件哈希
- 用时间窗口检索:锁定可疑时间点,向前向后扩展(攻击前侦察、攻击后扩散)
- 常见关联维度:登录事件 ↔ 进程创建 ↔ 网络连接 ↔ 文件操作 ↔ Web 访问

**3. 时间线工具**:

- **Splunk / Elastic Stack / SIEM**:统一检索与关联
- **plaso(log2timeline)**、**Timeline Explorer**:构建文件系统时间线
- 手工方式:按时间排序的日志汇总表(Excel/CSV),标注关键节点

## 三、关键日志源(Key Log Sources)

**1. Windows 安全日志(事件 ID 速查表)**:

| 事件 ID | 含义 | 分析要点 |
| --- | --- | --- |
| 4624 | 登录成功 | 重点:Logon Type 3(网络)/10(远程交互,如 RDP)、异常来源 IP、新账号 |
| 4625 | 登录失败 | 大量失败 = 暴力破解;关注源 IP、用户名、次数 |
| 4672 | 赋予特殊权限(管理员登录) | 管理员账号异常登录 |
| 4720 | 创建用户账户 | 攻击者创建后门账号的典型迹象 |
| 4722/4725 | 启用/禁用账户 | 关注异常变化 |
| 4726 | 删除用户账户 | 清理痕迹 |
| 4732/4728 | 将成员添加到本地/全局组 | 提权到 Administrators 的迹象 |
| 4738 | 修改用户账户 | 密码重置等 |
| 4740 | 账户被锁定 | 爆破迹象 |
| 4768/4769 | Kerberos 票据请求/服务票据 | 黄金票据/白银票据相关,4769 异常加密类型可疑 |
| 4688 | 进程创建 | 配合 4689,看异常进程命令行(需开启命令行审计) |
| 4697 | 安装服务 | 服务型后门安装痕迹 |
| 1102 | 安全日志被清除 | 攻击者清除日志的强烈信号 |
| 7045 | 安装新服务(系统日志) | 与 4697 呼应 |

**查看命令**:
```powershell
# 导出指定事件 ID 的安全日志
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime=(Get-Date).AddDays(-7)} | Export-Csv .\4625.csv
# 按来源 IP 统计登录失败
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} | Group-Object {$_.Properties[18].Value} | Sort Count -Descending
```

**2. Linux 日志**:

| 日志文件 | 内容 |
| --- | --- |
| `/var/log/secure`(RHEL/CentOS)或 `/var/log/auth.log`(Debian/Ubuntu) | SSH 登录、sudo、用户操作 |
| `/var/log/messages` / `/var/log/syslog` | 系统通用日志、服务事件 |
| `/var/log/wtmp`、`/var/log/btmp` | 登录成功/失败记录(`last`、`lastb` 查看) |
| `/var/log/cron` | 计划任务执行记录(排查计划任务后门) |
| `/var/log/nginx/access.log`、`error.log` | Web 访问与错误 |

**常用命令**:
```bash
# 查看 SSH 登录失败前 N 条(爆破排查)
grep "Failed password" /var/log/secure | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head
# 查看成功登录
grep "Accepted" /var/log/secure | tail -50
# 查看 sudo 使用
grep sudo /var/log/secure | tail -50
```

**3. Web 访问日志**:源 IP、请求方法、URI、状态码、UA、Referer、响应大小。重点检索:`?` 参数带命令特征、上传请求、敏感路径(`/admin`、`/upload`)、异常状态码(200 后跟 500 的利用尝试)。

**4. 防火墙/边界日志**:NAT 会话、源目 IP/端口、策略命中。用于确认外联(数据外传、C2 通信)与攻击来源。

**5. 其他**:EDR 遥测(进程树、文件事件)、DNS 日志(恶意域名解析)、邮件网关日志(钓鱼入口)、数据库审计日志(SQL 注入)。

## 四、内存取证入门(Memory Forensics)

内存取证用于还原运行中的进程、网络连接、恶意代码,适合无文件攻击、内存马、加密流量场景。

**取证步骤**:

1. **内存转储**:
   - Windows:`DumpIt`、`Magnet RAM Capture`、`winpmem`
   - Linux:`/proc/kcore`(需 root)、`LiME` 内核模块
   - VMware:直接取 `.vmem` 文件
2. **内存分析(Volatility)**:
   ```bash
   # 查看镜像信息(确定 profile)
   vol.py -f memory.dmp imageinfo
   # 列出进程(比对基线,找隐藏/异常进程)
   vol.py -f memory.dmp --profile=Win10x64 pslist
   vol.py -f memory.dmp --profile=Win10x64 psscan   # 查找隐藏进程
   # 列出网络连接
   vol.py -f memory.dmp --profile=Win10x64 netscan
   # 转储进程内存,提取恶意代码
   vol.py -f memory.dmp --profile=Win10x64 memdump -p <PID> -D ./dump/
   # 提取命令行
   vol.py -f memory.dmp --profile=Win10x64 cmdline
   # 查看注入(恶意代码常藏于注入区)
   vol.py -f memory.dmp --profile=Win10x64 malfind
   ```
3. **分析要点**:异常进程(无路径/随机名)、进程注入、网络连接(外联 IP/端口)、加载的 DLL/模块、MZ 头部可疑内存块。

**工具**:Volatility 2/3、MemProcFS、Dumplt、Redline(免费内存分析)。

## 五、磁盘取证入门(Disk Forensics)

磁盘取证用于恢复被删除文件、还原文件操作、提取历史痕迹。

1. **镜像**:用 `dd`(Linux)、FTK Imager(Windows,支持只读打开)、Guymager 制作原始镜像(RAW)或 E01 格式;对原始盘先做哈希校验
   ```bash
   dd if=/dev/sda of=/evidence/sda.img bs=4M status=progress
   sha256sum /evidence/sda.img
   ```
2. **文件系统分析**:Autopsy、The Sleuth Kit(tsk)、X-Ways;查看删除文件、文件元数据(MFT 记录、inode)
3. **文件恢复**:`testdisk`、`photorec`、`extundelete`、R-Studio(Windows);恢复被删除的恶意样本与文档
4. **分析要点**:浏览器历史(下载来源)、最近打开文件、USB 使用记录(Windows `Setupapi`/`Amcache`)、回收站、临时文件、未分配空间残留

## 六、日志分析定位攻击链的方法

攻击链(Intrusion Kill Chain)还原按"入口 → 立足 → 提权 → 横向 → 外传"展开:

1. **找入口**:Web 日志/WAF 日志找漏洞利用(上传、SQL 注入、命令执行);邮件日志找钓鱼;VPN/防火墙日志找弱口令登录
2. **找立足点**:登录日志找首次成功登录(4624 中异常 IP/非工作时间)、进程创建(4688)找投递样本
3. **找提权**:4728/4732 组变更、特权进程、漏洞利用特征
4. **找横向移动**:445/3389 等端口连接、新主机登录事件、共享访问日志
5. **找数据外传**:防火墙/代理日志中大流量外联、DNS 隧道特征、异常协议端口
6. **汇总成链**:把每一步用时间+源+目标+动作串联,验证假设,补齐缺口

**常用分析技巧**:

- 先定**关键时间点**,再双向扩展时间窗
- 用 **IOC(IP、域名、哈希、文件路径)** 反查全部日志
- 日志缺失本身是线索(日志被清、时间窗口断层)
- 大日志用检索工具分批处理,先粗筛再精查

## 七、取证报告要点

取证报告是事件处置与法律程序的交付物,应包含:

1. **案件概述**:事件背景、取证范围、委托方
2. **取证过程**:证据取得时间/方式、工具与版本、哈希值(证明完整性)
3. **证据清单**:介质、文件、日志的清单与存储位置(链式保管记录)
4. **分析发现**:时间线、关键证据(截图/日志摘录)、攻击链还原
5. **结论**:事件定性、影响范围、责任主体(如可确定)
6. **附录**:原始数据索引、工具输出、说明文档

> 报告用词严谨、只陈述证据支持的事实,区分"已证实"与"推断";保留原始证据直至案件完全结案。
