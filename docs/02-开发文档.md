# 灵枢（Lingshu）开发文档

**代码基线：** HEAD `e2353b0`（2026-08-19）
**框架版本：** AgentScope 2.0.6（`requirements.txt` 钉版 `agentscope==2.0.6`）

## 1. 开发环境

| 项 | 要求 |
|---|---|
| 操作系统 | Linux（Windows/macOS 未验证，MCP 路径以 Linux 为准） |
| Python | 3.13+（当前环境 3.13） |
| 依赖 | `pip install -r requirements.txt`（含 agentscope、fastapi、uvicorn、faiss-cpu/milvus-lite、reportlab、mcp 等） |
| 模型 | 至少一个 Provider 的 API Key：`DEEPSEEK_API_KEY`（必配，见 `.env.example`），或 Superadmin 在 Web 端 `模型配置` 注册 |
| 可选外部服务 | Qwen llama.cpp 端点、智谱 GLM、Milvus/Qdrant 远端向量库、AntSword/IDA/GDB MCP |

> 提示：当前 `.venv` 曾缺失 `apscheduler`（agentscope.app 依赖），如遇 `ModuleNotFoundError: No module named 'apscheduler'` 请 `pip install apscheduler==3.11.3`。

## 2. 配置项

### 2.1 环境变量（`.env.example` 为模板）

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` | DeepSeek 凭证 |
| `DEEPSEEK_GATEWAY_MODE` | `base_url`（默认）或 `full_endpoint`（平台将完整 `/responses` 注册为网关） |
| `DEEPSEEK_MODEL_LOW/MIN/MAX` | 三档模型名（默认 flash/flash/pro） |
| `DEEPSEEK_RESPONSES_MODELS` | 走 Responses 协议的模型列表 |
| `ZHIPU_API_KEY` / `ZHIPU_BASE_URL` / `ZHIPU_MODEL_*` / `ZHIPU_NATIVE_TOOLS` | 智谱 GLM |
| `QWEN_API_KEY` / `QWEN_BASE_URL` | Qwen llama.cpp 兼容端点 |
| `LINGSHU_COMMAND_TIMEOUT` | 命令默认超时（秒） |
| （已移除 `LINGSHU_WORKSPACE_MODE`） | 工作区仅支持 Docker 模式（每会话独立容器） |

### 2.2 运行时覆盖（模型注册表）

- `data/model_api_configs.json` 保存 Superadmin 注册的 Provider 配置（API Key 经 Fernet 加密）。
- `model_registry.load_runtime_overrides()` 将启用中的配置覆盖进 `RuntimeConfig`（.env 为兜底）。
- embedding 配置变更会触发 RAG 热重载（`api.py` `_reload_embedding_after_change`）。

## 3. 启动方式

### 3.1 API + 前端

```bash
cd Lingshu
# 生产（含 webui/dist 静态资源）
uvicorn api:app --host 0.0.0.0 --port 8000
# 开发（前端热更新请单独起 Vite dev server）
```

### 3.2 CLI

```bash
python main.py -t <IP/主机名>                          # 默认任务
python main.py -t <IP> -m Pro                          # 选档位（Low/Min/Max）
python main.py -t <IP> -g "获取 Web Shell"             # 指定任务目标
python main.py -t <文件/压缩包>                        # 归档/单文件目标
python main.py -h                                      # 全部参数
```

### 3.3 知识库命令行

```bash
python scripts/knowledge_cli.py build   # 构建/重建 RAG 索引
python scripts/knowledge_cli.py --help  # 检索、状态查看等
```

## 5. Agent 开发规范

### 5.1 新增专家

1. 在 `agent/` 新建工厂函数，如 `def create_xxx_agent(model, *, offloader=None, context_config=None, state=None) -> Agent`：
   - 系统提示词使用中文，明确「角色定位 / 职责边界 / 禁止行为 / 输出格式」；
   - 只注册本角色所需的工具（最小权限）；
   - 无状态修改权——只能返回结果，不接触 `MissionState.transition`。
2. 在 `agent/experts.py` 登记人设名与协作说明（若需要按题型动态人设，加入 `build_expert_assignments`）。
3. 在 `main.py` 的 `run_mission` 中接线：创建 Agent、绑定 `context_config` / `offloader` / `state`（参考 Brain/Attack 的创建方式）。
4. 若该 Agent 需要调度能力，只能通过 Orchestrator 的 `dispatch_*` 工具暴露，不能绕过。
5. 同步更新 `tests/`（参照 `test_agent_context.py` 的接线断言）与文档。

### 5.2 新增工具

1. 在 `Tools/` 实现工具函数，**范围校验在函数内部完成**（授权目标、审批状态、参数合法性）。
2. 用 `AllowedFunctionTool`（`Tools/tooling.py:468`）包装——`check_permissions` 恒 ALLOW，因为校验已在内部完成，绕过 AgentScope 默认 ASK 流程但保留类型/参数 schema。
3. 加入目标 Agent 的 `StrictJSONToolkit`（严格 JSON 校验在前，避免坏参数进入工具）。
4. 涉及命令执行：用 `create_scoped_shell_tool`（自动获得破坏性命令黑名单 + 授权 IP 校验 + 进程组超时清理）。
5. 涉及审计：调用 `state.record(...)` 写入审计链；涉及计划：复用 `Tools/Plan.py` 的 `_commit` 流程。
6. 提供 docstring 中文说明（LLM 依赖它理解工具用法）。

### 5.3 计划工具

- Brain 只能经 `SubmitPlan`（原子批量 4~8 条，id 连续，可 `fallback_on_invalid` 降级）登记计划。
- Orchestrator 用 `AddPlan/UpdatePlan/DeletePlan/ListPlan` 维护；`completed` 必须携带 `evidence` 文本，否则拒绝。
- 每次变更统一走 `_commit`：审计 → `store.checkpoint` → SSE `plan_updated`。

### 5.4 模型 Provider 扩展

1. 在 `LLM/model.py` 实现模型类（参考 `DeepSeekResponsesModel` / `ZhipuResponsesModel` / `Qwen` 工厂），或复用 `OpenAICompatible`（注册 `api_style=responses|chat`）。
2. 在 `config.py` `RuntimeConfig` 增加 provider 的 api_key/base_url/model 读取逻辑。
3. 在 `model_registry.py` 注册默认配置模板（供 Superadmin Web 表单使用）。
4. 在 `api.py` 的模型配置管理端点透出（CRUD + 启用/停用 + embedding 热重载）。

## 6. API 约定

- 基础路径 `/api`，除 `/api/register`、`/api/login`、静态资源外全部经 `JWTAuthMiddleware`（`api.py:965`）校验 Bearer JWT，`auth_epoch` 支持全局失效。
- 会话：`POST /api/session/start` → `GET /api/session/{id}/stream`（SSE）→ `POST /api/session/{id}/message`（审批/steering）→ `POST /api/session/{id}/cancel` / `resume`。
- 知识库：`GET /api/knowledge/status`、`POST /api/knowledge/search`、`POST /api/knowledge/reindex`。
- 模型：`GET /api/model-providers`、Superadmin `GET/POST/PUT/DELETE /api/superadmin/model-configs`。
- 文件：`GET /api/session/{id}/report`（PDF）、`/report/markdown`、`/jsonl`（完整导出）、`/messages`（分页）。
- 兼容层：`/api/mission/*` deprecated 端点代理到新会话端点（`api.py:2276-2311`）。

## 7. 事件协议（SSE）

| 事件类型 | 说明 |
|---|---|
| `message_delta` | 消息增量（字符级，前端节流合并渲染） |
| `message_complete` / `message_meta` | 消息完成与元数据 |
| `tool_start` / `tool_end` | 工具调用与结果 |
| `thinking_delta` | 推理过程 |
| `phase_changed` | 状态机迁移 |
| `plan_updated` | 计划全量快照 + 当前 phase |
| `approval_required` / `approval_resolved` | 审批请求/结果 |
| `session_status` | 会话状态（streaming/idle/terminal/cancelled） |
| `report_ready` | 报告生成完成 |

- 断线重连：客户端携带 `after_seq` / snapshot 恢复，未消费事件补齐。
- 持久化：`_persistence_worker` 批量异步落库，`BEGIN IMMEDIATE` + `MAX(seq)+1` 保证序号原子性。
