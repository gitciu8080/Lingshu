## 快速导读

- **只想了解一句话定位**：灵枢是一个以「唯一状态决策者 + 证据驱动 + 人工审批闸门」为核心的多智能体授权渗透测试框架，用状态机把 LLM 的"自由发挥"锁进可审计、可恢复、防幻觉的执行轨道。
- **想理解 Agent 怎么协作**：读 01 的架构图与 02 的协作链小节（Orchestrator 的 `dispatch_*` 是唯一入口）。
- **想知道"为什么不会编造成功结果"**：读 03，从威胁模型看七层防线。
- **想抄工具/技能清单**：直接翻 04 的 TOOLS 与 SKILLS 两节。

## 与 `docs/` 已有文档的关系

仓库根目录 `docs/` 下已存在三份材料：

- `docs/Lingshu项目汇报与介绍.md` —— 汇报/介绍型叙述；
- `docs/专题/大模型幻觉抑制技术方案.md` —— 幻觉抑制方案的设计论述（章节化、偏方案论证）；
- `docs/专题/核心技术特点.md` —— 核心技术特点的概述。

本 `ds-docs/` 文档集与之**互补而非重复**：定位为深度技术参考，正文以**代码位置（`file:line`）实证**为纲，每一处机制都能在仓库中找到落点；概念性论述（如威胁模型论证、设计动机）可交叉引用 `docs/专题/` 两篇文档。二者口径以代码为准。

## 引用规范（维护约定）

- 所有 `file:line` 引用以本仓库当前代码为准；若代码迁移导致行号漂移，请以符号名为准回查（如 `_ApprovalBroker.feed`）。
- Mermaid 图统一使用 `mermaid` 代码块，修改后请保持语法可解析。
- 新增 Agent / 工具时，同步更新 02（Agent 清单表）与 04（TOOLS 清单表）。
