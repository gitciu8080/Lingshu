# 灵枢（LingShu）源码部署手册

> 灵枢 —— 基于 AgentScope 2.x 的多智能体授权安全测试系统。
> 本文面向**全新 Ubuntu / Debian / Kali 服务器**，从零源码部署。
> 如需一键安装，可直接运行仓库内的 `scripts/install.sh`（见 [第 3 节](#3-快速开始一键部署)）。

---

## 1. 系统组成

| 组件 | 形态 | 说明 |
|---|---|---|
| CLI 任务入口 | `main.py` | 单次授权测试任务：`python main.py -t <目标>` |
| Web API 服务 | `api.py` | FastAPI + uvicorn，监听 `0.0.0.0:8080`，托管前端与全部 REST/SSE 接口 |
| Web 前端 | `webui/`（React 19 + Vite 7） | 新版 SPA，构建产物 `webui/dist/` 由 API 托管；未构建时 API 自动回退 |
| 旧版静态前端 | `frontend/` | 纯静态 `index.html + JS`，免构建，开箱即用 |
| 会话存储 | `data/users.db` | SQLite（用户 / sessions / session_messages / 审批快照等），**首次启动自动建表** |
| 任务持久化 | `.TaskMemory/` | 审计链、作战计划、RAG 知识库（`.TaskMemory/rag/`） |
| 长期记忆 | `.LongMemory/` | 成功攻击链经验（`agentic_memory.json`） |
| 报告与工作目录 | `.Reports/`、`WorkDir/` | PDF 报告输出；任务工作区（自动创建） |
| AntSword MCP | `Tools/AntSword-Loader-*` | 内置 Electron 客户端，API 启动时自动拉起，SSE 端口 `30080`（无桌面走 `xvfb-run`） |
| GDB MCP（可选） | `gdb-multi-mcp` | Reverse/Pwn 动态调试，需 `uv` 安装固定提交版本 |

## 2. 环境要求与前置检查

### 2.1 操作系统

- Ubuntu 22.04 / 24.04、Debian 12+、Kali Linux（推荐，自带 nmap/whatweb 等安全工具）
- 需 `root` 权限（或具备 `sudo`）执行系统依赖安装

### 2.2 运行时要求

| 运行时 | 最低版本 | 用途 |
|---|---|---|
| Python | **3.11+**（推荐 3.13） | 全部后端逻辑 |
| Node.js | **20.19+ 或 22.12+**（Vite 7 要求） | 仅构建 React 前端 `webui/` |
| pnpm | 10.x（仓库锁定 10.14.0） | 前端依赖管理 |
| uv（可选） | 最新 | 安装 `gdb-multi-mcp` |
| git | 任意 | 拉取源码 |

> 仅使用 CLI 或旧版静态前端时，**Node/pnpm 可不安装**（跳过第 4.4 节即可）。

### 2.3 网络与磁盘

- 出网能力：`apt` 软件源、PyPI、npm registry（`registry.npmjs.org` 或镜像）、GitHub（`gdb-multi-mcp` 安装）
- 模型 API 出网：DeepSeek `https://api.deepseek.com`（或内网 Qwen 端点）
- 磁盘空间：建议 **≥ 5 GB**（Python 依赖含 numpy/opencv/onnxruntime/pwntools 等较大包 + 前端依赖 + RAG 向量库）

### 2.4 前置检查命令

```bash
# 确认发行版
cat /etc/os-release

# 确认 Python 版本（需 3.11+）
python3 --version

# 确认 Node / pnpm（如需构建新版前端）
node --version
corepack --version || npm --version

# 确认 sudo 可用
sudo -v

# 磁盘空间
df -h /var /opt /home
```

## 3. 快速开始（一键部署）

```bash
# 1) 获取源码
git clone <你的仓库地址> Lingshu && cd Lingshu

# 2) 一键部署（安装系统依赖 + Python 依赖 + 前端构建 + 生成 .env）
chmod +x scripts/install.sh
sudo ./scripts/install.sh

# 3) 编辑 .env 填入模型密钥
vim .env
#    必填：DEEPSEEK_API_KEY=sk-xxxx（或改用 Qwen 端点）

# 4) 启动 Web 控制台
.venv/bin/python api.py
#    浏览器访问 http://<服务器IP>:8080
```

`install.sh` 支持参数（详见 [第 8 节](#8-一键脚本-installsh-说明)）：

```bash
sudo ./scripts/install.sh --skip-webui      # 不构建 React 前端（用旧版静态前端）
sudo ./scripts/install.sh --with-systemd    # 同时安装 systemd 服务并开机自启
sudo ./scripts/install.sh --dry-run         # 只打印将要执行的步骤，不实际安装
```

## 4. 完整部署步骤

### 4.1 系统依赖安装

```bash
sudo apt update
sudo apt install -y \
  python3 python3-venv python3-pip \
  git curl \
  tesseract-ocr tesseract-ocr-eng tesseract-ocr-chi-sim \
  gdb xvfb
```

逐项说明：

- `python3-venv` / `python3-pip`：创建虚拟环境与安装 Python 依赖（Debian 系默认不带 venv）
- `tesseract-ocr` 及语言包：`ocr_image` 工具依赖；**不装也能启动**，但调用时工具会返回明确的缺失提示
- `gdb`：Reverse/Pwn 动态调试（配合 `gdb-multi-mcp`）；仅做 Web/静态分析可省略
- `xvfb`：无桌面环境下托管 AntSword（Electron）虚拟显示；有图形桌面或禁用 AntSword 时可省略
- `git`、`curl`：拉取源码与连通性排查

> 若网络较慢，可将 pip/npm 切换为国内镜像（见 [第 7 节 FAQ](#7-常见问题-faq)）。

### 4.2 获取源码

```bash
git clone <你的仓库地址> Lingshu
cd Lingshu
```

> 仓库不含 Dockerfile，当前为纯源码部署；如需容器化可自行封装（见第 7 节）。

### 4.3 Python 环境与依赖

```bash
# 创建虚拟环境（放在项目根目录，命名 .venv）
python3 -m venv .venv

# 安装依赖（约 300+ 个包，耗时数分钟）
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt

# 验证关键包可导入
.venv/bin/python -c "import agentscope, fastapi, uvicorn; print('deps ok')"
```

注意事项：

- **opencv 双包**：`requirements.txt` 同时锁定 `opencv-python` 与 `opencv-python-headless`，二者互为冲突（安装后者会卸载前者）。若安装过程出现 opencv 相关报错，可临时注释其中一个再装：
  ```bash
  sed -i '/^opencv-python=/d' requirements.txt   # 保留 headless（服务器无 GUI 更合适）
  .venv/bin/pip install -r requirements.txt
  ```
- **onnxruntime / faiss / milvus-lite**：均为预编译 wheel，一般无需编译工具链；若报缺少 C++ 编译器，安装 `build-essential` 后重试。
- 数据库与各数据目录（`data/`、`.TaskMemory/`、`.LongMemory/`、`.Reports/`、`WorkDir/`）**首次启动时自动创建，无需手动初始化**。

### 4.4 前端构建（可选）

`api.py` 默认按以下优先级托管页面：`webui/dist/`（新版 SPA）→ `frontend/`（旧版静态）。

**方案 A：使用旧版静态前端（最快，免构建）**

什么都不用做，`frontend/` 目录已就绪，API 直接托管。

**方案 B：构建新版 React 前端**

```bash
# 启用 corepack 以获取仓库锁定的 pnpm 10.14.0
sudo corepack enable
corepack prepare pnpm@10.14.0 --activate

cd webui
pnpm install
pnpm build        # 产物输出到 webui/dist/
cd ..
```

> 若 `corepack` 不可用，可 `npm install -g pnpm@10.14.0` 替代。构建成功后访问根路径即为新版界面；未构建时 API 自动回退旧版，不会 404 崩溃。

### 4.5 配置 `.env`

```bash
cp .env.example .env
vim .env
```

**必填项（至少配置一个模型提供商）**：

| 变量 | 示例 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | `sk-xxxx` | DeepSeek API 密钥（使用 DeepSeek 时必填） |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | DeepSeek API 地址 |
| `DEEPSEEK_GATEWAY_MODE` | `base_url` | 普通 Base URL 用 `base_url`；完整 `/responses` 网关用 `full_endpoint` |

或改用 Qwen（内网 llama.cpp OpenAI 兼容端点）：

| 变量 | 示例 | 说明 |
|---|---|---|
| `QWEN_API_KEY` | `sk-placeholder` | Qwen 端点密钥 |
| `QWEN_BASE_URL` | `http://<内网IP>:8200/v1` | OpenAI 兼容端点 |
| `QWEN_MODEL` | `.../Qwen3.6-35B-A3B-UD-Q4_K_XL.gguf` | 模型标识（llama.cpp 用 GGUF 路径） |

**强烈建议修改的安全项**：

| 变量 | 默认 | 说明 |
|---|---|---|
| `JWT_SECRET` | 自动生成 | **务必设置固定值**：不设置时每次进程重启 token 都会变，已登录的 Web 会话全部失效 |
| `LINGSHU_USER` / `LINGSHU_PASS` | `lingshu` / `lingshu2026` | 外部靶场平台（NSSCTF/SLAB）默认提交账号，**不是** Web 控制台认证；控制台登录用注册账号（管理员由 `LINGSHU_SUPERADMIN_*` 创建） |
| `LINGSHU_SUPERADMIN_USERNAME` / `LINGSHU_SUPERADMIN_PASSWORD` | `superadmin` / 示例值 | 超级管理员账号；留空则不创建 `/superadmin` |
| `LINGSHU_REGISTRATION_INVITE_CODE` | 示例值 | 公开注册邀请码；留空关闭注册 |

**可选组件**：

| 变量 | 说明 |
|---|---|
| `LINGSHU_EMBEDDING_API_KEY` / `LINGSHU_EMBEDDING_BASE_URL` / `LINGSHU_EMBEDDING_MODEL` | 本地 RAG 知识库 Embedding 端点；不配置则 RAG 检索不可用但主流程正常 |
| `LINGSHU_PDF_FONT_REGULAR` / `LINGSHU_PDF_FONT_BOLD` | PDF 报告中文字体（指向已合法安装的 TTF）；缺省回退内置字体 |
| `LINGSHU_COMMAND_TIMEOUT` | scoped_shell 单条命令超时秒数（默认 300，取值 10–600，超出自动夹取） |
| `LINGSHU_ANTSWORD_AUTOSTART` | `false` 可禁用 AntSword 自动启动 |
| `QWEN_TOOL_CALL_MODE` | Qwen 工具协议：`simple` / `standard` |

### 4.6 数据库与数据目录

首次启动（CLI 或 API）时自动完成：

- `data/users.db`：SQLite 用户与会话库（`auth.init_db()` 导入即建表，`session_store.init_sessions_db()` 建会话表）
- `.TaskMemory/current_mission.json` 与 `.TaskMemory/sessions/*.json`：任务状态与审计链
- `.LongMemory/agentic_memory.json`：长期记忆（保留最近 50 条任务）
- `.Reports/`、`WorkDir/`：报告与任务工作区

> 备份策略：定期备份 `data/users.db` 与 `.TaskMemory/`、`.LongMemory/` 即可完整保留历史会话与经验。

## 5. 启动与验证

### 5.1 CLI 模式（单次任务）

```bash
# 网络目标（默认 DeepSeek Flash）
.venv/bin/python main.py -t 10.0.0.1

# 指定端口与任务目标
.venv/bin/python main.py -t 10.0.0.1:49152 -g "获取 Web Shell"

# 本地 CTF 文件（自动解压 + 分类）
.venv/bin/python main.py -t challenge.zip -g "ROP 二进制利用"

# 指定模型提供商与思考级别
.venv/bin/python main.py -t 10.0.0.1 -p qwen -m Min
```

参数速查：`-t/--target`（必填）、`-g/--goal`、`-p/--provider`、`-m/--model`（Low/Min/Max）、`--qwen-tool-mode`。完整帮助：`.venv/bin/python main.py -h`。

### 5.2 Web API 模式（控制台）

```bash
# 前台启动（Ctrl+C 停止）
.venv/bin/python api.py
# 等价于: .venv/bin/uvicorn api:app --host 0.0.0.0 --port 8080
```

- 监听：`http://0.0.0.0:8080`
- 首次启动会初始化数据库并异步初始化 RAG / AntSword，约需数秒至数十秒

### 5.3 systemd 服务化（生产推荐）

仓库根目录 `LingShu-Agent.service` 为参考单元。一键部署脚本 `--with-systemd` 会自动安装，也可手动执行：

```bash
# 1) 确认单元文件中的路径与你的部署路径一致
#    WorkingDirectory=  项目根目录
#    ExecStart=         <venv>/bin/python <项目根>/api.py
#    User=/Group=       运行用户（建议专用低权限用户，如 kali 或 lingshu）

# 2) 安装并启用
sudo cp LingShu-Agent.service /etc/systemd/system/lingshu-agent.service
sudo systemctl daemon-reload
sudo systemctl enable --now lingshu-agent

# 3) 常用运维命令
sudo systemctl status lingshu-agent        # 状态
sudo journalctl -u lingshu-agent -f        # 实时日志
sudo systemctl restart lingshu-agent       # 重启
```

> 单元已包含 `TimeoutStartSec=180s`（首次 RAG/Milvus 初始化）与 `TimeoutStopSec=90s`（MCP/持久化队列异步收尾），无需额外调整。

### 5.4 验证清单

```bash
# 1) API 存活（应返回版本 JSON）
curl -s http://127.0.0.1:8080/api/version

# 2) 首页可访问（返回 HTML）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/

# 3) AntSword / RAG 状态（以下端点需登录 Bearer Token，未认证返回 401 属正常）
#    curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8080/api/integrations/antsword/status
#    curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8080/api/knowledge/status

# 4) CLI 冒烟：本地授权测试文件跑通全流程（需 .env 已配置密钥）
.venv/bin/python main.py -t /path/to/your-challenge.zip -m Low 2>&1 | tail -20   # 替换为你的本地授权测试文件
```

浏览器访问 `http://<服务器IP>:8080`，在登录页使用注册账号登录（`POST /auth/login` 返回 JWT，后续请求带 `Authorization: Bearer <token>`；管理员由 `LINGSHU_SUPERADMIN_USERNAME/PASSWORD` 首次启动创建），再在 Web 控制台发起一次授权任务完成端到端验证。

## 7. 常见问题 FAQ

**Q1: `pip install -r requirements.txt` 报 opencv 相关冲突/错误？**
`opencv-python` 与 `opencv-python-headless` 共存于清单，二选一即可。服务器无 GUI 建议保留 `headless`：
```bash
sed -i '/^opencv-python=/d' requirements.txt && .venv/bin/pip install -r requirements.txt
```

**Q2: pip 安装很慢或超时？**
改用国内镜像：
```bash
.venv/bin/pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
```

**Q3: npm/pnpm 安装前端依赖慢？**
```bash
pnpm config set registry https://registry.npmmirror.com
```

**Q4: 提示 `tesseract` 未找到 / `ocr_image` 不可用？**
```bash
sudo apt install -y tesseract-ocr tesseract-ocr-eng tesseract-ocr-chi-sim
```

**Q5: `gdb-multi-mcp` 启动失败？**
确认已装 `uv` 且 `.mcp.json` 中的固定提交可访问（首次需联网拉取 GitHub）；`uvx --offline` 依赖本地缓存，首次请去掉 `--offline` 预热：
```bash
uvx --from git+https://github.com/Mistyovo/gdb-multi-mcp@6e8048b8e933bbbae79b6da16fe69249f56fe30d gdb-multi-mcp --version
```

**Q6: 8080 端口被占用？**
```bash
ss -tlnp | grep 8080
```
API 端口在 `api.py` 底部 `uvicorn.run("api:app", host="0.0.0.0", port=8080)` 修改；systemd 模式改单元文件 `ExecStart` 后 `daemon-reload && restart`。

**Q7: 登录后重启服务就掉线？**
`.env` 未设置 `JWT_SECRET`，每次进程启动重新随机生成导致旧 token 失效。在 `.env` 固定一个长随机值：
```bash
echo "JWT_SECRET=$(openssl rand -hex 32)" >> .env
```

**Q8: Web 页面是旧版（没有新界面）？**
`webui/dist/` 未构建。执行第 4.4 节方案 B 后重启 `api.py`。

**Q9: 前端访问返回 404？**
确认 API 已启动且 `frontend/index.html`（旧版）或 `webui/dist/index.html`（新版）存在；SPA 路由由 `/` 兜底处理。

**Q10: 部署到外网安全吗？**
本系统执行授权安全测试并内置命令执行能力，**切勿直接暴露公网**。必须：设置固定 `JWT_SECRET`、修改 `LINGSHU_SUPERADMIN_PASSWORD`、设置高强度注册邀请码，并限制来源 IP（防火墙/反向代理），仅对授权测试环境开放。

**Q11: 想用 Docker 部署？**
仓库暂无 Dockerfile。可自行封装：基础镜像 `python:3.13-slim` + 安装上述系统依赖 + `pip install -r requirements.txt` + 构建前端，`CMD` 启动 `uvicorn api:app --host 0.0.0.0 --port 8080`；注意挂载 `data/`、`.TaskMemory/`、`.LongMemory/`、`.Reports/`、`WorkDir/` 卷。

**Q12: 首次启动很慢？**
首次启动需初始化数据库、RAG 向量库并预热 AntSword，属正常现象；systemd 已配置 `TimeoutStartSec=180s`。

## 8. 一键脚本 `install.sh` 说明

```text
用法: sudo ./scripts/install.sh [选项]

选项:
  --skip-webui    跳过 React 前端构建（仅使用旧版静态前端）
  --with-systemd  安装 systemd 服务 lingshu-agent 并开机自启
  --dry-run       仅打印将执行的步骤，不实际安装
  -h, --help      显示帮助
```

行为约定：

1. **幂等可重跑**：已安装的 apt 包 / Python 依赖 / 已存在的 `.env` 不会重复覆盖；失败后重跑即可续传。
2. **`.env` 保护**：仅当 `.env` 不存在时从 `.env.example` 生成并提示填写密钥；已存在则跳过（不会覆盖你的配置）。
3. **前端构建**：默认尝试 `pnpm` 构建 `webui/`；构建失败或跳过时**不影响 API 启动**（回退旧版静态前端，可稍后重跑脚本或手动构建）。
4. **systemd 安装**（`--with-systemd`）：自动生成 `/etc/systemd/system/lingshu-agent.service`（内容与仓库 `LingShu-Agent.service` 一致：运行用户取 sudo 调用者、路径替换为实际部署路径）并 `enable --now`。
5. **退出码**：任意关键步骤失败即退出非零；失败命令与时间戳由 `trap ERR` 记录到 `/var/log/lingshu-install.log`。
