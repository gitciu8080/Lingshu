# 灵枢（Lingshu）技术报告

**代码基线：** HEAD `e2353b0`（2026-08-19）
**编制日期：** 2026-08-20
**运行数据统计区间：** 2026-08-03 ~ 2026-08-17（`docs/session_statistics.md`，439 会话）

## 摘要

灵枢是基于 AgentScope 2.x 的多智能体授权安全测试系统，以「唯一状态决策者 + 证据驱动 + 人工审批闸门」为核心治理模型，用状态机把 LLM 的开放式决策锁进可审计、可恢复、防幻觉的执行轨道。系统已完成 Brain→Orchestrator→Recon/Attack/Analysis/Reserve→Summary 的完整协作闭环、三层记忆体系、多 Provider 模型层、MCP 工具生态与 WebUI，并经过 164 项自动化测试验证（157 通过，通过率 95.7%）。

## 1. 技术成果

### 1.1 多专家协作

- 战略/战术/执行三层分离：Brain 只做计划、Orchestrator 唯一调度、Recon/Attack 等只执行并返回证据，杜绝横向事实污染与状态竞态。
- 专家人设按题型动态分配（`agent/experts.py`），Attack 内嵌 Analysis 研判 + CVE 情报 + scoped_shell，形成「侦察→研判→验证→利用」证据闭环。
- 嵌套调用保证单调度者语义与审计顺序确定性，ReAct 迭代预算按题型差异化分配。

### 1.2 授权安全控制

- 默认授权：目标解析时把「用户声明的目标」自动纳入 `ScopeRegistry`；网络命令必须显式包含授权 IP。
- 双重审批闸门：`request_exploitation_approval`（首次进入 EXPLOITATION 前）+ `dispatch_attack` 兜底 + AntSword 可写工具逐次联动；审批状态持久化，崩溃恢复不重复询问。
- 破坏性命令黑名单 + 进程组超时清理 + 命令输出落盘 artifacts（v2 流式）。

### 1.3 过程可审计

- SHA-256 前向哈希审计链（seq/previous_hash/event_hash），篡改即断链，可整体校验。
- 状态机合法迁移白名单、计划 completed 证据强制、工具 JSON 校验失败记录参数哈希后安全收尾。
- 全量事件持久化（消息/推理/工具/审批/计划），支持 JSONL 原样导出，满足竞赛「完整、原样、可对应、含过程」的提交要求。

### 1.4 知识与报告

- 三层记忆：`.RAG` 知识库（11 大类静态事实 + 冷记忆卡片）+ `.LongMemory` 长期经验（脱敏、热记忆 ≤50 条、溢出归档回知识库闭环）+ 会话短期记忆（`SUMMARY_SCHEMA` 强制保留恢复语义）。
- 报告：Summary Agent 生成结构化 Markdown（CTF WRITEUP 规范：忠实性/完整性/规范性约束）+ PDF + JSONL 导出 + Markdown 下载。
- 在线判题集成：NSSCTF `submit_nss_flag` 与 Slab `submit_slab_flag`，Flag 正确由平台返回判定，客观化成功口径。

### 1.5 模型与平台

- 统一工厂支持 DeepSeek（Responses + 网关模式）、智谱 GLM、Qwen（llama.cpp）、任意 OpenAI 兼容 Provider，三档（Low/Min/Max）模型映射。
- AgentScope Service 封装（`integrations/agentscope_service/`）把整个任务封装为单个 AgentScope Agent，事件翻译、角色历史镜像、审批透传，可接入 AgentScope 账号面板。
- 前端 Vite+React 主界面 + 原生 JS 兜底；Workspace v2 内容寻址隔离，防路径逃逸与跨会话串扰。

## 3. 系统优点

1. **可信执行轨道**：状态机 + 审计链 + 证据强制把 LLM 的「自由发挥」限制为可验证动作序列，伪造成功/越权推进在机制上不可行。
2. **人机协同闸门**：攻击动作人工批准 + 三态决策（批准/补充侦察/拒绝）+ 崩溃不重复询问，兼顾效率与安全。
3. **记忆分层且防污染**：知识库只读注入带来源标注、长期记忆脱敏归档、短期记忆压缩保留恢复语义，三层职责清晰并形成「经验→知识」闭环。
4. **模型中立**：统一工厂 + 注册表 + 网关模式，DeepSeek/GLM/Qwen/自定义 Provider 可切换，三档档位适配成本/质量。
5. **可恢复可导出**：检查点 + Workspace 隔离 + JSONL 完整导出，任务中断可恢复、过程可复查。

## 4. 当前问题与风险

1. **测试契约漂移**：`test_qwen_contract`（4 用例）与 `test_attack_antsword_mcp`（1 用例）未随实现更新（`Parameters.thinking_enable` 新契约、`client.is_stateful` 新属性），存在「测试沉默」风险——错误可能被误认为通过。
2. **环境依赖不一致**：`.venv` 与 `requirements.txt` 漂移（曾缺 `apscheduler`，fastapi 实际 0.115.0 vs 声明 0.141.1），导致 `agentscope.app` 导入链在部分环境失败，`test_agentscope_service` / `test_web_stream_performance` 无法运行。
3. **active 会话残留**：45 个 active（10.3%）未达终态，可能与取消/中断路径或进程组清理时序有关，需核查 `cancel_session` 双层取消与 `ProcessTracker` 收尾。
4. **分类器 unknown 占比高**：34.4% 题型判定 unknown，影响 Brain 计划与专家人设的针对性；`reclassify` 依赖 Recon 证据，建议扩充关键字/扩展名信号库。
5. **qwen 成功率偏低**：已终结成功率 29.8%，或与 llama.cpp 端点可用性/思考模式配置相关，建议归因分析（区分模型能力 vs 端点故障）。
6. **统计口径**：session_stats 统计截至 08-17，未覆盖最新 GLM/slab 能力；`success=NULL`（active/cancelled）占比 44%，「成功率(全部)」口径需谨慎引用。

## 5. 性能与安全建议

### 5.1 性能

- 长会话上下文：依赖 `ContextConfig(trigger_ratio=0.75)` 触发压缩，建议对 >500 消息会话监控压缩频率与质量；`SUMMARY_SCHEMA` 字段缺一即压缩失败，需保留兜底。
- 持久化：`_persistence_worker` 批量落库已缓解逐条写放大，建议对高并发场景评估 SQLite WAL 与连接池。
- RAG 检索：多库并发检索（`_search_across`）建议增加 top_k 上限与 score 阈值，避免低频任务注入过多噪音。

### 5.2 安全

- **审批语义**：非肯定答复一律视为拒绝（安全默认）已实现；建议补充「审批请求超时自动拒绝」策略，防止挂起会话长期滞留 active。
- **MCP 最小化**：AntSword 可写工具集需随权限模型演进持续收敛；IDA/GDB 用只读工具集（无 patch）的正确性建议纳入 CI 断言（已有 `test_gdb_mcp_config.py`）。
- **审计链完整性**：`verify_audit_chain` 已支持整体校验，建议在任务终态自动执行一次校验并记入结果，防静默篡改。
- **密钥管理**：模型 API Key 经 Fernet 加密存储，建议评估 KMS 轮换与审计（`data/model_api_configs.json` 权限收紧为 600）。
- **供应链**：`requirements.txt` 286 项含大量逆向/取证工具链依赖，建议锁定哈希（`pip freeze` + hashes）并在 CI 做依赖审计。

## 6. 结论

灵枢已在架构层面完成从「多智能体编排」到「可信安全执行框架」的跃迁：状态机、审计链、审批闸门、证据强制、严格参数校验共同构成多层防幻觉防线，运行数据显示已终结任务成功率 71.8%（DeepSeek 档位达 85.2%），工具调用闭环运转正常。当前主要风险集中在测试契约维护、环境依赖一致性与 active 残留治理，属工程化问题而非架构缺陷。建议按第 4/5 章清单逐项治理，并补充 GLM/slab/Workspace v2 时代的运行统计，形成持续演进的技术基线。
