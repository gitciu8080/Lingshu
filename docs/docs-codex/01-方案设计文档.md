# 灵枢·利刃Agent 方案设计文档

**项目类型：** 面向授权安全测试的多专家协作智能体  
**文档版本：** 1.0  
**编制日期：** 2026-08-17  
**当前代码基线：** 分支 `2026-08-12`，HEAD `02419d3`

## 1. 项目概述

灵枢·利刃Agent 是一个面向授权安全测试场景的多智能体协作系统。系统以任务目标、授权范围和可审计性为核心约束，通过 Brain、Orchestrator、Recon、Analysis、Attack、Reserve、Summary 等专家角色完成从任务理解、侦察、研判、人工审批、验证到报告生成的闭环。

系统不以“自动攻击”为设计目标，而是以授权边界、最小影响、人工闸门、证据留存和可恢复执行为基本原则。所有网络与文件操作必须在授权目标范围内执行，攻击阶段必须经过人工批准。

## 2. 设计目标

### 2.1 功能目标

1. 支持 CLI 与 React/Vite WebUI 两种使用方式。
2. 支持 DeepSeek、Qwen 及 OpenAI 兼容协议等模型配置。
3. 支持 `.RAG` Markdown 知识库检索、长期记忆和 Workspace 会话隔离。
4. 支持 AntSword、IDA、GDB 等 MCP 工具按专家角色接入。
5. 支持流式消息、推理过程、工具参数、工具输出和审批事件持久化。
6. 任务结束后生成 Markdown 总结和中文 PDF 报告，并支持完整 JSONL 会话导出。

### 2.2 非功能目标

- **安全性：** 默认授权、目标范围校验、破坏性命令拦截、攻击阶段人工审批。
- **可审计性：** 任务状态、阶段变化、计划、工具调用和结果均形成事件记录。
- **可恢复性：** 使用 MissionState、Workspace 和检查点支持崩溃恢复与安全停止。
- **可扩展性：** Agent、工具、模型 Provider、知识库和报告模板均可独立扩展。
- **可用性：** SSE 实时推送、消息分页、工具历史滚动、自动滚动开关和移动端适配。

## 3. 总体架构

```text
用户 / WebUI / CLI
        │
        ▼
FastAPI API 层（认证、会话、SSE、审批、文件、报告）
        │
        ▼
run_mission / MissionState / MissionStore
        │
        ├── Brain：战略理解与计划
        ├── Orchestrator：唯一状态调度者
        │     ├── Recon：授权侦察
        │     ├── Analysis：漏洞研判
        │     ├── Attack：验证与利用
        │     └── Reserve：逆向分析
        ├── Summary：总结与 PDF
        ├── RAG / AgenticMemory：知识与经验
        └── MCP：AntSword、IDA、GDB 等工具服务
```

### 3.1 状态机

```text
PLANNING → RECON → ANALYSIS → EXPLOITATION
                         ↓           ↓
                      FAILED   POST_EXPLOITATION
                                      ↓
                                  COMPLETED
```

状态迁移由 Orchestrator 统一执行。其他 Agent 只能产生结果，不能直接修改任务终态。

### 3.2 专家职责

| 专家 | 职责 | 执行权限 |
|---|---|---|
| Brain | 分析目标、任务目标和历史经验，形成战略计划 | 计划登记 |
| Orchestrator | 调度专家、推进阶段、处理审批和终态 | 状态与计划管理 |
| Recon | 端口、服务、路由、指纹和攻击面收集 | 授权范围内侦察 |
| Analysis | 根据证据研判漏洞和攻击路径 | 纯推理，原则上不执行命令 |
| Attack | 执行低影响验证、调用 CVE/命令/WebShell 工具 | 受审批和范围约束 |
| Reserve | IDA/GDB 二进制逆向和动态分析 | MCP 会话受控执行 |
| Summary | 汇总全过程并生成报告 | 只读会话与任务状态 |

## 4. 安全设计

### 4.1 授权范围

- 用户输入的 IP、域名、端口和上传文件在任务创建时规范化。
- `ScopeRegistry` 保存目标范围快照，网络工具必须显式匹配授权目标。
- `scoped_shell` 拦截未授权目标和高危破坏性命令。
- 上传文件使用会话级 Workspace 隔离，避免不同任务之间直接共享路径。

### 4.2 人工审批

首次进入 EXPLOITATION 前必须请求人工审批，审批事件包含侦察摘要、作战计划、理由和候选方案。批准状态写入 MissionState，审批结果进入消息和审计链。拒绝后只能补充侦察、调整方案或安全结束。

### 4.3 数据审计

SQLite 保存会话、消息、工具调用、计划和流式快照；MissionState 保存结构化任务状态及审计事件。JSONL 导出保留结构化字段和原始数据库行，满足竞赛对“完整、原样、可对应、含过程”的提交要求。

### 4.4 模型与工具隔离

模型调用由统一配置工厂创建。工具通过 `AllowedFunctionTool` 注册，并在工具函数内部进行目标范围和审批检查。AntSword、IDA、GDB MCP 按专家绑定，避免无关专家获得全部工具。

## 5. 数据流设计

1. 用户登录后创建会话。
2. API 创建 SessionContext、Workspace 和 MissionState。
3. Brain 形成计划并登记 Plan 项。
4. Orchestrator 调度 Recon、Analysis、Attack 或 Reserve。
5. 事件通过回调进入 SSE，同时异步写入 `session_messages`。
6. 用户输入通过队列进入任务，必要时中断当前 Agent 并重新规划。
7. 任务进入终态后，Summary Agent 读取结构化状态和完整事件转录。
8. 系统生成 PDF、报告事件和 JSONL 导出内容。

## 6. 部署形态

- Python 3.13+，推荐使用 Miniconda `agentscope` 环境。
- FastAPI 负责 API 和静态前端服务。
- React/Vite 负责 WebUI 开发和构建。
- Milvus/嵌入模型为可选知识库运行时。
- MCP 服务按需启动，AntSword 服务可由 API 生命周期托管。

## 7. 设计取舍

- 使用 SSE 而非 WebSocket，降低前端接入复杂度并适配已有事件模型。
- 使用 SQLite 作为本地审计存储，适合单机部署；高并发生产环境可迁移至 PostgreSQL。
- 任务状态与消息分离保存，既支持前端分页，也支持完整原始导出。
- Summary Agent 失败时保留结构化降级摘要，避免任务终态丢失。
