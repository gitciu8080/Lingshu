# 灵枢·利刃Agent 开发文档

**项目类型：** 面向授权安全测试的多专家协作智能体  
**适用分支：** `2026-08-12`  
**当前基线：** `02419d3`

## 1. 开发环境

| 项目 | 要求 |
|---|---|
| Python | 3.13 或更高版本 |
| Node.js | 支持 Vite 7 的版本 |
| 包管理 | pnpm 或 npm |
| AgentScope | 项目代码按 AgentScope 2.x 设计，运行环境以锁定依赖为准 |
| 数据库 | SQLite；知识库可选 Milvus |
| 模型 | DeepSeek、Qwen 或 OpenAI 兼容 API |

推荐环境：

```bash
conda activate agentscope
pip install -r requirements.txt
cd webui
npm install
```

## 2. 配置项

核心配置位于 `.env`，可参考 `.env.example`。至少需要配置模型 API Key、JWT 密钥和管理员密码。生产环境不得使用示例密钥、默认密码或公开注册配置。

注册安全配置：

```env
LINGSHU_REGISTRATION_INVITE_CODE=高强度随机邀请码
```

该配置为空时关闭公开注册。注册密码策略由认证模块校验；提交前应确保策略与产品要求保持一致。

## 3. 启动方式

### 3.1 API 与前端

```bash
python api.py
```

API 会加载 `webui/dist` 中的生产构建。开发阶段：

```bash
cd webui
npm run dev
```

### 3.2 CLI

```bash
python main.py -t <授权目标>
python main.py -t <授权目标> -m Max
python main.py -t <授权目标> -g "任务目标"
```

## 5. Agent 开发规范

### 5.1 新增专家

1. 在 `agent/` 新建模块和创建函数。
2. 明确输入 Msg、工具集合、模型配置和上下文策略。
3. 通过 `stream_agent_reply` 统一处理流式输出和中断。
4. 通过 `event_callback` 推送文本、推理、工具和状态事件。
5. 在 Orchestrator 中以受控工具方式调度。
6. 将专家名称、专业领域和失败路径加入测试文档。

### 5.2 新增工具

- 使用 `AllowedFunctionTool` 注册。
- 工具函数内部必须再次校验目标范围和审批状态。
- 工具输出应返回可序列化文本或结构化对象。
- 不得把未授权目标、凭据、破坏性命令或任意文件路径交给工具。
- 工具调用必须通过事件回调记录名称、参数、开始和结束结果。

### 5.3 计划工具

计划项由 `Tools/Plan.py` 管理。新增、更新、删除和完成均应持久化并推送 `plan_updated`。标记 completed 时必须提供 evidence，防止模型伪造完成状态。

## 6. API 约定

主要接口包括：

| 接口 | 作用 |
|---|---|
| `POST /auth/login` | 登录并返回 JWT |
| `POST /auth/register` | 使用邀请码注册 |
| `GET /api/sessions` | 分页读取当前用户会话 |
| `POST /api/session/start` | 创建任务 |
| `GET /api/session/{id}/stream` | SSE 事件流 |
| `GET /api/session/{id}/messages` | 分页历史消息 |
| `GET /api/session/{id}/jsonl` | 导出完整原始会话 |
| `GET /api/session/{id}/report` | 下载 PDF 报告 |
| `POST /api/session/{id}/message` | 发送情报或审批消息 |
| `POST /api/session/{id}/cancel` | 请求取消任务 |
| `GET /api/knowledge/status` | 知识库状态 |
| `POST /api/knowledge/search` | 知识库检索 |

除登录、注册、静态资源和版本信息外，API 默认要求 Bearer Token。会话和 Workspace 接口必须校验用户归属。

## 7. 事件协议

常用事件：

```text
mission_start / mission_end
phase_change
text_start / text_end
thinking_start / thinking_end
tool_call_start / tool_call_end
approval_required / approval_resolved
plan_updated
expert_joined
flag_found
report_ready
```

结束事件保存完整正文，工具结束事件保存完整参数和输出。前端刷新时通过数据库补偿历史事件，SSE 只负责实时传输。

## 8. 数据库约定

`data/users.db` 包含用户、会话、消息、流式快照和模型配置表。数据库属于运行数据，不应提交真实用户、Token、Flag、目标地址或 API Key。提交时使用空白结构示例文件或脱敏数据库。

## 9. 前端开发

```bash
cd webui
npm run build
```

前端使用 React 状态管理会话、事件和懒加载消息；CSS 同时维护亮色、暗色和液态玻璃主题。液态玻璃主题修改必须经过视觉回归检查，避免改变滤镜、折射和性能降级策略。

## 10. 提交规范

- 提交前执行 Python 编译、TypeScript 编译和 Vite 构建。
- 不提交运行数据库、密钥、上传文件、`.TaskMemory` 运行产物和真实报告。
- Commit message 使用中文，说明功能、修复范围和验证结果。
- 涉及安全策略时补充威胁模型、误报/拒绝路径和回滚方式。
