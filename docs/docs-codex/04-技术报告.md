# 灵枢·利刃Agent 技术报告

**项目名称：** 灵枢·利刃Agent  
**项目类型：** 面向授权安全测试的多专家协作智能体  
**报告日期：** 2026-08-17  
**代码版本：** `2026-08-12` / `02419d3`

## 摘要

灵枢·利刃Agent 基于 AgentScope 2.x、FastAPI、React/Vite 和 SQLite 构建，面向授权安全测试提供多专家协作、人工审批、工具编排、知识库检索、长期记忆、Workspace 隔离、PDF 报告和原始 JSONL 会话导出能力。

系统当前数据库共记录 439 个会话、106,434 条会话消息和 22,494 次工具调用开始事件。已完成会话 177 个，失败 130 个，取消 87 个，仍处于 active 的会话 45 个。统计表明系统已经具备较完整的真实运行数据和审计链路，但仍需要针对消息配对、活跃任务回收、知识库可用性和高并发场景继续完善。

## 1. 技术成果

### 1.1 多专家协作

以 Brain→Orchestrator→Recon/Analysis/Attack/Reserve→Summary 为主链路。Orchestrator 负责唯一状态迁移和专家调度，减少多个 Agent 同时修改任务状态造成的不一致。

### 1.2 授权安全控制

通过目标规范化、ScopeRegistry、scoped_shell、破坏性命令拦截和攻击阶段人工审批建立多层控制。Attack 的高风险工具和 MCP 操作按审批状态动态放行，避免仅依赖模型提示词。

### 1.3 过程可审计

系统同时保存结构化 MissionState、SQLite 消息、工具调用事件、审批事件、计划清单和 Workspace 引用。JSONL 导出保留用户输入、Agent 输出、推理、工具参数及工具结果，适合竞赛提交和内部复盘。

### 1.4 知识与报告

`.RAG` 目录作为 Markdown 只读语料源，向量库和哈希清单写入 `.TaskMemory/rag`。Summary Agent 在任务终态阶段生成总结，Report 模块使用中文字体生成 PDF。

## 3. 系统优点

1. 任务状态、工具行为和用户消息具备较完整的追踪链路。
2. Agent 与 MCP 的职责边界较清晰，Attack、Reserve 不共享全部工具。
3. 任务取消、流式输出、Summary 收尾和 PDF 生成已经形成独立阶段。
4. React 前端提供消息懒加载、工具历史滚动、自动滚动和多主题适配。
5. 数据库设计支持消息分页，避免每次打开会话加载全部历史。

## 4. 当前问题与风险

### 4.1 认证策略需继续对齐需求

当前最新提交中的密码校验为至少 8 位并要求大小写、数字；如果项目验收要求至少 12 位和特殊字符，应继续调整并补充自动化测试。

### 4.2 数据库与知识库污染风险

运行数据库包含大量任务、工具调用和目标相关记录，不应直接作为 Git 提交内容。`.RAG` 当前存在大量删除状态，需由维护者确认是知识库迁移、清理还是误删。

### 4.3 active 残留

当前有 45 个 active 会话。应增加启动恢复扫描、超时回收和管理员只读监控，区分真实执行中的任务与异常退出产生的残留。

### 4.4 事件一致性

工具开始/结束和推理开始/结束数量不完全一致。应在导出前标记未闭合事件，并在任务 finally 中统一生成补偿结束事件。

## 5. 性能建议

- 对 `session_messages(session_id, seq)` 建立覆盖索引并验证 SQLite 查询计划。
- 将事件持久化队列、SSE 队列和模型输出缓冲设置上限，防止长任务内存增长。
- 将工具结果摘要与原始结果分离，原始结果进入 Workspace，消息只保存引用和摘要。
- 对 Summary Agent 使用固定最大输入和上下文压缩策略。
- 生产环境将 SQLite 迁移至 PostgreSQL，并将 Workspace/报告迁移到对象存储。

## 6. 安全建议

- 关闭默认管理员弱密码，使用环境变量注入强随机密码。
- 默认关闭公开注册，邀请码使用一次性或短期有效机制。
- 对报告、JSONL、Workspace 和会话详情统一执行用户归属校验。
- 继续完善审批者与任务申请者的身份分离。
- 提交前清理数据库、日志、上传文件和知识库中的敏感信息。
- 对模型 API Key 使用密钥管理服务，不在本地配置文件和数据库明文保存。

## 7. 结论

灵枢·利刃Agent 已形成面向授权安全测试的多专家协作基础平台，具备从任务创建、计划调度、授权侦察、人工审批、工具执行、过程审计到总结报告的完整工程链路。当前系统已积累较大规模真实会话数据，下一阶段重点应从“功能闭环”转向“数据质量、权限自动化测试、活跃任务治理、事件一致性和生产部署可靠性”。
