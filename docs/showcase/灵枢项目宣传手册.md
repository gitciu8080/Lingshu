# 灵枢（Lingshu）项目宣传手册

> **定位语**：把大模型从"聊天高手"变成"能打硬仗、敢担责任"的智能体作战团队。
> 本文档用于项目展示、评优汇报、对外宣传与商务路演；所有能力均可演示、所有数字均可查证。

---

## 一、一句话认识灵枢

**灵枢是一套基于多智能体架构的授权安全测试作战平台** —— 它不满足于让 AI"回答你"，而是让一支由 9 大专家角色组成的 AI 团队，自主完成从情报侦察、漏洞研判、攻击验证到结果归档的完整渗透测试流程，**全程状态机管控、人工审批把关、证据链可回放**。

> 如果说单智能体是"一把没有保险的枪"，灵枢就是**一支纪律严明、令行禁止、战果可查的特种作战小队**。

---

## 二、序言：我们在解决什么问题

大模型做安全测试，过去有三座大山：

| 大山 | 表现 | 后果 |
|------|------|------|
| **幻觉** | AI 编造端口、漏洞、CVE，甚至谎称"已拿到 Flag" | 结果不可信，等于没做 |
| **越权** | AI 扫描未授权 IP、执行破坏性命令、擅自扩大战果 | 法律与安全红线 |
| **黑箱** | 过程不可审计、失败不可复盘、中断不可恢复 | 无法用于正式场合 |

**灵枢的回答**：不依赖模型的"自觉"，而是把纪律写进架构——用状态机锁住流程、用审批闸门锁住攻击、用证据要求锁住结论、用审计哈希链锁住历史。**AI 可以自由思考，但不能自由行动。**

## 三、灵枢是什么：可治理多智能体作战平台

```text
任务 → 战略规划(Brain) → 战术调度(Orchestrator) → 侦察(Recon) → 研判(Analysis)
     → 攻击/逆向(Attack/Reserve) → 审批(ScopeAuditor) → 收尾(Summary)
                    ↓
        全部受控于：状态机 · 人工审批 · 动态授权范围 · 审计哈希链
```

**平台特征一句话概括**：`多智能体分工 + 唯一决策者 + 证据驱动 + 人工审批 + 全程可审计 + 断点可恢复`。

## 四、九大亮点（每一条都能现场演示）

### 1. 一支"AI 专家团队"，而不是一个聊天机器人
9 大专家角色各司其职：战略规划（Sophia）、行动指挥（Alex）、网络侦察（Ethan）、文件分析（Iris）、漏洞研判（Nora）、攻击手（按题型动态换将）、逆向专家（Ryan）、授权审计（Grace）、报告专家（Mia）。**侦查的归侦查，研判的归研判，动手的归动手** —— 认知隔离从架构上杜绝"一个模型既分析又瞎动手"。

### 2. 唯一决策者：纪律锁在架构里
只有总指挥（Orchestrator）能推进阶段、宣布结果。其他 Agent 再聪明，也**没有改变任务状态的权限**。这不是提示词约束，是代码事实。

### 3. 七层防幻觉防线：AI 想撒谎，做不到
角色约束 → 状态机锁 → 证据强制（标记完成必须有证据）→ 人工审批双保险 → 动作指纹熔断（换措辞重试会被识别并封禁）→ 命令/参数硬校验 → 审计哈希链。**每一层都是代码兜底，不赌模型心情。**

### 4. 攻击动作人工把关：人在回路，且是双保险
首次进入攻击阶段前，系统自动生成三档候选方案（最小化验证 / 证据驱动 / 目标导向），由操作员选择并调整优先级；**即使模型跳过申请，dispatch_attack 也会在函数层强制拦截**——审批状态持久化，崩溃恢复也不会重复询问。

### 5. 动态授权范围：授权即边界，越界即拦截
初始目标 + DNS 解析自动注册；侦察中发现的内网 IP 需经独立审计专家（ScopeAuditor）审核证据后才纳入授权；`scoped_shell` 对每条命令做破坏性黑名单、IP 白名单、目标显式包含三重校验。**想打到授权范围外？机器不答应。**

### 6. 动作指纹熔断：不撞南墙不回头，但只撞两次
系统用 SHA-256 动作指纹（工具+目标+参数+证据版本）识别"同一个动作换个说法再打"的无效重试，相同动作+相同错误累计两次自动熔断——**AI 的"坚持"被转化成理性的"换路"**。

### 7. 120+ 专业技能库：让通用大模型变身领域专家
内置 10 大 CTF 题型技能库 + 120+ 攻击/漏洞/工具/竞赛技能包（CyberPenda），运行时按题型动态加载；配合本地 RAG 知识库与长期经验记忆（59 张脱敏经验卡片），**每次任务都是"带着档案上岗"**。

### 8. 专业工具深度融合：WebShell、IDA、GDB 一网打尽
AntSword（37 个 WebShell 管理工具）、IDA（45 个静态逆向工具）、GDB（动态调试）以 MCP 方式受控接入——只读操作放行、危险入口封禁、写操作实时联动审批状态。**专业工具的能力 + 灵枢的纪律。**

### 9. 全流程可回放：从"黑箱"到"庭审记录"
每一步推理、工具调用、状态迁移、审批决策都写入 **SHA-256 前向哈希链**，篡改即失效；工具输出落盘为 artifacts 并带哈希指纹；任务可在任意断点恢复且不重放终态。**过程透明到可以当证据。**

## 六、应用场景

- **授权渗透测试**：给定 IP/主机名，AI 团队自主完成侦察→研判→验证→报告；
- **CTF 竞赛自动化**：Web/Pwn/逆向/密码/取证/杂项/OSINT/AI-ML 全题型，支持文件类目标（压缩包/ELF/PE/APK/PCAP/镜像）自动解压分析；
- **应急响应与样本分析**：恶意样本静态分析、密码学材料破解（内置自研 TonyEnc 解码器）；
- **安全教学与演练**：把 AI 的完整决策过程实时流式呈现，是最好的"老师"；
- **红队武器化研究**：技能库持续扩充，攻击链可沉淀为长期记忆复用。

## 九、愿景

灵枢的名字取自《黄帝内经》——"经脉之枢纽，生命之枢机"。

我们相信，**安全测试的未来不是"更聪明的单模型"，而是"纪律严明的智能体团队"**。当 AI 学会了思考，灵枢教它学会**负责任地行动**：每一次探测都在授权之内，每一个结论都有证据支撑，每一步过程都经得起回放。

> **让 AI 像战士一样能打，像账房先生一样留痕，像律师一样讲证据。**
